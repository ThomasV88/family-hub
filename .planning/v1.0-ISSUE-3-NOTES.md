# Issue #3: user manual (implementation notes)

## What was built

- Page `/manual` (route `manual.index`, `access:authenticated`, no module grant, no personal data). Controller `App\Http\Controllers\ManualController`, loader `App\Manual\ManualRepository`, Inertia page `resources/js/Pages/Manual/Index.vue`.
- Content: versioned JSON in `resources/manual/<locale>/<topic>.json` plus `_categories.json` per locale. English is the source; Slovak and Polish are drafts.
- Placement: sidebar (own group under the modules, so `MODULES` and the module-access tests are unchanged) and the account menu (right after Settings). NOT in the phone bottom bar (five modules already fill it); on phones the manual is reached through the account menu.
- Interface strings: `manual.*` and `nav.manual` in `lang/{en,sk,pl}.json`.

## Content format

Topic file:

```json
{ "id": "tasks", "category": "modules", "order": 30, "title": "...", "summary": "...",
  "adminOnly": false, "covers": ["module:tasks"],
  "sections": [ { "id": "create", "title": "...", "adminOnly": false, "covers": [], "blocks": [ ... ] } ] }
```

Block types: `p {text}`, `steps {title?, items[]}` (numbered; the default title is "Where to click"), `list {items[]}`, `tip|warning|example {text}`, `table {caption, columns[], rows[][]}` (first column is the row header).

Inline markup inside any string: `**bold**`, `[label](topic-id)`, `[label](topic-id#section-id)` (anchor inside the manual) and `[label](/settings/security)` (an app page that must exist as a GET route). Anything else stays plain text. No HTML is parsed anywhere (the renderer builds vnodes, no raw-HTML directive).

`covers` is internal (stripped before the page): `module:<key>` for every entry of `resources/js/Shell/modules.js`, `settings:<key>` for every key of `app/Support/SettingsSections.php`. Administrator sections must be covered by an `adminOnly` topic or section.

`adminOnly` topics and sections are removed on the server for non-admins (they never reach the browser).

## Topics (11 per locale, plus _categories.json)

getting-started, overview, tasks, wishlist, finance, health, account-security, admin (adminOnly), who-sees-what, faq, glossary. Categories: start, modules, account, admin, help.

## How to extend

1. Change behaviour users see: edit the matching topic in `en`, `sk` and `pl` in the same change (keep section ids, block counts and links identical).
2. New module or Settings section: add a topic (or a section) with `covers`, in all three locales. The coverage test fails until you do.
3. Run `npx vitest run tests/js/manual` (Node 22 container) and `pest tests/Feature/Manual`.
4. Rule is also in `CLAUDE.md` ("User documentation (mandatory)").

## PROVISIONAL choices

- Manual is not in the phone bottom bar.
- Sections of topics with 3 or fewer sections start open; longer topics start collapsed (Expand all / Collapse all buttons). Searching forces matching sections open.
- "AI is off until the administrator has set it up and turned it on" follows the issue text. The code may have the Codex agent enabled by default (only the per-person switch is off by default), so check the first-run state and reword `health#ai` and `admin#ai-agents` if needed.
- Confirm it's you and idle lock are described generically (no minutes), pointing to "Settings > Security". Re-check wording after the parallel re-confirmation work lands (modal wording `Confirm it's you`, label of the Settings page).
- Statements taken from config and may change with it: 72 hour delete window (`MEDICAL_DELETE_WINDOW_HOURS`), 10 MB documents, 10 files at once, 200 documents per person, 5 MB wishlist images, 2 MB / 5000 rows CSV, 7 day invitations, 60 minute reset links, 12 character passwords, 2 year audit, 12 month AI call log, 14/7/3/1 day gift reminders.
- There is no in-app "change password" or own session list; the manual says so (password via Forgot password, sessions revoked by the administrator).
- Backups paragraph: nightly encrypted backups on the same server, deleted records can survive in older backups.
