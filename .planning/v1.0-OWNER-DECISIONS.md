# Owner decisions for the production release (2026-11-15)

Collected interactively before the first production deploy. Phase DEFERRED.md files keep the original questions.

## Health (Phase 7)
- **Decision A (own record):** keep the current behaviour. A linked member needs the Health module grant even for their own record (narrows the locked CONTEXT wording "always sees own record"). Confirmed.
- **Decision B (deleting):** changed. Health records can be **archived, not fully deleted, once older than a window (default 72 hours, from the record's `created_at`)**. Inside the window a full delete is allowed. The window is configurable in the server env. Scope: persons AND individual records (visits, medications, allergies, vaccinations, documents). An archived record is hidden from lists, exports, the emergency card, reminders and AI, and a member with Edit can restore it from an Archive section.
- **WR-05 (image previews cache):** private browser cache is allowed (as built). PDFs and downloads stay `no-store`.
- **WR-11 (vaccination reminder text):** keep the person's name in the title (as built).
- **WR-12 (medical image processing):** raise the limits: max 3600 px, JPEG quality 90 (was 2400 px, 82). Originals are still not kept.

## Security and accounts
- **Second factor:** the admin switch "require a second factor for Health and Finance" is turned ON from the start in production.
- **Google sign-in:** not now. Production starts with email and password plus the second factor. Can be added later without code changes.
- **GDPR position:** strictly personal and family use (household exemption), only family members the owner invites. To be written into docs/ops.
- **Translations:** launch with the current SK/PL drafts and fix by feedback.

## UI
