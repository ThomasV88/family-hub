# v1.0 issue 2: lost draft after "Confirm it's you", and one-hour windows

Source: GitHub issue 2 (owner, Slovak): creating a bank account asked to re-verify, and after verifying the account was not saved and the form was gone. Owner decision 2026-11-15: both windows default to 1 hour and are changeable in Settings.

## What was wrong

Creating a finance account is `POST /settings/finance-accounts`, behind `access:admin` + `access:recent`. A stale confirmation made `RequireAccess::toConfirm` (and, for Health and Finance writes, `SensitiveGate`) answer an Inertia write with a redirect to `/confirm-access`. The page navigated away (draft lost), and after confirming the member was sent to the previous GET page. The request was never repeated. This is the same for every write, not only accounts.

## What was built

### 1. Central "Confirm it's you" dialog with in-memory replay
- Server (`App\Security\StaleGateResponse`, `SensitiveGate`, `RequireAccess`): an Inertia write (X-Inertia, not GET/HEAD) or a JSON call that hits a stale gate gets `423 {error: confirm_required | reauth_required, methods: {password, totp, passkey}}` (booleans only, `no-store` from the global middleware). No redirect, nothing saved, no audit row. GET navigations still redirect to `/confirm-access` (the page flow is unchanged and still works). Passive/prefetch requests keep the bare `{error: reauth_required}`. A member who must enrol a second factor is still sent to `/settings/security` (not replayable).
- Client `resources/js/Security/staleGate.js`:
  - `installStaleGate(router)` (called in `app.js`) wraps `router.visit`, so every Inertia write is covered without touching pages: `router.post/put/patch/delete`, `useForm`, `<Form>`, `<Link method>`. It adds an `onHttpException` that swallows the gate 423 (the original visit finishes, the form stops "processing"), opens the dialog, and after confirming re-issues the same visit with the original callbacks and a snapshot of the payload (`structuredClone`; `onBefore` is not repeated).
  - `runWithGate(attempt)` does the same for JSON/XHR helpers. `securityFetch`, `securityUpload`, `securityDownload` take `{ replay: true }`; `importApi.preview` uses it directly. A cancelled dialog resolves `{ ok: false, error: 'cancelled' }`.
  - Replay rules (all in staleGate.js, all tested): only a request the gate refused; once (a second refusal after the replay is reported with a toast `security.confirm_modal.replay_failed`, never reopens or loops); same signed-in member (user id compared at refusal and at replay); within 5 minutes (`REPLAY_WINDOW_MS`), otherwise nothing is sent and the member is told; same-origin relative URLs only (cross-origin or protocol-relative targets are not wrapped). Nothing is stored in localStorage, sessionStorage or cookies.
  - Concurrent refused submissions share one dialog; each is replayed once, in order. Cancel resolves all of them as cancelled.
- `Components/Security/StaleGateHost.vue` is mounted once at the app root (`app.js` renders it next to the Inertia `App`). It reuses `UiDialog` (focus trap, Escape cancels, focus returns to the control that triggered the submit), `ReauthPrompt` and `ReauthForm` in `dialog` mode: the same methods and rules as `/confirm-access` (password only when the member has no second factor, TOTP code, passkey; no recovery code; Google-only members get "Sign in again"; no Google re-auth). Errors are inline in the form's existing live alert, there is no second live region, no new colours.
- Copy: `security.confirm_modal.*` in en, sk, pl (identical key sets). SK and PL are drafts for native review.

### Call paths that use the central mechanism
All Inertia writes (default, no per-page code), which includes:
- Finance: accounts (Settings > Finance accounts, `settings.finance_accounts.*`, the reported case), transactions, budgets, recurring and bills, categories, import wizard commit/undo/discard and the file post (`router.post('/finance/import')`).
- Health: people, records (allergies, medications, vaccinations, visits and their verify/given), documents update/destroy, archive and restore, AI consent.
- Settings admin actions behind `access:recent`: permissions, invitations (create, resend, link, revoke), health people (members, link), finance accounts, wishlist managers, second-factor reset (own inline dialog kept, see limits), the new security timings.
JSON/XHR calls that pass `replay: true`:
- Health: document upload (`securityUpload`), document download, export download, AI run, AI cancel (panel and review page), AI suggestion accept/reject/undo/edit.
- Settings: AI agent enable/model/move (`AiAgents.vue`), AI bulk dry run, start, pause, resume, cancel (`BulkRegenPanel.vue`), security timings card.
- Finance import preview (`importApi.js`).
`handleHealthRefusal` and the finance import page treat `cancelled` as "stay where you are, nothing was sent". They still navigate to `/confirm-access` for a refusal that survives a replay, and to `/settings/security` for a missing second factor.

### 2. Timing defaults and Settings
- `config/security.php`: `idle_seconds` and `confirm_window_seconds` default 3600 (env `SECURITY_IDLE_SECONDS`, `SECURITY_CONFIRM_WINDOW_SECONDS` still the fallback default, same clamps).
- `App\Security\SecurityTimings` reads the admin's value from `app_settings` (keys `security.idle_seconds`, `security.confirm_window_seconds`, the same table the requirement switch uses), memoised per request through the scoped `AppSettings`. A missing or malformed stored value (string, float, bool, array, 0, negative) falls back to the config default; an out-of-range integer is clamped (idle 60..86400, confirm 60..3600). `SensitiveSession::fresh()` and `recentlyConfirmed()` (idle gate, `access:recent`) use it.
- `PUT /settings/security/timings` (`settings.security.timings`): `access:admin` + `access:recent` + `throttle:20,1`, strict integer validation, audited with `security_policy_changed` carrying only `{setting, value}` (one row per changed value, in the same transaction, audit before write). Listed in `SensitiveRoutes::accessGranting()` (the existing `settings.security.policy` was added there as well), the endpoint matrix and the arch recency test.
- UI: card "Re-confirmation" on Settings > Members (`SecurityTimingsCard.vue`), two fields ("Re-confirm after inactivity in Health and Finance", "Re-confirm sensitive actions after") as number + minutes/hours, stored in seconds. Saves through the replaying `securityFetch`. The audit table shows "set to 2 hours" with proper SK/PL plurals.
- Updated: every Pest test that pinned 900/600 or "stale" at 11 minutes or 1 hour, `docs/ops/server.md`. No `.env` examples carry these variables. No hard-coded "15 minutes"/"10 minutes" copy existed in lang (the confirm page uses `{minutes}` from the effective idle time).

## PROVISIONAL choices (owner to confirm)
- The new timings card sits on Settings > Members (next to the second-factor requirement switch), not on a new page or on the member's own Security page. The existing admin Security setting lives there.
- Audit reuses `security_policy_changed` instead of a new event: setting `security.idle_seconds` / `security.confirm_window_seconds` and the new number of seconds.
- Replay window is 5 minutes. The idle and confirm values are shown in minutes, or hours when exact.
- Pest "lost draft" reproduction: the old behaviour was pinned by `SensitiveGateTest` ("bounces a stale Inertia write with 303"); that test now asserts the 423-in-place contract instead. The browser-side scenario is `tests/js/finance/AccountStaleGate.test.js` (real Inertia `App`, router and `useForm`, fake HTTP client).
- SK/PL copy is a draft for native review.

## Limits
- The older in-dialog flows of Settings > Security (authenticator setup, turn off, new recovery codes, passkey add/remove, the requirement switch, member second-factor reset) keep their own inline confirmation step and do not use the central dialog (they already return to the same dialog and retry). They do not pass `replay`.
- `GuardTwoFactorRoutes` (turning off a live authenticator) still answers its own 423 body without `methods`.
- A GET navigation to a Health or Finance page after the idle window still goes to `/confirm-access` and back (nothing was being edited).
- A Vue component that calls `router.visit` for a write before `app.js` runs `installStaleGate` is not covered; there is none.
- The dialog cannot replay an upload whose `File` was released by the browser; a File held in a form field stays valid.
- Passkey confirmation inside the dialog is tested with the existing fake only; no real authenticator was used.
