## Contracts this plan defines

- `App\Auth\SessionRevoker`: `revokeAll(User $user): int` (deletes all `sessions` rows for user_id and rotates `remember_token` with `Str::random(60)` in one transaction, returns rows deleted); `revokeOne(User $user, string $sessionId): bool` (deletes the row only where id AND user_id match, rotates remember_token, returns whether a row was deleted). It never writes audit rows itself (callers do, plan 08).
- `App\Support\SettingsSections::for(User): array` returns the visible sections in order, each { key, href, labelKey, icon }: members (admin only, only when `Route::has('settings.members')`), audit (admin only, only when `Route::has('settings.audit')`), appearance (everyone). Every settings controller passes it as prop `sections`. Plans 05 and 06 add routes; the sections appear automatically.
- `SettingsLayout.vue` props: `sections`, `current` (key), `title` (i18n key). Renders the section nav (aria-label settings.nav_label, aria-current on the active item) and the content slot per UI-SPEC screen 5.
- Middleware alias `no-referrer` (sets `Referrer-Policy: no-referrer`) for pages with secrets in the URL; plan 09 uses it on /invite/{token}.
- Reset status keys: forgot-password success flash `status = reset_link_sent`; reset success redirects to /login with `status = password_reset` (Login.vue already renders it, plan 02).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser -> /forgot-password, /reset-password | Untrusted email/token input, enumeration and token guessing |
| Reset email -> inbox | Token travels by email and in the URL |
| Worker -> SMTP | Queued mail delivery |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-17 | Information Disclosure | forgot-password response | mitigate | success and failed contracts bound to the same response; broker messages mapped to neutral keys; queued notification; test asserts identical responses |
| T-02-18 | Spoofing | reset token guessing | mitigate | framework broker (hashed tokens, 60 min expiry, timebox), ThrottleAuthRoutes on password.update |
| T-02-19 | Information Disclosure | token leakage via Referer | mitigate | Referrer-Policy no-referrer on /reset-password/{token}; page loads no third-party assets |
| T-02-20 | Elevation of Privilege | attacker session survives password reset | mitigate | ResetUserPassword calls SessionRevoker::revokeAll (rows deleted + remember_token rotated); test asserts |
| T-02-21 | Elevation of Privilege | revokeOne IDOR across users | mitigate | delete scoped by id AND user_id; SessionRevokerTest |
| T-02-22 | Denial of Service | reset mail flooding | mitigate | per-IP and per-email limits on password.email |
</threat_model>
