## Contracts used and defined

- From plan 07: Invitation::findByToken, Invitation::state, InviteService, flash contract. From plan 03: Preset::grants, UserFactory states, `access:guest`. From plan 04: alias `no-referrer`. From plan 05: AuditLogger, events invite_accepted and google_linked.
- `InviteService::accept(Invitation $inv, array $attrs, ?string $googleId = null): User` — in one DB::transaction with `lockForUpdate()` on the invitation: re-check state is 'valid', refuse if a user with the email now exists, create the user with forceFill (email from the invitation, name, password hashed or `Hash::make(Str::random(64))` for Google, locale from the invitation, email_verified_at now, google_id when given, is_admin false), write module_permissions from the invitation's preset, set accepted_at and accepted_user_id, record invite_accepted (actor the new user). Throws a domain exception mapped to 'auth.error.invite_invalid' when the state is not valid.
- Routes: routes/web/invite.php: GET /invite/{token} (invite.show, access:guest, no-referrer, throttle 10/min), POST /invite/{token} (invite.accept, access:guest, no-referrer, throttle 10/min). routes/web/google.php: GET /auth/google/redirect (auth.google.redirect, access:guest, throttle 10/min), GET /auth/google/callback (auth.google.callback, access:guest, throttle 10/min).
- Login status keys added here: `google_failed` (danger, auth.error.google_failed) and `google_not_invited` (danger, auth.error.google_not_invited). Invite page error key: `google_mismatch` (danger, invite.accept.google_mismatch with {email}).
- `googleEnabled` = client id and secret both configured (`config('services.google.client_id')` and `client_secret` filled). Passed to Auth/Login (FortifyServiceProvider loginView) and Auth/AcceptInvite.
- Never persist Google access or refresh tokens (CLAUDE.md "never store OAuth tokens"); only `sub` (as users.google_id) and the verified email are used.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Invite link holder -> /invite/{token} | Anyone with the link can try to register |
| Google -> /auth/google/callback | Identity assertion from an external IdP via the browser |
| Session -> invite token | Plain invite token held in the server-side session during the Google round trip |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-47 | Tampering | double accept race | mitigate | transaction + lockForUpdate + state re-check + partial unique index; double-accept test |
| T-02-48 | Spoofing | Google account with unverified email | mitigate | email_verified required in every branch; tests |
| T-02-49 | Spoofing | account takeover via Google email change | mitigate | match by google_id (sub) first; same email with different sub refused |
| T-02-50 | Elevation of Privilege | self-signup through Google | mitigate | user creation only inside the invite branch; login-page Google never consumes invites (decision 2); test |
| T-02-51 | Tampering | OAuth callback CSRF | mitigate | Socialite stateful driver (state in session); exceptions -> google_failed |
| T-02-52 | Spoofing | session fixation after accept/Google | mitigate | session regenerate on every login path; tests |
| T-02-53 | Information Disclosure | invite token via Referer/logs | mitigate | no-referrer on invite routes, no third-party assets, throttle 10/min; token never logged |
| T-02-54 | Information Disclosure | invite token in session payload | accept | server-side DB session, removed after the callback, invite expires in 7 days |
| T-02-55 | Information Disclosure | Google OAuth tokens stored | mitigate | token discarded; test asserts no token value in users/sessions |
</threat_model>
