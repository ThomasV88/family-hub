Exactly the 01.1 set: 4 sizes (14, 16, 20, 24), 2 weights (400, 600). Do not use `--text-xs`, `--text-lg`, `--text-3xl`.

## Color

Reuse 01.1 values. 60/30/10 holds: dominant `--color-bg`, secondary `--color-surface` / `--color-surface-2`, accent `--color-primary`, destructive `--color-danger`.

Accent reserved for (this phase, subset of the 01.1 closed list):
1. The single primary button per view/dialog ("Sign in", "Create account", "Send reset link", "Set new password", "Send invite", "Save permissions")
2. Selected settings section item (soft background, label color, 2px start-edge indicator) and selected tab underline/label
3. Focus ring, links in body text ("Forgot password?", "Back to sign in")
4. Checked switch and selected filter chip
5. "Sign in with Google" is a secondary button, NOT accent

Destructive (`--color-danger`) reserved for: "Revoke session", "Revoke all sessions", "Revoke invite" confirm buttons, field error text/border, lockout error alert, "Revoked"/"Expired" invite tag. Never for permission level "none" (none is neutral muted, not an error).

Semantic tags: `success` = Active member, Accepted invite; `warn` = Pending invite; `danger` = Expired/Revoked invite, Failed login in audit log; `neutral` = roles, event categories. Every tag has text, optionally an icon.

Sensitive-module emphasis: Health and Finance column headers get a `Lock` icon (muted, `aria-hidden`) plus the text "Restricted by default" as help text; no extra color.

## Screens and Interaction Contract

Routes (all Inertia pages under `resources/js/Pages`): `/login`, `/invite/{token}`, `/forgot-password`, `/reset-password/{token}`, `/settings` (redirects to `/settings/members`), `/settings/members`, `/settings/audit`, `/settings/appearance`. Auth pages use `AuthLayout`; settings pages use `AppShell`.

### 1. Login (`/login`)
- Card title (h1) "Sign in". Fields: Email (`type=email`, `autocomplete=username`, autofocus), Password (`autocomplete=current-password`, show/hide toggle button with `aria-pressed`, label "Show password"/"Hide password"), checkbox "Stay signed in for 30 days" (unchecked default), primary button "Sign in" (full width, loading state), divider with text "or", secondary full-width button "Sign in with Google" (Google "G" glyph inline SVG, plain, text label always present), link "Forgot password?" below the button.
- Errors: one `UiAlert` danger above the form with `role="alert"`; generic message only (never reveals whether email exists). Field errors only for empty/invalid format. Lockout: danger alert "Too many attempts" with remaining wait shown as minutes (ICU plural); button disabled until the wait ends.
- No sign-up link. Info line under card: "Family Hub is by invitation only. Ask your family admin for an invite."
- Google failure (email not invited / mismatch): same page, danger alert with specific safe copy (no account enumeration beyond "this Google account is not invited").
- Already signed in: redirect to Overview.

### 2. Invite accept / register (`/invite/{token}`)
- Valid token: title "Join your family on Family Hub". Under title, body line "You were invited as {email}." (email shown read-only in a disabled `UiInput` labelled "Email" so it is announced). Fields: Name, Password, Confirm password, helper text for password rules ("At least 12 characters. A long sentence works well."), primary "Create account". Secondary "Continue with Google" with hint "Use the Google account for {email}." Password strength: text hint only, no color meter; rules checked server-side.
- Language: preselected from the invite (admin chose it) and shown via the `LanguageSwitcher` on the page.
- Invalid/used/expired/revoked token: `UiErrorState` (not a form) titled "This invite cannot be used" with body per case (expired: "It expired after 7 days. Ask your family admin to send a new one."; used: "It has already been used. Try signing in."; revoked/unknown: "It is no longer valid. Ask your family admin for a new invite."), action link "Go to sign in". Same generic copy for unknown vs revoked.
- After success: signed in, redirect to Overview with `UiToast` "Welcome to Family Hub, {name}."
- Google email mismatch: danger alert "That Google account uses a different email. Use the Google account for {email}."

### 3. Forgot password (`/forgot-password`)
- Title "Reset your password"; body "Enter your email and we will send you a link."; field Email; primary "Send reset link"; link "Back to sign in".
- Always shows the same success state after submit (no enumeration): success `UiAlert` "If an account exists for that email, a reset link is on its way. The link works for 60 minutes." Focus moves to the alert (`role="status"`). Throttle error as in login.

### 4. Reset password (`/reset-password/{token}`)
- Title "Choose a new password"; fields New password, Confirm new password (hints as register); primary "Set new password". Success: redirect to `/login` with success alert "Your password was changed. Sign in with the new one." Invalid/expired token: `UiErrorState` "This reset link cannot be used", body "It may have expired. Request a new one.", action "Request a new link". Resetting revokes all other sessions (state this in helper text: "You will be signed out on other devices.").

### 5. Settings shell (`/settings/*`)
- Layout from sketch 008 A: section list left, content right. Section list is a vertical `nav` (aria-label "Settings") with items: "Members and access" (`Users`), "Audit log" (`ScrollText`), "Appearance and language" (`Palette`). Non-admins see only "Appearance and language"; `/settings/members` and `/settings/audit` return 403 page (also server enforced) with `UiErrorState` "You do not have access to this page" and action "Back to overview".
- Container width >= 640px: two columns, list 240px, gap 32px, content max 880px. Below 640px: the section list becomes a full-width `UiList` landing at `/settings`, each item navigates to the section; section pages show a "Back to settings" link (`ChevronLeft`) above the h1. Selected item uses `aria-current="page"`.
- Page h1 is the section title (Heading 20/600). AccountMenu "Settings" links to `/settings` (non-admin to `/settings/appearance`).

### 6. Members and access (`/settings/members`)
- Header row: h1 "Members and access", primary button "Invite member" (leading `UserPlus`) end-aligned (wraps below title on phone).
- Two groups, each a `UiCard` with a Heading: "Members" (`MemberRow` list) and "Invitations" (pending/expired/revoked rows).
- `MemberRow`: avatar, name, email, role tag ("Admin" / "Member"), "You" neutral tag on own row, status tag "Active". Trailing button "Manage" (secondary, sm) opens the member `DetailPanel` (docked on desktop, overlay on iPad, bottom sheet on phone, per 01.1 presentations).
- Invitation row: email, preset/language tag text, status tag (Pending warn "Pending, expires {date}", Expired danger, Revoked danger), trailing actions: "Resend" (`RotateCw`), "Copy link" (`Copy`, copies, then `UiToast` "Invite link copied"), "Revoke" (`Ban`, opens confirm dialog). Resend on expired invite issues a new 7-day link.
- Empty (no invitations): `UiEmptyState` "No pending invitations", body "Invite a family member to get started.", action "Invite member". Loading: `UiSkeleton` rows. Error: `UiErrorState` with "Try again".

### 7. Invite dialog (`UiDialog`, from "Invite member")
- Title "Invite a family member". Fields: Email (required), Starting access (`UiSelect`: Parent, Child, Grandparent, Guest, with hint line under it describing the selected preset), Language (SK/PL/EN, defaults to admin's), helper text "The invite works for 7 days and can be used once."
- Buttons: primary "Send invite", secondary "Cancel". Default focus on Email.
- After success the dialog switches to a result view: success `UiAlert` "Invite sent to {email}.", a read-only `UiInput` "Invite link" with button "Copy link", buttons "Done" (primary) and "Invite another". If email delivery fails (queue/SMTP error): warning alert "We could not send the email. Copy the link and share it yourself." and the link stays visible.
- Errors: existing member email -> field error "This email already belongs to a member. Ask them to sign in."; invalid email as 01.1 pattern.

### 8. Member panel: permissions and sessions (`DetailPanel`)
- Title: member name (h2) with email below, avatar. `UiTabs`: "Permissions", "Sessions".
- Permissions tab: preset `UiSelect` "Apply preset" with options Parent, Child, Grandparent, Guest, plus button "Apply" (secondary); applying only fills the selects below (nothing saved yet) and shows an info alert "Preset applied. Adjust anything, then save." Then four `UiField` rows (To-do, Wishlist, Finances, Health), each a `PermissionSelect` with hint. Health and Finances rows show a `Lock` icon and hint "Restricted by default". A fifth static row "Settings": text "Admins only" with `UiTag` neutral; for admin members "Always allowed" and the select rows still editable for health/finance (admin gets None there until granted, with note "Admins do not get Health or Finances automatically."). Footer: primary "Save permissions", secondary "Cancel" (reverts). Unsaved changes: Save enabled only when dirty; closing the panel with changes asks confirm dialog "Discard changes?" (buttons "Discard" danger, "Keep editing" secondary, default focus "Keep editing").
- Role toggle (admin vs member) is NOT in this phase (admin created via artisan; not changeable in UI) (discretion).
- Own row guard: admin cannot lower their own settings access (it is not an option); the panel for yourself says "You are the admin and always keep access to settings."
- Success: `UiToast` "Permissions saved". Server error: danger alert inside the panel, selections kept.
- Sessions tab: list of the member's sessions (`UiListRow`): device icon (`Monitor`/`Smartphone`), "Browser on OS" (parsed user agent), line "Last active {relative time}, IP {ip}", tag "This device" on the viewer's own current session, tag "Stays signed in" for 30-day sessions. Trailing "Revoke" (danger ghost, sm) per row -> confirm dialog. Footer button "Revoke all sessions" (danger secondary) -> confirm dialog; hidden when only one session and it is the viewer's own. Empty: `UiEmptyState` "No active sessions", body "This member is not signed in anywhere."
- Phone: the panel is a bottom sheet with Close button; matrix rows stack one per line at 100% width.

### 9. Permission matrix (overview inside Members section)
- A secondary view of the same data: `UiTabs` at top of the Members section: "Members" (list view) and "Permission matrix". Matrix is a `UiTable`: rows = members (avatar + name), columns = To-do, Wishlist, Finances, Health, Settings. Cell = read-only `UiTag` showing level text with icon (None neutral+`Ban`, View neutral+`Eye`, Edit success+`Pencil`); Settings column shows "Admin" tag or "-" ("No access"). Row is a button that opens the member panel focused on the Permissions tab. Editing happens only in the panel (single save path, fewer accidental changes) (discretion; sketch 008 inline edit rejected for the first release because every change is audited).
- Below 560px the table collapses to stacked cards (01.1 `UiTable` responsive): each card lists member name then four "Module: Level" lines.
- Legend line under the table: "None: cannot see the module. View: can read. Edit: can read and change."

### 10. Audit log (`/settings/audit`)
- h1 "Audit log". Intro line: "Who did what and when. Content of records is never logged. Entries are kept for 2 years."
- Filter bar (`UiCard`, wraps): Member (`UiSelect`, "All members"), Event type (`UiSelect`, "All events": Sign-in, Failed sign-in, Invite, Permission change, Session revoked, Health data, Finance data), Date from, Date to (native `type=date`), button "Apply filters" (secondary), link-style button "Clear filters". Filters reflected in the URL query.
- Table columns: When (date + time), Member, Event, Details (e.g. "Read health data", "Changed Finances for Anna: None to View"; never record content), IP. Event column is a `UiTag`. Sticky header; 25 rows per page; pagination below: "Previous" / "Next" buttons plus text "Page {n} of {total}"; page change moves focus to table caption.
- Read-only: no row actions, no export in this phase. Responsive: below 560px each entry is a stacked card.
- Empty (no matches): `UiEmptyState` "No entries match", body "Try a wider date range or clear the filters.", action "Clear filters". Loading: skeleton rows. Error: `UiErrorState`.

### 11. Appearance and language (`/settings/appearance`)
- Reuses `ThemeSwitch` and `LanguageSwitcher` in a `UiCard` with headings "Theme" and "Language". No new behavior (language persisted to account when signed in, per existing `/locale`).

### 12. AccountMenu (avatar `UiMenu`)
- Items in order: header (name, email, non-interactive), "Settings" (`Settings` icon, link), Language (existing), Theme (existing), separator, "Log out" (`LogOut`, button posting logout). Log out is immediate with no confirm; on success redirect to `/login` with info alert "You have been signed out." Module nav items for modules with access `none` are hidden (AppShell reads grants); the "Settings" menu item and nav are always shown, section visibility follows admin status.
- Session revoked elsewhere: the next request returns to `/login` with info alert "You were signed out. Sign in again to continue." (Inertia 401/419 handled globally, no data left on screen, no-store headers already in place.)
- Forbidden module routes render the 403 `UiErrorState` ("You do not have access to this page") inside AppShell.

## Interaction and Accessibility Contract (additions to 01.1)

- Forms: one primary button per card; Enter submits; submit button shows loading state and width is stable; on validation error focus moves to the first invalid field and an error summary is not needed for single-column forms of at most 4 fields. Server alert errors get `role="alert"`.
- Autofill and password managers: correct `autocomplete` tokens (`username`, `current-password`, `new-password`, `email`, `name`); no `autocomplete=off`; paste is allowed in password fields.
- `inputmode` and `type` set properly; inputs 16px (no iOS zoom).
- Do not leak state: generic auth errors; same response copy for known/unknown email in reset.
- Matrix selects are native `<select>`: keyboard and screen reader support free; each has a unique accessible name; save status announced via toast `role="status"`.
- Dialogs and confirm dialogs: default focus on the safe button; destructive button never default. Panel and dialog behavior as 01.1.
- Session and audit tables use real `<table>` with `<caption>` (visually hidden) and `scope` on headers; row action buttons carry the member/device in `aria-label` (e.g. "Revoke session: Safari on iPhone").
- Time: absolute timestamps in audit (locale format) with `<time datetime>`; relative time ("2 hours ago") only in session list via `Intl.RelativeTimeFormat`.
- Touch: all new controls 44px hit area on phone/iPad.
- Tests: axe (vitest-axe) on each page in light/dark and en/sk/pl; Pest feature tests assert 403 states render; pseudo-long string test for the matrix and filter bar.
- Caching: auth and settings pages must remain `no-store`; nothing from these screens enters the service worker.

### Destructive actions in this phase

| Action | Confirmation approach |
|--------|----------------------|
| Revoke invite | `UiDialog` confirm: title "Revoke invite", body names the email and the consequence, buttons "Revoke invite" (danger) and "Keep invite" (secondary, default focus) |
| Revoke one session | Confirm dialog (`sessions.revoke_*`), danger "Revoke", safe "Keep signed in" default focus |
| Revoke all sessions of a member | Confirm dialog (`sessions.revoke_all_body`), same buttons |
| Discard unsaved permission changes | Confirm dialog (`permissions.discard_*`), "Discard" danger, "Keep editing" default focus |
| Permission change itself | Not destructive: no confirm, explicit "Save permissions" step, audited, toast on success |
| Log out | No confirm, reversible by signing in |
