## Contracts this plan defines (plan 09 consumes them)

- Table invitations: id, email string (stored lowercase), token_hash char(64) unique, preset string(20), locale string(5), invited_by foreign to users (null on delete), expires_at timestampTz, accepted_at, revoked_at, mail_failed_at nullable timestampTz, accepted_user_id nullable foreign to users (null on delete), timestamps. Partial unique index `invitations_one_open` on lower(email) WHERE accepted_at IS NULL AND revoked_at IS NULL.
- `Invitation::state(): string` returns 'valid' | 'expired' | 'used' | 'revoked'. `Invitation::findByToken(string $plain): ?Invitation` looks up by `hash('sha256', $plain)`. Casts preset to Preset.
- `InviteService` (app/Auth): `create(User $admin, string $email, Preset $preset, string $locale): array{invitation, token}` (refuses with a validation error key invite.dialog.error.exists if a user with that lowercased email exists; an existing open invite for the same email is revoked and replaced in the same transaction, auditing invite_revoked then invite_created), `resend(User $admin, Invitation $inv): string` (new token + 7-day expiry, clears mail_failed_at, queues mail, audits invite_resent), `rotateLink(User $admin, Invitation $inv): string` (new token + 7-day expiry, no mail, audits invite_resent with meta email), `revoke(User $admin, Invitation $inv): void` (sets revoked_at, audits invite_revoked). Token = `Str::random(40)`; plain token returned only to the caller, never stored or logged. Only pending or expired, non-revoked, non-accepted invites can be resent/rotated/revoked (others 409 back with no change).
- Link format: `url('/invite/'.$token)`; plan 09 registers GET /invite/{token} named invite.show.
- One-shot link handoff to the browser: session flash `flash_data.invite = { email, link, mailQueued: bool, rotated: bool }` (shared by plan 02's `flash.data`). Never put the link in a query string or a persistent prop.
- Members page prop `invitations` = list of { id, email, preset, locale, state, expiresAt, mailFailed } for invites that are not accepted, newest first.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Admin browser -> invitation endpoints | Admin-supplied email/preset/locale |
| Invite link -> email / chat | Bearer token for account creation travels outside the app |
| Queue (jobs table) -> worker -> SMTP | Notification payload holds the plain token until sent |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-35 | Information Disclosure | token at rest | mitigate | only sha256 hash stored; plain token returned once via flash; test asserts absence in DB and audit |
| T-02-36 | Information Disclosure | token in queued job payload | accept | jobs table is in the same private DB, deleted after send, 7-day expiry; no logging of the token |
| T-02-37 | Elevation of Privilege | non-admin creates invites | mitigate | access:admin on all routes; matrix rows |
| T-02-38 | Tampering | preset/locale injection | mitigate | request validation against Preset enum and sk/pl/en |
| T-02-39 | Spoofing | stale link reuse after resend | mitigate | resend/rotate replace token_hash; old token fails lookup (test) |
| T-02-40 | Repudiation | unaudited invite changes | mitigate | invite_created/resent/revoked audit rows in the service |
| T-02-41 | Denial of Service | invite mail flood | mitigate | throttle 30/min on invitation routes, admin-only |
</threat_model>
