## Facts about this repo (verified while planning)

- Host PHP lacks pdo_pgsql/intl: every composer/artisan/Pest command runs in the app container. Use compose project `fh0201`: `docker compose -p fh0201 run --rm app <cmd>`; tear down with `docker compose -p fh0201 down -v` at the end. The dev image already contains composer (docker/app/Dockerfile copies it from composer:2).
- Language files are `lang/en.json`, `lang/sk.json`, `lang/pl.json` (codes sk|pl|en), NOT `lang/en-GB.json` as the UI-SPEC says. They are nested JSON objects shared to Vue in full by HandleInertiaRequests.
- Plurals are vue-i18n pipe strings, not ICU. `resources/js/i18n.js` FORM_ORDER: en = [one, other] (2 segments), sk and pl = [one, few, many, other] (4 segments). Existing example: `home.checks_count` = "{count} check | {count} checks". Called as `t(key, n, { named: {...} })` or `t(key, { minutes }, minutes)`.
- Laravel's `__()` cannot read nested JSON keys, so backend-originated text uses either PHP group files (lang/{locale}/*.php) or returns an i18n key for Vue to translate. Existing group file: lang/en/common.php.
- axe-core 4.14.0 and `tests/js/helpers/axe.js` (`expectNoAxeViolations`) already exist, so the research's optional `vitest-axe` is NOT needed and must not be added.

## Error/message contract (defined here, used by every later plan)

Server validation errors and session flashes that the UI shows carry i18n keys from lang/*.json (for example `auth.error.failed`, `invite.accept.error.password_short`), never prose. Vue pages render them with `t(value)`. The only non-key error value is `errors.throttle`, which holds whole minutes as a numeric string.
