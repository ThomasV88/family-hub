## Phase Goal

**As a** family admin, **I want to** invite my relatives to Family Hub and decide per person and per module what they may see and change, **so that** everyone can sign in safely and private health and money data stays private.

<objective>
Slice 2: the deny-by-default policy layer. Per-member, per-module grants exist in the database, one `requireAccess(user, module, level)` gate plus one `access:<rule>` middleware guard every route, a global guard refuses any route that forgot to declare a rule, and a hand-written role-by-endpoint Pest matrix proves it. Members see a proper 403 page and the nav hides modules they cannot use.

Purpose: AUTH-07 in full (CONTEXT "Permissions": one deny-by-default requireAccess layer called by every controller/route; role-by-endpoint matrix that fails if an endpoint is not registered). Data model for AUTH-05 and the preset definitions for AUTH-06 (CONTEXT presets, admin gets settings but health/finance none until granted).
Output: enums, module_permissions table, AccessGate, two middlewares, per-feature route files, matrix harness, Forbidden page, access-aware nav, staging seeder grants.
</objective>

## Contracts this plan defines (every later plan consumes them)

- Enums in `app/Access`: `Module` (string-backed: todo, wishlist, finance, health; method `audited()` true for finance and health), `AccessLevel` (int-backed: None 0, View 1, Edit 2; method `label()` returns 'none'|'view'|'edit'), `Preset` (string-backed: parent, child, grandparent, guest; method `grants()` returns an array keyed by Module value with AccessLevel for all four modules).
- Preset grants (locked, CONTEXT): parent = todo edit, wishlist edit, finance edit, health none; child = todo edit, wishlist edit, finance none, health none; grandparent = same as child; guest = todo view, everything else none.
- `AccessGate` (bound with `scoped` in AppServiceProvider, never cached across requests): `level(User, Module): AccessLevel` (missing row = None), `allows(?User, Module, AccessLevel): bool`, `requireAccess(?User, Module, AccessLevel): void` (abort 403), `isAdmin(?User): bool`, `levels(User): array<string,string>` for the shared prop, `forget(User)` to drop the per-request cache after a save. Admin status never implies module access (research Anti-Patterns: no Gate::before).
- Route rules via middleware alias `access`: `access:public`, `access:guest` (signed-in users are redirected to '/'), `access:authenticated`, `access:admin`, `access:module,<module>,<level>`. Guest on a non-public route: redirect to /login (with session status `session_ended` when the request carried a session cookie whose id no longer exists, see Task 1). Authenticated but denied: 403.
- Route files: `routes/web.php` keeps Phase 1 routes and then requires every `routes/web/*.php` file in sorted order. Each later plan adds its own file (settings.php, settings-audit.php, settings-members.php, invitations.php, sessions.php, invite.php, google.php), so parallel plans never edit the same route file.
- Matrix files: `tests/Support/EndpointMatrix.php` merges every `tests/Support/EndpointMatrix/*.php` file (each returns route name => spec). Spec shape: `method`, `uri` (with placeholders), `params` (closure receiving the role users map, returning route params, optional), `data` (request body, optional), `expect` (role => status). Roles (tests/Support/Roles.php): guest, admin (no module grants), parent, child, grandparent, guestPreset, noGrants. Each later plan adds its own matrix file.
- Fortify route-name map (EnsureRouteDeclaresAccess, because Fortify routes cannot carry per-route middleware from config): login and login.store => guest; logout => authenticated; password.request, password.email, password.reset, password.update => guest. Confirm names against 02-01-SUMMARY route list.
- Shared prop `auth.access` = { todo, wishlist, finance, health } with 'none'|'view'|'edit' (empty object for guests), plus existing `auth.user.isAdmin`.
- Frontend module keys differ (`tasks`, `finances` in modules.js): map in one place, `ACCESS_KEY = { tasks: 'todo', wishlist: 'wishlist', finances: 'finance', health: 'health' }`.
