## Facts and contracts

- phpunit.xml forces SESSION_DRIVER=array; session tests insert rows into the `sessions` table directly and set `config(['session.driver' => 'database'])` where a real round trip is needed (research Validation Architecture).
- "Stays signed in": plan 05's Login listener stores `auth_remember` true in the session. SessionList decodes the payload with `unserialize(base64_decode($payload), ['allowed_classes' => false])` only to read that one flag (SESSION_ENCRYPT is false; if decoding fails, staysSignedIn is false). The payload never leaves the server.
- Routes (routes/web/sessions.php, all access:admin): GET /settings/members/{user}/sessions (settings.members.sessions.index, JSON), DELETE /settings/members/{user}/sessions/{session} (settings.members.sessions.destroy), DELETE /settings/members/{user}/sessions (settings.members.sessions.destroy_all).
- Audit: session_revoked with target the member and meta {device}; session_revoked_all with target the member.
- Known trade-off: revokeOne rotates remember_token, so other devices of that member lose their remember cookie (their live sessions continue until they expire). Accepted: security over convenience; document in SUMMARY.
</context>

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-02-42 | Elevation of Privilege | revoked device returns via remember cookie | mitigate | SessionRevoker rotates remember_token; end-to-end test with only the remember cookie |
| T-02-43 | Elevation of Privilege | IDOR revoking another member's session | mitigate | delete scoped by id AND user_id, 404 otherwise; access:admin |
| T-02-44 | Information Disclosure | session payload exposure | mitigate | explicit field mapping, payload decoded server-side only with allowed_classes false |
| T-02-45 | Tampering | unserialize on payload | mitigate | allowed_classes false prevents object injection; payload written only by the framework |
