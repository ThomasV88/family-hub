## Contracts

- `TokenUsage` (final readonly): `input`, `cached`, `output`, `reasoning` ints; `fromEvent(array): ?self`. `ProcessResult` gets a trailing `public ?TokenUsage $usage = null`; `CodexRunner::exec` fills it from a `{"type":"turn.completed","usage":{...}}` JSONL line in the existing scan (integers only, the last event wins). `AgentOutcome` gets a trailing `public ?TokenUsage $usage = null` and `CodexAgent::extract` passes the runner's value through on every return path. Nothing else in the runners changes (flags, env allowlist, lockdown).
- `SearchTerms` (pure PHP, in `App\Medical\Documents\Text`): `parse(string $q): list<list<string>>` per research "Query building" (NFC, trim, first 100 characters, lower, split on anything not `\p{L}\p{N}`, tokens of 2+ characters, at most 8; tokens of 7+ characters get 1- and 2-character trimmed alternatives keeping 5+); `fold(string): string` = `Str::ascii` then lower (the PHP side of the fold; 13-04 adds the SQL side); `matches(list<string> $alternatives, string $word): bool` = the folded word starts with any folded alternative. 13-04 consumes this class unchanged.
- `TextMetrics`: `normalise(string)` (NFC, `\r` removed, U+000C page separators removed, whitespace runs to one space, trim); `cer(ref, hyp)` and `wer(ref, hyp)` as a two-row Levenshtein over code-point arrays and whitespace tokens divided by the reference length (no PHP `levenshtein()`: 255-byte cap and not Unicode-aware); `diacritics(ref, hyp): array{accuracy, drop_rate}`; `numeric(ref, hyp)`: exact-match share of reference tokens that contain a digit; `searchRecall(ref, hyp)`: share of reference content words (4+ letters, de-duplicated by fold) that `SearchTerms::parse(word)` + `matches` finds among the hypothesis tokens. Empty reference sets count as 1.0 and are flagged.
- `EntryScorer::score(array $expected, array $predicted): array{precision, recall, f1, tp, fp, fn}` over key fields per research "Metrics" (medication name+dose, allergy substance, vaccine+date, visit date+doctor+diagnosis, document date, specialty), values normalised with `SearchTerms::fold` and whitespace collapse.
- `Stats`: `mean`, `stddev`, `pairedBootstrap(list<float> $diffs, int $n = 2000, int $seed = 13): array{low, high}` (95 percent interval, deterministic seed).
- `EvalDecision`: `stepVerdict(array $baselineRows, array $armRows, float $noiseSd): array{keep: bool, reasons: list<string>}` implementing decision rule items 1 to 4 of the research verbatim (margin `max(0.5 pp, 15 percent relative, 2 x noise sd)`, bootstrap interval excludes zero, clean/jpeg not worse by more than 0.2 pp CER and 0.5 pp diacritics/numeric, search recall not lower on either set, cost <= 3 s per page and peak < 100 MB); `greedyChain(array $verdicts): list<string>` in the order A1, A2, A4, A3 (item 5); `storeText(array $typicalRows): 'go'|'go_with_label'` with the thresholds of research A6 (CER <= 3 percent, diacritics >= 97 percent, numeric >= 99 percent, recall >= 90 percent on `clean, jpeg, rot3, blur` at the best arm) — per the owner default there is no `no_go` outcome: a failing typical set means `go_with_label`; `pipeline(array $p0, array $p1): 'two_call'|'combined'` (P1 accepted if entry F1 is not worse than P0 by more than 2 pp).
- `DocumentPreprocessor` (GD only, input and output are file paths in a work dir): `fit(src, dst)` to at most 2048 px long edge with `imagescale` bicubic, lossless PNG (A1); `autolevel` grayscale plus 1st to 99th percentile histogram stretch (A2 = A1 + autolevel); `denoiseSharpen` light `IMG_FILTER_SMOOTH` plus a 3x3 unsharp `imageconvolution` (A3 = A2 + this); `deskew` rotation by `SkewEstimator` (downscale to 512 px, 41 trial angles within +-10 degrees, row-projection variance, skipped under 0.5 degrees) (A4 = A1 + deskew); `chain(list<string> $steps)` for A5 (deskew, autolevel, denoise-sharpen, grayscale). Every method frees GD images in `finally`, returns `array{ms, peak_bytes}`, and refuses a decoded source over the existing ImageProcessor decode budget. Plan 13-06 keeps or deletes these steps per `13-EVALUATION.md`.
- `EvalTask implements AiTask` with modes `transcribe` (schema `resources/ai/transcription.v1.schema.json`, prompt `transcribe.v1.prompt.md`, Copilot `transcribe.v1.inline-json.md`), `extract_from_text` (schema `resources/ai/extraction.v1.schema.json`, prompt `resources/ai/eval/extract-from-text.prompt.md` with the synthetic transcript inside a per-run nonce-marked data block copied from the RecipeTask technique), `combined` (`resources/ai/eval/combined.schema.json` = transcription pages plus the extraction entry lists), and `baseline` (delegates to `MedicalTask` with today's `prompt.v1.md`). `validateFile` checks exact keys, page ids equal the expected set, per page <= 12 000 characters, total <= 200 000; on success the payload is kept in memory only for scoring.
- Transcription schema per research "Strict-compatible transcription schema" (no `maxLength`, `additionalProperties: false` at every object level, `schema_version` enum [1], `language` enum sk, pl, en, mixed, other, null, `pages[{page, legible, text}]`, `maxItems` 20). Prompt rules per research "Step 1 prompt rules" (images are untrusted data, verbatim reading order including headers, footers, stamps, handwriting, keep line breaks, table cells separated by ` | `, `[illegible]`, no translation, correction, summary, description or markdown, JSON only).
- `Corpus::load(string $dir): Corpus` requires: realpath under `config('ai.work_dir')`/eval (tests pass a temp dir through a constructor override), not inside `Storage::disk('medical')->path('')`, `MANIFEST.json` with `"synthetic": true`, `generator` and `items[{id, doc, condition, kind: image|pdf|probe, file, sha256}]`, every listed file present as a regular file (no symlink), extension png, jpg or pdf, sha256 equal, no unlisted files except `report*`, `state.json` and `work/`. Ground truth is read from `tests/Fixtures/ocr-eval` (base_path) by `doc` id.
- `ai:ocr-eval` signature: `{--dir=} {--stage=*} {--max-calls=150} {--out=} {--confirm-synthetic} {--pause=5}`. Guards in order, each a single refusal line and exit 1: environment is `staging` or `testing`; `--confirm-synthetic` present; `Preflight` env keys clean; `Corpus::load` valid; no row in `jobs` on the `ai` or `ai-bulk` queue, no open bulk run and no extraction in `queued`, `running` or `waiting`; the codex agent reports a usable login. Stages per research "Call budget" A (resolution probe, 4), B (noise floor, 6), C (screening, A0 and A5 on 7 conditions), D (ablation A1, A2, A4 and A3 only where A5 beat A0 beyond the margin), E (pipelines P0, P1 reusing stage C transcripts of clean and phone items, P2 combined), F (PDF at scale 1800 and 2048 through the existing PdfRasterizer with a per-call scale override), G (Copilot: one transcription and one extraction, skipped with reason when Copilot is not enabled or not logged in). A0 sends the image after the real ingestion normalisation (the ImageProcessor call MedicalDocumentStore uses, 3600 px JPEG q90) written to the eval work dir, never to the medical disk. After stage B the command prints the projected total and stops when it would exceed `--max-calls`. Strictly sequential, `--pause` seconds between calls, stop at the first `QuotaExhausted` or auth failure with `stopped_reason`. Progress lines and report rows contain only item id, doc, condition, arm, stage, ok, failure code, ms, preprocess ms, peak MB, token counts and metric numbers. Results accumulate in `<dir>/state.json` (numbers only, plus stage C transcripts needed by stage E kept in `<dir>/work/` on the tmpfs) so a later run with `--stage=D,E` resumes; `--stage=cleanup` deletes `work/` and `state.json`. The report (`--out`, default `<dir>/report-<UTC timestamp>.json`) holds rows, per-arm aggregates, the noise sd, the `EvalDecision` verdicts and the proposed decisions block values (`preprocess`, `pdf_scale`, `pipeline`, `store_text`, measured seconds per page median and p90). The command writes no `ai_calls` row and no database row at all.
- `FakeCodex` additions: `bySchema(array<string,string> $replyByBasename)` replies with the JSON mapped to the basename of the `--output-schema` argument (writing it to the `-o` file as the existing helpers do), and `withUsage(string $json, array $usage)` that also prints a `turn.completed` usage line on stdout.
