## Contracts

- Routes in new `routes/web/health-search.php` (no route model binding, every miss the same answer, like `health-documents.php`):
  - `POST /health/search` -> `DocumentSearchController@search`, middleware `access:module,health,view`, `throttle:30,1,health.search`, name `health.search`.
  - `GET /health/people/{person}/documents/{document}/text` -> `DocumentTextController@show`, `access:module,health,view`, `throttle:60,1,health.documents.text`, name `health.documents.text`.
  - `DELETE /health/people/{person}/documents/{document}/text` -> `DocumentTextController@destroy`, `access:module,health,edit`, `throttle:30,1,health.documents.text.destroy`, name `health.documents.text.destroy`.
- `DocumentSearchRequest`: `q` required string max 200 (SearchTerms cuts to 100); `person` nullable string max 64 (no uuid rule: a malformed value must give the empty result, not a 422); `page` nullable integer 1..50. A request with no usable token answers `{items: [], hasMore: false, page: 1}` with 200.
- `DocumentSearchQuery::search(Viewer $viewer, list<list<string>> $terms, ?string $person, int $page): array{items: list<array>, hasMore: bool}` — one statement built with the query builder starting from `Visibility::apply(DB::table('medical_documents'), $viewer)` (unaliased: Pitfall 4), joined to `medical_subjects` for the person name, LEFT JOIN `medical_document_texts` on `document_id` and `subject_id`, LEFT JOIN `medical_visits` for the visit name only when the visit is not archived (else null), a `to_tsquery('simple', ?)` built from the tokens: each alternative becomes `public.fh_unaccent(lower(?)) || ':*'` joined with `|` inside a token group and `&` between groups, every alternative a bound parameter (tokens contain only letters and digits, never concatenated as text); predicate `(medical_document_texts.search @@ q OR to_tsvector('simple', public.fh_unaccent(medical_documents.title)) @@ q)`; when `$person` is a syntactically valid uuid add `medical_documents.subject_id = ?`, otherwise (malformed) return the empty result without querying; order `coalesce(ts_rank_cd(medical_document_texts.search, q, 32), 0) desc, medical_documents.created_at desc, medical_documents.id`; limit 21 offset (page - 1) x 20; selects body only for these rows. No `ts_headline`, no count query.
- `Snippets::build(string $body, list<list<string>> $terms, int $max = 2, int $radius = 80): array{snippets: list<list<array{text: string, hit: bool}>>, page: ?int}` — tokenise with `\p{L}[\p{L}\p{N}]*` keeping byte offsets, fold each word with `SearchTerms::fold` and compare with `SearchTerms::matches`; first one or two hit windows of about 80 characters either side, cut at word boundaries and never across U+000C; adjacent windows merged; page = 1 + count of U+000C before the first hit; no hit in body -> empty snippets and null page (title-only match).
- Search item JSON: `{documentId, personId, personName, title, uploadedOn (Y-m-d in family time zone), visitId|null, visitName|null, page|null, snippets, textComplete (bool, true when no text), pagesRead|null, pagesTotal|null}`; response `{items, hasMore, page}`.
- `DocumentTextQuery` (request side, scoped like DocumentQuery): `forDocument(Viewer, MedicalSubject, string $documentId): ?DocumentText` (document visible and not archived at View level); `documentIdsWithText(Viewer, MedicalSubject): list<string>`; `anyVisible(Viewer): bool`.
- `DocumentTextController@show`: person resolved through SubjectQuery as the other document routes do; unknown, hidden or archived -> the same 403 as `health.documents.file`; visible without text -> 404; else `{pages: [{page, text}], pagesRead, pagesTotal, complete, language}`. `@destroy`: editor only (route middleware plus `DocumentTextStore::remove`); success -> 204 and audit event; nothing removed -> the same 403 as other write misses (MED_LS parity).
- Audit: new `AuditEvent::MedicalTextRemoved = 'medical_text_removed'`, meta keys `subject`, `record` (ids only, like `MedicalArchived`), module Health, recorded by the controller after a successful remove. AuditTable.vue renders it with `audit.detail.medical_text_removed`; labels en "Removed recognised text in Health", sk draft "Odstránený rozpoznaný text v Zdraví", pl draft "Usunięto rozpoznany tekst w Zdrowiu".
- `PersonPage` props: every `documents[]` item gets `hasText: bool`; new top-level `search: {enabled: bool, textReliability: 'reliable'|'uncertain'}` where `enabled = config('ai.ocr.enabled') || DocumentTextQuery::anyVisible($viewer)` and `textReliability` comes from `config('ai.ocr.text_reliability')` (anything else -> uncertain). The text itself is never a prop.
- `tests/Support/MedicalPrivacy/search.php` area file: params and hidden params for `health.documents.text` and `health.documents.text.destroy`, payloads for `health.search` (a q that matches the hidden canary) and for the destroy route, visible and hidden seeds that store text through `docTextSave`. `MED_LS_GET_INVENTORY` gains `health.documents.text`; the destroy route joins the write parity inventory; `MedicalCacheHeadersTest` covers the search POST and the text GET (no-store, private).
- `tests/Support/EndpointMatrix/health-search.php`: rows for the three routes per role preset (read routes: parent 200, everyone without Health view 403, guest redirect 302; search answers 200 with empty items for members without any visible person only if the access middleware lets them through, else 403 — mirror the existing health matrix rows).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| member browser -> search endpoint | free text query, optional person id, page |
| database -> response | full medical text turned into snippets and text views |
| editor -> remove endpoint | deletes medical content |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-13-19 | Information disclosure | search leaks hidden or archived documents (rows, counts, timing, 403 vs 404) | mitigate | Visibility::apply in the same statement as the text predicate, no count query, LIMIT+1 hasMore, malformed person returns empty without querying, byte-identical differential test, MedicalPrivacy net |
| T-13-20 | Tampering | SQL injection or tsquery operator injection | mitigate | tokens limited to letters and digits by SearchTerms, every alternative a bound parameter inside fh_unaccent(lower(?)), no string concatenation; tests with operator characters |
| T-13-21 | Tampering | HTML injection through snippets or text view | mitigate | PHP {text, hit} segments and plain JSON strings, no ts_headline; 13-05 renders with interpolation only |
| T-13-22 | Information disclosure | medical words in URLs, history, Referer, logs | mitigate | POST JSON body for search, no query logging, no-store; logs checked in DocumentSearchTest |
| T-13-23 | Elevation | view-only member removes text | mitigate | route needs Health edit, store requires Edit membership; tests |
| T-13-24 | Repudiation | text removed without trace | mitigate | content-free audit event medical_text_removed with ids only |
| T-13-25 | Denial of service | expensive queries | mitigate | throttle 30 per minute, 8 tokens max, 100 characters, 20 rows per page, page max 50, GIN index |
</threat_model>
