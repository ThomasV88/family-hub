- Migration `2026_12_02_100000_create_medical_document_texts_table.php` (raw `DB::statement` for extension, function and generated column; Schema builder elsewhere):
  - `CREATE EXTENSION IF NOT EXISTS unaccent`; when it fails and the environment is production or staging, throw a RuntimeException whose message says the owner role must be able to create the trusted `unaccent` extension (same guard style as `2026_11_19_110000_create_ai_call_tables.php`).
  - `CREATE OR REPLACE FUNCTION public.fh_unaccent(text) RETURNS text LANGUAGE sql IMMUTABLE PARALLEL SAFE STRICT AS $$ SELECT public.unaccent('public.unaccent'::regdictionary, $1) $$` (schema-qualified so pg_restore with an empty search_path works; `CREATE OR REPLACE` because `migrate:fresh` drops tables but not functions).
  - Table `medical_document_texts`: `document_id uuid primary key`, `subject_id uuid not null`, `extraction_id uuid null` (plain column, no FK, like ai_calls), `started_by bigint not null` (plain id, no FK, for staging:audit), `agent varchar(20) null`, `model varchar(60) null`, `text_version smallint not null`, `language varchar(5) null`, `pages_read smallint not null`, `pages_total smallint not null`, `complete boolean not null`, `body text not null`, `search tsvector GENERATED ALWAYS AS (to_tsvector('simple', public.fh_unaccent(body))) STORED`, `created_at`, `updated_at` timestamptz. FK `(document_id, subject_id) REFERENCES medical_documents (id, subject_id) ON DELETE CASCADE` (reuses `medical_documents_id_subject_unique`, like `medical_ai_extractions`). CHECKs: `char_length(body) <= 200000`; `text_version >= 1`; `pages_total between 1 and 50`; `pages_read between 0 and pages_total`; `NOT complete OR pages_read = pages_total`; `language IS NULL OR language IN ('sk','pl','en','mixed','other')`. Indexes: `medical_document_texts_search_index` GIN on `search`; btree on `subject_id`.
  - `down()`: refuse with a RuntimeException when any row exists; otherwise drop the table and the function (keep the extension).
  - No GRANT statement: `fh_app` gets table rights through `ALTER DEFAULT PRIVILEGES FOR ROLE fh_owner`, and functions are executable by PUBLIC by default (asserted by a test).
- `config/ai.php` new block `'ocr' => ['enabled' => (bool) env('AI_OCR_ENABLED', false), 'text_reliability' => env('AI_OCR_TEXT_RELIABILITY', 'uncertain'), 'text_version' => 1, 'max_page_chars' => 12000, 'max_total_chars' => 200000]`. `text_reliability` is `reliable` or `uncertain`; anything else reads as `uncertain`. The page batch size and page cap are added by 13-06 from `13-EVALUATION.md`.
- `TextNormalizer::page(string): string`: `mb_scrub` to valid UTF-8, NFC, CRLF and CR to LF, remove U+000C, remove C0 controls except LF and TAB, remove C1 controls, remove bidi and invisible direction marks (U+200E, U+200F, U+061C, U+202A to U+202E, U+2066 to U+2069), strip trailing whitespace per line, cut to `max_page_chars` on a code point boundary. `TextNormalizer::body(list<string> $pages): string` joins normalised pages with U+000C and cuts the total to `max_total_chars` (dropping whole trailing pages first, then cutting the last kept page).
- `DocumentText` (final readonly value object, no Eloquent model on purpose: the text must never ride along on `MedicalDocument` serialisation): `documentId, subjectId, pagesRead, pagesTotal, complete, language, body`; `pages(): list<string>` splits on U+000C.
- `SaveOutcome` enum: `Saved`, `ConsentOff`, `Archived`, `Missing`.
- `DocumentTextStore`:
  - `save(string $documentId, string $extractionId, int $startedBy, ?string $agent, ?string $model, ?string $language, list<string> $pages, int $pagesTotal, bool $complete): SaveOutcome` — job side, unscoped by design (like AiJobQuery): one `DB::transaction`; reads the document's subject; `SELECT ai_consent, archived_at FROM medical_subjects WHERE id = ? FOR SHARE`; document row `archived_at IS NULL` (row locked `FOR SHARE`); returns ConsentOff, Archived or Missing without writing; otherwise upserts by `document_id` with the normalised body, `pages_read = count($pages)`, `text_version = config('ai.ocr.text_version')`, language whitelisted (else null). Never catches exceptions (a QueryException carries bindings; the job's content-free catch handles it).
  - `remove(Viewer $viewer, string $subjectId, string $documentId): bool` — request side: deletes where `document_id = ?`, `subject_id = ?`, `subject_id IN Visibility::subjectIds($viewer, AccessLevel::Edit)` and the document is not archived; requires `$viewer->canEdit()`; returns whether a row was deleted. (The HTTP route and audit event come in 13-04.)
  - `purgeForSubject(Viewer $viewer, string $subjectId): int` — request side, scoped the same way at Edit level; used by setConsent.
- `SubjectQuery::setConsent`: when `$value` is false and the update changed the row, call `DocumentTextStore::purgeForSubject($viewer, $id)` inside the same transaction, after the update (constructor-inject the store).
- `tests/Support/MedicalPrivacy.php`: add `medical_document_texts` to READ_TABLES and MUTATION_TABLES.
- `StagingAudit::rules()`: add `['medical_document_texts', "(started_by in {$real})"]` next to the `medical_ai_extractions` rule.
- `tests/Support/DocumentTextFixtures.php` (new, used by 13-04 and 13-05): `docTextSave(MedicalDocument $doc, list<string> $pages, int $pagesTotal = null, bool $complete = true, ?string $language = 'sk'): void` which turns AI consent on for the person when needed and calls `DocumentTextStore::save`; canary constants `DOC_TEXT_CANARY = 'ZxCanaryOcr'` and a three-language sample (Slovak `Žltačka`, `ľadviny`, `Penicilín`; Polish `zażółć`, `Łukasz`; English `paracetamol`).

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-13-11 | Information disclosure | text attached to the wrong person | mitigate | composite FK (document_id, subject_id) to medical_documents; save derives subject from the document row |
| T-13-12 | Repudiation / privacy | text stored after consent withdrawal or for archived records | mitigate | FOR SHARE lock on the person row and archive recheck inside save's transaction; purge inside setConsent's transaction; tests |
| T-13-13 | Information disclosure | text in exports, emergency card, props, ai_calls, audit, jobs, logs | mitigate | no Eloquent relation on MedicalDocument, arch pins on readers, no logging in the namespace, canary leak test across all sinks |
