## Phase Goal

**As a** family admin who runs the AI document reading, **I want to** choose which AI agents read documents and in what order, have runs wait out or route around an exhausted usage limit, and re-read past documents in bulk with a dry run first, **so that** document reading keeps working on our subscriptions while nobody's accepted data is overwritten and no private content reaches me or any log.

## Contracts

- `AiBulkJobQuery::tick(CarbonImmutable $now): array{enqueued: ?string, reconciled: int, completed: int}` inside one transaction holding `pg_advisory_xact_lock(hashtext('ai-bulk-tick'))`:
  1. Delete `ai_bulk_dry_runs` older than one day.
  2. Reconcile items with `outcome IS NULL` whose extraction is terminal: ready/superseded -> read, failed -> failed, cancelled with reason decided -> skipped, any other cancelled -> cancelled, missing row -> gone. Counting rule (plan checker revision): every count is derived from item rows by outcome, so an item is counted exactly once; nothing increments `skipped_count` during the run.
  3. Completion (step 5 decides it, see there): `eligible_total` is display only and is never part of the completion test.
  4. Gates for the one active run (status active only), any false -> no enqueue: local hour (`ai.local_timezone`) >= `ai.bulk.start_hour`; items enqueued since local midnight < daily_cap; no open item (single flight, includes waiting); now - last_enqueued_at >= `ai.bulk.spacing_minutes`; global active extraction count < `ai.bulk.max_global_active`; `AgentRegistry::candidates([], bulk: true)` not empty. When only the agent gate fails, set `blocked_since` if null; when an item is enqueued, clear it.
  5. Pick `AiBulkEligibility::nextCandidate(scope, runId)` (it already excludes documents that became ineligible after the dry run: consent off, decided, deleted, now active; those simply drop out and never become items). When it returns null and no item of the run is open: complete the run (status completed, finished_at, `skipped_count` written once as the number of skipped items plus `max(0, eligible_total - number of items)`, i.e. the documents that dropped out, audit `AiBulkRunChanged {action: completed, scope, count: read items}` with the run's admin as actor). This completion check runs before the pacing gates of step 4 so a paused-by-cap or off-peak day does not delay it; a paused run is not completed. Otherwise, in one transaction: lock the person row `FOR SHARE`, recheck consent on and kind in (pdf, image) and no accepted decision (a race since the pick: insert the item with outcome skipped and nothing else, so it is counted once through its row); insert the extraction (queued, `bulk_run_id`, `started_by` = run admin, `agent` = first bulk candidate), the attempt-1 `ai_calls` row (with `bulk_run_id`), the item row, the `MedicalAiRunRequested` audit row {subject, document} with the admin as actor, update `last_enqueued_at`. A `23505` on `one_active` (an interactive run won) -> item skipped.
  Returns the new extraction id (dispatched after commit by the command).
- `ai:bulk-tick` (`AiBulkTick`): calls tick; dispatches `RunExtractionJob($id)` on connection database, queue `ai.bulk.queue`; a dispatch exception -> `AiJobQuery::failQueued($id)` (item reconciles to failed); prints only counts.
- routes/console.php: `Schedule::command('ai:bulk-tick')->everyFiveMinutes()->withoutOverlapping()->name('ai-bulk-tick')`.
