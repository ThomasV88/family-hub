## Contracts

- `AiRunQuery`: `ACTIVE = ['queued', 'running', 'waiting']`; `cancel` treats `waiting` exactly like `queued` (immediate `cancelled` reason user, model 'default', `MedicalAiRunFinished` audit; no call row to close); `statusMap` entries gain `availableAt` (ISO 8601, only for waiting), `failureCode` (FailureCode value, only for failed), `agent` and `model` (only for ready; model null when 'default'); `start`: refusal `unavailable` only when `!$registry->anyRunnable()`; the attempt-1 call row and the extraction's agent = first of `candidates()` else first of `enabled()`; on an active run (now including waiting) returns `active` with that id; `noticeAcknowledged(Viewer)` = the viewer's ack row exists and its comma-separated `providers` contains every key of `$registry->providers()`; a start with `acknowledged = true` upserts the ack with `providers` = sorted enabled keys joined by ','; `busy`: the per-user cap counts only rows with `bulk_run_id IS NULL`, the global cap counts all active rows; `QUOTA_FAILURES` unchanged (no quota_exhausted, no quota_timeout).
- `PersonPage` `ai` props gain `providers` (enabled keys in saved order); `noticeAcknowledged` uses the new rule.
- `AiRunController::status` returns `available` = `AgentRegistry::anyRunnable()` (documents payload from the extended statusMap).
- `AiReviewQuery::review` adds `provenance` {agent, model|null} for ready and superseded proposals and `newerWaiting` {id, availableAt}|null when a newer extraction of the same document is waiting; opening a waiting extraction on the review route returns its status (waiting, availableAt) like queued/running in Phase 8.
- `zz_ai_agents.php`: seeds, for the hidden person and for a visible person, one waiting extraction (with available_at) and one ready Copilot-produced extraction (agent copilot, model 'gpt-test-copilot') whose payload carries MedicalPrivacy::CANARY, plus the routes/params the harness needs (status route, review route), following the zz_ai.php structure.
