Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Privacy and gate contract (inherits 07 and 08 entirely)

- Every admin endpoint here (list agents, update agent, move agent, check login, dry run, start, pause, resume, cancel, history) is admin-only server-side with identical 403 `UiErrorState` ("Back to Settings" link) for non-admins. Setting changes and bulk actions are audited before state change, content-free (who, agent, changed field names, enum/boolean/position, a validated model string; bulk: admin id, scope, cap, counts).
- JSON/fetch calls go through `securityFetch`; 423 maps via the existing gate handler. Nothing is replayed. No dry-run result, scope or cap is stored in `localStorage`, `sessionStorage`, IndexedDB or Inertia `remember` (component memory only; a reload discards a dry run, which is the intended freshness rule). Responses `Cache-Control: private, no-store`; the service worker never caches these pages or polls.
- Counts only: the bulk panel, its history and its polls never show a person name, document title, document id, proposal content, or any per-document row. Counts are never broken down by person. A "skipped: AI is off" count is a number, not a list.
- The "Read by" line and "waiting" time are content-free (agent display name, model string validated by pattern, time). They go to anyone who may see the document's status (Edit on the person), the same audience as the 08 status tag. Agent errors, quota transcripts, CLI output and reset-time raw text are never shown in the UI.
- Model strings are rendered with text interpolation only (never HTML), shown as-is (identifier), not translated.
- Provider disclosure stays truthful (Screen 2, "Where the document goes"): the permanent "Sends this document to ..." line names every provider that is currently enabled.

## Screens and Interaction Contract

### 1. Admin "AI agents" section

Focal point: the ordered agent list; the user's job is "which agent runs first, is it signed in, is it switched on".

Placement and structure:
- Settings admin section "AI agents" (nav entry, h2 "AI agents"), after "AI calls". Intro (14/400 muted): "Choose which AI tools read documents and in which order. If the first tool has reached its usage limit, the next one is tried. Nothing here stores a password or a key."
- Then `<ol aria-label="AI agents in order">` of two `AgentCard`s (Codex, Copilot in saved order; order is data, never hardcoded). Claude and Antigravity are not drawn at all (no disabled placeholders).
- Below the list: `BulkRegenPanel` (Screen 3) in its own card, h2 "Bulk re-generation".
- Muted line under the list: "Order and switches apply to new runs. Runs already started are not changed." with link "Open AI calls".

`AgentCard` contents, in order:
1. Header row: position badge (the number "1" / "2", `<span aria-hidden="true">`), h3 agent name ("OpenAI Codex", "GitHub Copilot": proper nouns, not translated), the on/off state tag.
2. Enable row: `UiSwitch` with visible label "Use {agent}" and helper "When off, this tool is never used." The whole row is the 44px target. Toggling saves immediately (see states). Switch label never changes with state.
3. Order row: two secondary buttons with icon and visible text, "Move up" (`ChevronUp`) and "Move down" (`ChevronDown`), each 44px, accessible name "Move {agent} up, now position {n} of {total}" / "Move {agent} down, now position {n} of {total}". Disabled at the ends with `aria-disabled="true"` (focusable, no action, no tooltip; the position text tells why). Position helper (14/400): "Position {n} of {total}. Tried {first | after the first | ...}" is NOT used: keep only "Position {n} of {total}". No drag handle, no drag at all.
4. Model field (`UiField` + `UiInput`, visible label "Model", `autocomplete="off"`, `spellcheck="false"`, `inputmode="text"`). Helper: "Leave empty to use the tool's default model." Placeholder: none (never a fake model name). Secondary "Save model" button beside/under it (Enter in the field saves; it is a single-field form). Validation (client mirrors server; server is the authority): empty allowed; otherwise 1 to 64 characters, `^[A-Za-z0-9][A-Za-z0-9._:/-]*$` (**PROVISIONAL** pattern, the plan may tighten; must equal the server rule). Error text (danger, `aria-describedby`, `aria-invalid`): "Use letters, numbers, dots, dashes, colons or slashes only, up to 64 characters." Validation runs on Save (not on every keystroke); the error clears when the value changes. Unchanged value: Save is `aria-disabled`. Saved value shown after save; no "default" label is invented for empty.
5. Login health: `AiLoginHealthCard` (h4 "{agent} login") exactly the 08 states and behaviour (status tag, "Last checked {datetime}", "Check again" with 3 s polling up to 30 s, then "No answer yet. Try again later."), with `{agent}` in the expired text. Copilot-specific words: none (same text; the expired help names the agent). No login form, token field or credential is ever shown or accepted.
6. Cooldown line (only when the agent has `cooldown_until` in the future): tag "Usage limit reached" plus line "Paused until {when}. It is skipped until then." The state is read-only: no "clear" button (**PROVISIONAL**, conservative: cooldown is the server's decision).

Enable and warning rules:
- Codex defaults: on, position 1. Copilot defaults: off, position 2.
- Enabling an agent is always allowed, regardless of login health. If the agent's health is anything other than "Logged in" at the moment it is on (including Not checked yet, Login expired, AI service not responding), the card shows a non-modal `UiAlert` warn (not `role="alert"`, page content, shown while that state holds, so it also shows on reload): "{agent} is switched on but is not signed in yet ({state}). It will be skipped until it is signed in on the server." plus ghost link-button "Check again". This is the "Copilot enable while not logged in" warning; it applies to both agents so Codex is not special-cased.
- Disabling the only enabled agent: the switch is `aria-disabled="true"` with a visible line under it "At least one tool must stay on, or nobody can run AI. Turn another tool on first." (**PROVISIONAL**; conservative).
- Turning the switch on moves nothing in the order. Disabled agents keep their position and can still be moved.

States (per card, never blocking the whole page):
- Saving (switch, move, model): the control that was used gets `aria-busy="true"`, sibling controls in that card are `aria-disabled` until the response (no concurrent saves), a `Loader` icon plus the word "Saving" (14/400 muted, `role="status"`) appears in the card header. No optimistic reorder: the list reorders after the server answers (consistency over speed, calls are tiny).
- Success: politely announced status (single `role="status"` region for the section), text only: "{agent} is now on." / "{agent} is now off." / "{agent} moved to position {n} of {total}." / "Model for {agent} saved." Plus a short toast with the same text (no names of people ever involved). Header "Saving" disappears.
- Error: inline `UiAlert` danger in the card, `role="alert"` once: "We could not save this. Nothing was changed. Try again." The control returns to its previous value. A 409/stale order (another admin changed the order) reloads the list silently and announces "The order was changed by someone else. It is shown as it is now."
- Empty: if the server returns no agents (misconfiguration), `UiEmptyState` (icon `Bot` muted 32px) heading "No AI tools found", body "Ask whoever runs the server to check the AI setup." no action.
- Load error: `UiErrorState` "Something went wrong" with "Try loading again". Loading: `UiSkeleton` of two cards.
- Another admin editing at once: last write wins; the response is the source of truth.

Reorder focus rules: after "Move up/down" the DOM order changes; focus stays on the same agent's same-direction button. If that button is now disabled (agent reached an end), focus moves to the agent's opposite-direction button. Focus is never lost to `<body>`. Announcement as above.

Keyboard and screen reader:
- Tab order: switch, Move up, Move down, model field, Save model, Check again, then the next card. Enter in the model field saves, Space/Enter activates buttons and the switch (Space). No custom shortcuts, no `tabindex` greater than 0.
- Structure: `<main>`, h2 "AI agents", `<ol>` read as "list, 2 items", each card a `<li>` with `aria-labelledby` = its h3; switch announces "Use OpenAI Codex, switch, on"; order buttons carry the position names above; model field announces label, helper and error; the position badge is `aria-hidden` because the position is in the button names and "Position {n} of {total}" text.
- Health card polls announce only transitions ("{agent} is signed in.", "{agent} login expired.").

### 2. Waiting for AI quota, provenance, and cancel (documents, lists, review header)

Focal point: one tag that answers "why isn't it done, and when will it retry", with Cancel as the only action.

Status table (additions to the 08 table; 08 states unchanged):

| State | Tag | Detail line (14/400 muted) | Next action |
|-------|-----|----------------------------|-------------|
| waiting (available_at in the future) | Waiting for AI quota, retrying after {when} | "The AI services have reached their usage limit. We will try again by themselves. You can leave this page." | "Cancel run" |
| waiting (available_at passed, still waiting) | Waiting for AI quota, retrying soon | same line | "Cancel run" |
| failed (24 h of waiting exceeded, code `quota_timeout`) | AI could not read this | "The AI usage limit did not come back in time. Nothing was saved. Try again later, or add the details by hand." | "Run AI again" |
| ready, with provenance | Suggestions ready | "{n} suggestions to review." then the provenance line below | Primary "Review suggestions" |

- `{when}`: the reset time in the family time zone via `Intl.DateTimeFormat`, time only (`HH:MM` per locale, 24 h in SK/PL, locale default in EN) when it is today, otherwise weekday plus time ("Tue 03:10"); wrapped in `<time datetime>`. Never rendered without `<time>`. The tag is a `UiTag`; it holds the full sentence and wraps.
- Where it shows: `DocumentPanel` (tag + detail + Cancel run, replacing the Run AI button exactly like queued/running), document rows in timeline and folder lists (tag only, the short text "Waiting for AI quota" without time to keep rows calm; the time is in the panel), and the review header (see below). It never shows on a document with a superseded or terminal run.
- Cancel while waiting: secondary "Cancel run" (`Ban`), immediate, no confirm (nothing is lost), toast "Run cancelled", status becomes "Cancelled", focus returns to "Run AI". Same endpoint and copy as 08. If a fallback attempt had just started when the user cancelled, the 08 rule applies: stays as-is until the worker confirms. Copy never claims nothing was sent after a start.
- Fallback is invisible in the status (no "trying Copilot" text, no per-attempt tags on the document); only the provenance line and the admin AI calls rows show which agent did the work. Moving from Codex to Copilot is not announced to the user because the permanent provider line (below) already discloses it.
- Polling: extends the 08 `useAiStatus` poller (no new mechanism). While status is `waiting`, poll every 60 seconds (visible tab only, pause when hidden, resume on `visibilitychange`), stopped on any terminal state, and after 60 minutes of continuous visible waiting stop with "Still waiting. Reload the page to check again." (**PROVISIONAL**; the 5 s / 15 s / 15 min rule still governs queued and running). A status change from waiting to queued or running returns to the faster schedule.
- Announcements: transitions only via the single `role="status"` region: "Waiting for AI quota. Retrying after {when}." on entering waiting; then "AI is reading this document.", "Suggestions are ready.", "AI could not read this document.", "Run cancelled." as in 08. Polls that change nothing announce nothing. `aria-busy="true"` on the status block while waiting, `Hourglass` is `aria-hidden`.
- Loading: the 08 tag-height `UiSkeleton`, no layout jump.

Review header (`AiReviewPage`):
- Provenance line (14/400 muted) directly under the existing status tag row: "Read by {agent} {model}" (for example "Read by GitHub Copilot gpt-5"), and when the model is empty or unknown: "Read by {agent}". `<time>` of the run stays on its existing line. The line is also shown in `DocumentPanel` under the "{n} suggestions to review." detail when status is ready (the same `AiProvenanceLine`). It is not shown in lists, toasts or `aria-live` text.
- If a newer run is waiting for quota while an older ready proposal is open: below the provenance line a neutral tag with `Hourglass`, "A newer run is waiting for AI quota, retrying after {when}" and ghost "Cancel run" (Edit only). The older proposal stays fully reviewable (it is not superseded until a newer one is ready; if it becomes ready the 08 superseded banner applies). Reviewing continues without interruption; the line is the only change.
- A waiting extraction opened directly on the review route behaves like queued/running in 08: the review page shows the status block (tag, detail, Cancel run) instead of panes.
- "Read by" for a Copilot result stays plain text: model output never becomes part of the line, only the registered agent name and the validated model string.

Where the document goes (permanent provider line, REPLACES the 08 fixed line):
- The always-visible muted 14/400 line under "Run AI" names every enabled provider, derived from `ai_agent_settings` (enabled only):
  - Only Codex on: "Sends this document to OpenAI."
  - Both on: "Sends this document to OpenAI, or to GitHub if OpenAI is not available."
  - Only Copilot on: "Sends this document to GitHub."
- One-time notice (`AiNoticeDialog`): the 08 notice is kept for the Codex-only world. When Copilot is enabled for the first time, members who acknowledged the old notice see an updated notice once on their next "Run AI" (**PROVISIONAL**: server stores a notice version per member; version bumps when the set of enabled providers gains a provider, never when one is removed). Updated title "Send this document to OpenAI or GitHub?" body "This document will leave this server and be sent to OpenAI, or to GitHub if OpenAI is not available, to be read. They may keep it under their own terms. You will check every suggestion before anything is saved. You will see this notice again only if another service is added." Buttons unchanged: primary "Run AI", safe default-focus "Keep document private" (08 checker follow-up; Esc and backdrop equal it). The same request records the acknowledgment and queues the run.
- Admins see a one-line reminder under the Copilot switch when turning it on: "Documents may then be sent to GitHub. Members will see a new notice before their next run." (muted, not an alert).
- Unavailable states for non-admins (08 line) also apply when every enabled agent is expired/down; a cooling-down or waiting state is NOT unavailable: Run AI remains available and the run queues into waiting.

### 3. Admin "Bulk re-generation" panel

Focal point: the dry-run result, because the whole panel exists to make "what will this do" visible before anything leaves the server.

Panel (`UiCard`, h2 "Bulk re-generation", inside the AI agents page). Intro (14/400 muted): "Read past documents again with AI. First check what would be read. Nothing you or a member already accepted is ever changed, and you see only counts, never names or content."

Layout states of the panel (exactly one block active, mutually exclusive):
A. Plan block (no active run): scope, cap, dry run, Start.
B. Active run block (a run is running, paused or waiting): progress, controls. The plan block is hidden and replaced by the line "A bulk run is active. Pause or cancel it before planning another."
C. History table below in both cases.

A. Plan block:
1. Scope: `role="radiogroup"` with visible legend "Which documents?" and three radio rows (44px rows, description 14/400 under each label):
   - "Documents without any suggestions yet" (default)
   - "Documents whose latest AI run failed"
   - "All documents" with description "Documents with accepted suggestions are still skipped."
   Arrow keys move and select (radiogroup pattern of `ViewSwitch`); one Tab stop.
2. Cap: `UiField` + number `UiInput` (`inputmode="numeric"`, `min=1`), label "Runs per day", helper "At most {max}. One run at a time, starting after {hour}." default `20` (config default; `{max}` and `{hour}` come from config, hour shown in the family time zone in locale time). Error (on blur or on dry-run press): "Choose a whole number from 1 to {max}." Non-numeric input is rejected by the field and shown as the same error.
3. Dry run: secondary button "Check what would run" (`Layers` not used; no icon beyond optional `ListChecks` from 08). While the call runs: button `aria-busy`, label stays, status "Checking..." (`role="status"`), other controls `aria-disabled`.
4. Result block (`<section aria-labelledby>` h3 "Result of the check", surface-2): `<dl>` rows, numbers only:
   - "Documents that would be read": {n} (emphasised 16/600)
   - "Skipped: AI is off for the person": {n}
   - "Skipped: file type cannot be read by AI": {n}
   - "Skipped: already has suggestions you accepted from": {n}
   - "Skipped: already waiting or running": {n}
   - "About {days} days at {cap} per day" (derived, plural key; shown only when eligible > 0)
   - "Checked at {time}" (`<time>`, 14/400 muted) and "This check is valid for {minutes} minutes." (config, **PROVISIONAL** 15 minutes).
   Zero eligible: the block shows the numbers plus the line "Nothing would be read with these settings." and Start stays disabled.
   Focus moves to the h3 (`tabindex="-1"`) when the result arrives; the region announces once: "Check finished. {n} documents would be read." Counts never include a per-person breakdown, titles or ids.
5. Freshness rule ("fresh dry run"): a dry run is fresh only when it succeeded, is not older than its validity window, and scope and cap are unchanged since. Changing scope or cap, expiry, or a server-side 409/410 for the token marks it stale: the result block dims, a `UiAlert` warn appears "This check is out of date. Check again before starting." and Start is disabled. The server also enforces this via the dry-run token; the UI never infers freshness from the clock alone for the final word.
6. Start: primary `UiButton` "Start bulk run" (the only accent button in the panel). Disabled-until-fresh is implemented as `aria-disabled="true"` (focusable, press announces the reason) with a permanent visible line beneath it: "Check what would run first." (no fresh check) or "The last check is out of date. Check again." (stale) or "Nothing would be read with these settings." (zero eligible). The line is the button's `aria-describedby`.
7. Start confirm (`UiConfirmDialog`, not danger because it queues, it deletes nothing; it does send documents): title "Start bulk re-generation?" body "{n} documents will be sent to {providers} to be read, at most {cap} per day, one at a time, after {hour}. Nothing already accepted is changed. You can pause or cancel at any time." where `{providers}` is the same enabled-provider wording as Screen 2 ("OpenAI", "OpenAI or GitHub", "GitHub"). Buttons: primary "Start bulk run" / safe secondary "Do not start" (default focus; Esc and backdrop equal it). Confirm uses the dry-run token; a 409/410 closes the dialog and shows the stale alert. Success: toast "Bulk run started", panel switches to block B, focus moves to the "Progress" h3.
8. Start errors (inline `UiAlert` danger, `role="alert"` once, above Start): "We could not start the run. Nothing was sent. Try again." Dry-run error: "We could not check what would run. Nothing was started. Try again." Another admin started a run meanwhile (409): panel switches to block B without an error and announces "A bulk run is already active."

B. Active run block:
- State tag (Color table), h3 "Progress", `UiProgress` (`role="progressbar"`, `aria-valuenow` = handled, `aria-valuemax` = total, `aria-valuetext` = the visible sentence) with the visible sentence "{done} of {total} documents handled" (plural key).
