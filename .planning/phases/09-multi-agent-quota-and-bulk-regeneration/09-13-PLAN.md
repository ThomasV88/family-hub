## Phase Goal

**As a** family admin who runs the AI document reading, **I want to** choose which AI agents read documents and in what order, have runs wait out or route around an exhausted usage limit, and re-read past documents in bulk with a dry run first, **so that** document reading keeps working on our subscriptions while nobody's accepted data is overwritten and no private content reaches me or any log.

## Contracts

- `AiBulkEligibility` (final, App\Medical\Queries; docblock "Counts and candidate selection for bulk re-generation. Selects no names, titles or content."): `counts(string $scope): array{eligible: int, skipped_consent: int, skipped_unsupported: int, skipped_decided: int, skipped_active: int}` as one aggregate query (research Code Examples), buckets in priority order unsupported (`d.kind NOT IN ('pdf','image')`), consent off, decided (any `accepted` decision on any extraction of the document), active (queued/running/waiting), else eligible; scope predicates `no_proposal` (no ready or superseded extraction), `last_failed` (newest non-superseded extraction failed, ordered `queued_at DESC, id DESC`), `all`. `nextCandidate(string $scope, string $runId): ?array{document_id: string, subject_id: string}` = the same eligible predicate, not already an item of the run, outside the Phase 8 per-document cool-down, `ORDER BY d.created_at, d.id LIMIT 1` (used by 09-14).
- `AdminAiBulkQuery` (final; docblock "Admin bulk planning and control. Integers, enums and times only."):
  - `dryRun(User $admin, string $scope, int $cap): array{token, checkedAt, validMinutes, counts}`: audits `AiBulkRunChanged {action: dry_run, scope, count: eligible}` then inserts the `ai_bulk_dry_runs` row with the counts.
  - `start(User $admin, string $token, bool $acknowledged): array{result: ok|expired|stale|active, panel?}` in one transaction: `FOR UPDATE` on the dry-run row; another admin's token, a consumed token or age > `ai.bulk.dry_run_ttl_minutes` -> expired; recount `counts(scope)['eligible']` differs -> stale; insert the run (`active`, scope and cap from the row, `eligible_total`, `dry_run_id`) where a `23505` on `ai_bulk_runs_one_open` -> active; set `consumed_at`; upsert the admin's `ai_notice_acks.providers` to the current enabled providers (the confirm dialog names them). This is the acknowledgment that applies to every run of the bulk job: 09-10 restricts bulk attempts to the starting admin's acknowledged providers, so a provider enabled after Start is not used until the admin acknowledges it again; audit `started` with count eligible.
  - `pause(User, string $runId)`, `resume(User, string $runId)`: status flip (`paused_at`), audited, invalid transition -> result 'conflict'.
  - `cancel(User, string $runId)`: run -> cancelled with `finished_at`, then `AiBulkJobQuery::cancelRunExtractions($runId, $admin->id)`, audited `cancelled` with the count of stopped items.
  - `panel(): array{active: ?array, history: list<array>}`: active = {id, status, state (running|paused|next_batch|waiting_quota|stopped), scope, dailyCap, total, done, read, failed, skipped, waiting, left, todayUsed, nextBatchAfter (ISO|null), availableAt (ISO|null)}; counts come from the run's items only (each item counted once by its outcome: read, failed, cancelled, skipped; open items counted as waiting or in flight), `total` = `eligible_total` from the dry run (display only), `left` = max(0, total - items); `skipped_count` on the run is not incremented during the run: 09-14 writes it once at completion; `state` derived: paused when paused; stopped when `blocked_since` older than `ai.bulk.stopped_after_hours`; waiting_quota when an open item's extraction is waiting (availableAt = its available_at); next_batch when today's cap is used or the local hour is before `ai.bulk.start_hour` (nextBatchAfter = next start hour in `ai.local_timezone`); else running. history = last `ai.bulk.history` finished or open runs {startedAt, scope, dailyCap, wouldRead, read, failed, skipped, status}. The run id is the only id returned (needed for controls); no started_by, no document or person ids.
- `AiBulkJobQuery` (final, App\Medical\Queries; docblock "Unscoped by design: system side of bulk runs, no viewer. Lifecycle columns only; never returns names."): `cancelRunExtractions(string $runId, ?int $actorId): int` sets the run's `queued` and `waiting` extractions to `cancelled` reason user, with `available_at = NULL` in the same UPDATE (CHECK `(available_at IS NOT NULL) = (status = 'waiting')`) and `waiting_since` left unchanged as history, (closing their open call rows, one `MedicalAiRunFinished` audit row each with status cancelled) and sets `cancel_requested_at` on its `running` extraction; returns the count. MD_MUT_ALLOWLIST gains `'AiBulkJobQuery' => 'ai-bulk scheduler and bulk cancel: queued extraction rows and lifecycle columns only, no viewer, no content (09-13)'` and the pinned key list becomes ['AdminSubjectQuery', 'SystemQuery', 'AiJobQuery', 'AiBulkJobQuery'].
- Controller and routes (added to 09-12's files): `GET /settings/ai-agents/bulk` `settings.ai_agents.bulk` (`access:admin`, `throttle:60,1`) -> panel JSON, no-store; `POST /settings/ai-agents/bulk/dry-run` `settings.ai_agents.bulk.dry_run` (admin, recent, `throttle:12,1`) validates `scope` `in:no_proposal,last_failed,all`, `cap` `integer|min:1|max:{ai.bulk.max_cap}`; `POST /settings/ai-agents/bulk` `settings.ai_agents.bulk.start` (admin, recent, `throttle:6,1`) validates `token` uuid, `acknowledged` accepted -> 201 {panel} / 410 {reason: expired} / 409 {reason: stale} / 409 {reason: active, panel}; `POST /settings/ai-agents/bulk/{run}/pause|resume|cancel` (admin, recent, `throttle:12,1`) -> 200 {panel} / 404 unknown run / 409 conflict. `index` gains props `bulk` (panel) and `bulkConfig` {defaultCap, maxCap, startHour, timezone, validMinutes}. SensitiveRoutes: the POST names in `accessGranting()` (bulk start sends many documents out), the GET in `grantAllowlist()` ("bulk counts only"). Matrix rows for every new route.
