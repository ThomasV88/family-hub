## Phase Goal

**As a** family admin who runs the AI document reading, **I want to** choose which AI agents read documents and in what order, have runs wait out or route around an exhausted usage limit, and re-read past documents in bulk with a dry run first, **so that** document reading keeps working on our subscriptions while nobody's accepted data is overwritten and no private content reaches me or any log.

## Contracts

- M1 `create_ai_agent_settings`: table exactly as research Q4 M1 (agent PK varchar(20) CHECK in ('codex','copilot'), enabled, position smallint 1..9 with `UNIQUE (position) DEFERRABLE INITIALLY DEFERRED`, model varchar(60) NULL with CHECK `^[A-Za-z0-9][A-Za-z0-9._:-]{0,59}$`, updated_by bigint NULL without FK, updated_at); seed ('codex', true, 1, null), ('copilot', false, 2, null); `ai_agent_status` adds `cooldown_until timestamptz NULL`, `quota_hits smallint NOT NULL DEFAULT 0`, `last_quota_at timestamptz NULL`; `ai_notice_acks` adds `providers varchar(40) NOT NULL DEFAULT 'codex'`. Down drops what it added.
- M2 `extractions_waiting_and_bulk_columns`: research Q4 M2 verbatim (status CHECK with 'waiting', cancel_reason CHECK with 'decided', columns available_at, waiting_since, bulk_run_id uuid, waiting CHECK `(available_at IS NOT NULL) = (status = 'waiting')`, recreated `medical_ai_extractions_one_active` and `_open_index` with waiting, new `medical_ai_extractions_waiting_due_index`; `ai_calls.bulk_run_id uuid NULL`, `ai_calls_extraction_attempt_unique`, `CREATE OR REPLACE FUNCTION ai_calls_guard_update()` with the identical body plus `bulk_run_id` in the immutable identity list). Down throws a RuntimeException naming the count when any row is `waiting` (never silently rewrites rows), otherwise restores the Phase 8 constraints, indexes and function body.
- M3 `create_ai_bulk_tables`: research Q4 M3 (ai_bulk_dry_runs, ai_bulk_runs with CHECKs scope in ('no_proposal','last_failed','all'), status in ('active','paused','cancelled','completed'), daily_cap 1..100, `ai_bulk_runs_one_open` unique on `((true)) WHERE status IN ('active','paused')`, plus `blocked_since timestamptz NULL`; ai_bulk_run_items PK (bulk_run_id, document_id), outcome varchar(10) NULL CHECK in ('read','failed','cancelled','skipped','gone'), `ai_bulk_run_items_enqueued_index`). Plain id columns, no foreign keys (history survives deletion). Created by `fh_owner`; `fh_app` DML comes from the default privileges.
- Models (no `Medical` prefix, research Q4): `AiAgentSetting` (table ai_agent_settings, primaryKey 'agent', string key, non-incrementing, timestamps off, casts enabled bool, position int), `AiBulkRun` (uuid key via HasUuids, casts for times and ints), `AiBulkDryRun` (uuid key, casts). No business logic in models; reads and writes go through Query classes in later plans.
- Factories: `MedicalAiExtractionFactory::waiting(?CarbonInterface $availableAt = null)` (status waiting, available_at default now + 30 min, waiting_since now, started_at null), `::bulk(string $runId)` (sets bulk_run_id); new `AiBulkRunFactory` with states `active()`, `paused()`, `cancelled()`, `completed()`.
