## Contracts

- `AiJobQuery` (stays the allowlisted system query; no new class touches medical tables here):
  - `claim(id)` additionally returns `bulk_run_id`; when no open ai_calls row exists (resumed run) nothing else changes.
  - `beginAttempt(string $id, string $agent, ?string $bulkRunId): int` (attempt number): if the open (running/queued) call row has the same agent it is reused (moved to running); if its agent differs it is closed `cancelled` (it never ran) and a new row is inserted `running` with `attempt = max + 1`, `queued_at = started_at = now`, `agent`, `bulk_run_id`; with no open row a new row is inserted the same way.
  - `closeAttempt(string $id, string $status, FailureCode $code, string $model, int $durationMs): void` closes only the open call row (extraction stays running).
  - `parkWaiting(string $id, CarbonImmutable $availableAt): bool` per research SQL (only `running` and not cancel-requested; `waiting_since = COALESCE(waiting_since, now())`); `waitingSince(string $id): ?CarbonImmutable`.
  - `resumeDue(int $limit = 20): list<array{id: string, bulk_run_id: ?string}>` per research SQL (FOR UPDATE SKIP LOCKED, `queued_at = now()`, available_at NULL); `rewait(string $id): void` (back to waiting, available_at now + 1 minute) for a failed dispatch.
  - `finishReady(..., string $agent, string $model, ...)`: records the producing agent on the extraction row; for a row with `bulk_run_id`, after the existing locks, if the document's current ready proposal has any `accepted` decision, finish the new row `cancelled` with reason `decided` (no supersede) and return false.
  - `reapStuck()` additionally fails `waiting` rows with `waiting_since < now - (ai.quota.wait_cap_hours h + 5 min)` as `failed(quota_timeout)`, setting `available_at = NULL` in the same UPDATE (required by the CHECK `(available_at IS NOT NULL) = (status = 'waiting')`) and keeping `waiting_since` unchanged (historical anchor of the cap, never cleared), model 'default', with a `MedicalAiRunFinished` audit row {subject, document, status: failed} (actor = starter or null). The `queued` branch and its 6 h rule are unchanged.
  - `bulkRunCancelled(string $bulkRunId): bool` (reads ai_bulk_runs.status).
  - `ackedProviders(?int $userId): list<string>` (reads the user's `ai_notice_acks.providers`, comma-separated keys; empty list when there is no row or no user).
  - Every exit from `waiting` sets `available_at = NULL` in the same statement and leaves `waiting_since` as it is: resume (waiting -> queued), reaper (waiting -> failed), user cancel (09-11) and bulk cancel (09-13). `waiting_since` is only ever written by the first park.
- `RunExtractionJob` (constructor unchanged, ids only; `$timeout` = `ai.timeouts.job` 660): claim -> recheck -> `Preflight::envKeysClean` -> document, work dir, rasterize once -> `$allowed = $jobs->ackedProviders(started_by)` (re-read before every attempt, so an acknowledgment made meanwhile counts; for bulk rows this is the starting admin's acknowledgment, which 09-13 records at Start from the providers named in the confirm dialog) -> `$tried = []`, `$deadline = now + job budget - 30` -> loop `while ($agent = $registry->nextCandidate($tried, $bulk, $allowed))`: recheck (abort: finishCancelled with consent/access/user reason, next agent never started); `beginAttempt`; `extract(new AgentInput(..., deadline: $deadline), abortClosure)`; recheck again (late result discarded as in Phase 8); ok -> `finishReady` (false -> finishCancelled mapping as Phase 8 WR-01; `decided` reason for the bulk guard) + `recordSuccess`, stop; `QuotaExhausted` -> `recordQuotaHit(agent, resetAt, minutes)` + `closeAttempt(failed, quota_exhausted)`, add to tried; `Auth` -> `recordAuthFailure` + `closeAttempt(failed, auth)`, add to tried; any other failure -> `finishFailed(code)` (terminal). No candidate left: if no enabled agent is in `$allowed` at all (for example Copilot was enabled and Codex disabled after the user acknowledged a Codex-only notice) -> finishFailed(`notice_required`) without any spawn; otherwise `$resume = $registry->earliestResume($bulk, $allowed)`; null -> finishFailed with the last attempt's code (`auth` or `quota_exhausted`) or `no_agent` when nothing was tried; `$resume > (waitingSince ?? now) + wait_cap` -> finishFailed(`quota_exhausted`); otherwise `parkWaiting($id, $resume)` (false because cancel was requested -> finishCancelled(user)). Before beginning an attempt with less than `ai.timeouts.min_call` seconds left: finishFailed(`timeout`). Audit `MedicalAiRunFinished` only on terminal finishes, never on park. Work dir cleanup in finally on every path, including park.
- Recheck for bulk rows (claim has `bulk_run_id`): starter user exists, active and `is_admin`; `bulkRunCancelled` false (else cancelled reason user); `AiConsent::allows` (else consent). Interactive rows keep the Phase 8 recheck (AccessGate::forget + Health Edit + member editor + consent + cancel).
- Resumed runs: the provider-acknowledgment filter above runs inside the job at claim and before every attempt, so a run resumed by `ai:resume-waiting` is held to the starter's acknowledgment at resume time, not at queue time.
- `ai:resume-waiting` (`AiResumeWaiting`): `resumeDue()`, then after commit dispatch `RunExtractionJob` per id on `ai.queue`, or on `ai.bulk.queue` when `bulk_run_id` is set; a dispatch exception -> `rewait(id)`; prints only the count.
