## Phase Goal

**As a** family admin who runs the AI document reading, **I want to** choose which AI agents read documents and in what order, have runs wait out or route around an exhausted usage limit, and re-read past documents in bulk with a dry run first, **so that** document reading keeps working on our subscriptions while nobody's accepted data is overwritten and no private content reaches me or any log.

<objective>
Make usage-limit attempts visible and filterable in the admin call log, and drop the login card data from the AI calls page now that the card lives in AI agents.

Purpose: AI-06 (admins see how fallback happened; each attempt is a row); CONTEXT "Each attempt is its own ai_calls row (agent and model recorded per attempt)"; research C7 ("Usage limit reached" call filter), Q3 "Visibility" (filter value `quota`); UI-SPEC Screen 4 (status tag "Usage limit reached" warn with Hourglass, filter option, no bulk labelling: PROVISIONAL 10) and the AiLoginHealthCard row (card moves, PROVISIONAL 8: changes 08-17 output).
Deliberate tightening (plan checker revision, recorded in DEFERRED.md and confirmed in 09-20 under A10): the UI-SPEC accepted that the AI calls log keeps showing person names under the Phase 8 admin exception for every row. For rows with a `bulk_run_id` that would tell the admin which people's documents bulk processed, which CONTEXT ("the admin sees counts and status only, never person names ... for people they cannot otherwise see") and the A10 framing (consent is the only gate, the admin sees counts only) do not allow. Bulk rows therefore have their person masked; interactive rows keep the Phase 8 behaviour.
Output: query filter, row flags and bulk masking, controller prop change, filter option, tag and masked cell, tests.
</objective>
