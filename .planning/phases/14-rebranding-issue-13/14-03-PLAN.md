## Placement decisions (Claude's Discretion in CONTEXT, following the brand guide usage page)

- Variants: light theme uses `/icons/familyhub-logo.svg` (kit primary: mark and orange wordmark on the peach brush, aspect about 2.94:1); dark theme uses `/icons/familyhub-logo-dark.svg` (kit mono-for-dark-bg: all white, no brush, aspect about 5.49:1), per the guide rule "use mono-for-dark assets on dark backgrounds". Size is set by height only, width auto (guide: always scale uniformly). No shadow, filter or opacity on the logo (guide don'ts).
- Theme selection mirrors tokens.css: dark when `:root[data-theme="dark"]`, or when the system prefers dark and `:root` is not `[data-theme="light"]`. Both images are rendered; CSS hides one with `display: none`, which also removes it from the accessibility tree, so both carry the same alt text.
- Sizes: top bar 32px high (fits the 56px bar); AuthLayout 64px high with `margin-block: var(--space-4)` to approximate the guide's clear space (icon height) around it; offline page 56px.
- Error pages: the 403 page (resources/js/Pages/Errors/Forbidden.vue) renders inside AppShell, so the top bar logo covers it. Other HTTP errors use Laravel's built-in minimal pages, which never showed the old name or mark; they stay as they are.
- Alt text: TopBar keeps its existing `appName` computed (`page.props.app?.name ?? t('app.name')`); AuthLayout uses `t('app.name')` (FamilyHUB after 14-04) so it needs no usePage mock in the auth tests.
- Not a link: the top bar name was not a link before; the logo is not made one (no behaviour change).
- offline.html is static and precached: it can use only prefers-color-scheme, with `<picture><source media="(prefers-color-scheme: dark)" srcset="/icons/familyhub-logo-dark.svg">` and an `<img src="/icons/familyhub-logo.svg" alt="FamilyHUB" height="56">`; both files are precached by 14-02, so the logo works offline.
