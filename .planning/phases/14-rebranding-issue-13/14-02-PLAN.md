## Facts gathered while planning

- Kit files (`.planning/phases/14-rebranding-issue-13/brand-kit/`): favicon/android-chrome-192x192.png and android-chrome-512x512.png (transparent, mark nearly edge to edge), favicon/apple-touch-icon.png (180x180, transparent: iOS would render it on black), favicon/favicon.ico (16 and 32 px), png/icon-1024.png (1024x946, transparent), logo/*.svg. The SVGs colour paths through `fill="var(--color-N)"` with the map in a `style` attribute on the outer `<g>` (`--color-1: #f2963e; --color-2: #e54738; --color-3: #1c4e9a; --color-4: #e8897a`, all #ffffff in mono-for-dark-bg.svg) and carry `<title>Logo</title>` plus `aria-label` attributes such as "Container vecteezy_vector-black-brush-lines-set_109463.svg".
- No kit maskable icon exists. Maskable safe zone: everything must fit in a centred circle of 80 percent of the side. For a 1024x946 source scaled to width s the diagonal is about 1.361 s, so s at most 602 on a 1024 canvas; use 560 (diagonal about 74 percent).
- Precache allowlist (scripts/check-sw-precache.mjs) accepts `icons/<name>.(png|svg)` and `offline.html`; vite.config.js globs `icons/*.{png,svg}`, so every file in public/icons is precached (keep only files that are used).
- nginx serves /icons/ with `Cache-Control: public, max-age=604800`; renaming the files is the cache-bust. favicon.ico is served from the web root by `location /`.
- ImageMagick 6 (`convert`, `identify`) is installed on the host; no new package is needed. `@vite-pwa/assets-generator` and `pwa-assets.config.js` generated the old blue "FH" icons from public/icons/icon.svg; that source is removed here.
</context>
