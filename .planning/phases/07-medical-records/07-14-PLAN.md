## Facts

- Routes (07-10, 07-12): POST `/health/people/{person}/documents` (multipart `file`, `title`, `visit_id`; JSON 201/422), GET `.../documents/{document}/preview/{thumb|view}` (images only), GET `.../documents/{document}/file` (attachment), PATCH `.../documents/{document}` (title, visit_id), DELETE `.../documents/{document}`.
- Server limits: `config('medical.document_max_bytes')` (10 MiB) and `config('medical.upload_batch_max')` (10).
- HEIC cannot be previewed (no decoder in the image): show the no-preview card; never attempt a client-side conversion.

## Contracts this plan adds

- PersonPage props: `documents` (list of `{id, kind, title, visitId, uploadedOn, sizeBytes}`; never path, sha256 or mime details beyond kind), `limits` (`{maxMb, filesAtOnce}` from config), each visit's `documentCount` (scoped count of this person's documents per visit), timeline entries `{type: 'document', id, date: uploadedOn}` for documents without a visit, the `documents` filter key when any exist, and folder data for "Documents without a visit" (ids of unattached documents). Panel kinds: `new-document` (edit only; optional `visit` query parameter must resolve to this person's visit, else 403) and `document` with id (403 on miss).
