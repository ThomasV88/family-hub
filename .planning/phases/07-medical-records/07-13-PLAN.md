## Shared rules

Same as earlier slices; parameter name `vaccination` carries the PUBLIC uuid (`public_id`); the bigint id never appears in URLs, props, area files or responses. Today = family-timezone date computed in PHP. Due status is computed by the server only.

**authorize() first (phase-wide rule for every record FormRequest, checker W1):** the FormRequest's `authorize()` resolves `{person}` with `SubjectQuery::findVisible(Viewer::for($this->user()), (string) $this->route('person'), AccessLevel::Edit)`, stores the result on the request (a `subject(): MedicalSubject` accessor the controller uses instead of a second lookup) and returns false on null. A failed authorize() throws AuthorizationException, which bootstrap/app.php renders as the same Errors/Forbidden 403 page as abort(403), so a hidden, unknown or malformed person (and a View-only member) gets the one identical 403 before any validation runs and a validation error can never reveal that a hidden id exists. Record ids (`{visit}`, `{allergy}`, `{medication}`, `{vaccination}`, `{document}`) are still resolved in the controller through the record query (miss -> abort(403)). Every slice adds a test: an invalid body (e.g. empty required field) sent to a hidden person id, the own_off person id, a random uuid and 'abc' gives the identical 403 (status and body equal to a valid body sent to a random uuid; no 302/422 validation response and no session errors). Both VaccinationRequest and MarkVaccinationGivenRequest follow it.

## Contracts this plan creates

- Table `medical_vaccinations`: id bigint generated always as identity PK (internal: `notification_outbox.subject_id` and `audit_logs.subject_id` are unsignedBigInteger), public_id uuid NOT NULL UNIQUE (v4), subject_id uuid FK cascade, vaccine varchar 120 NOT NULL, given_on date NOT NULL, next_due_on date NULL, notes varchar 500 NULL, CHECK (next_due_on IS NULL OR next_due_on >= given_on), provenance columns and CHECK as medical_visits, created_by, timestampsTz; partial index on next_due_on WHERE next_due_on IS NOT NULL; index (subject_id).
- Model MedicalVaccination: `$hidden = ['id']`, public_id set via `Str::uuid()` on creating, no route key binding (controllers resolve explicitly).
- `App\Medical\Queries\VaccinationQuery`: `forSubject(Viewer, MedicalSubject, string $today): Collection` (rows with computed `status` overdue|due_soon|later|none and `dueInDays`; order: items with next_due_on ascending first, then past vaccinations by given_on desc), `attentionCount(...)` (overdue + due_soon for this person only; due_soon = 0..config('medical.due_soon_days') days), `find(Viewer, MedicalSubject, string $publicId, AccessLevel $min = View)`, `create`, `update`, `delete`, `markGiven(Viewer, MedicalSubject, string $publicId, string $givenOn, ?string $nextDueOn): bool` (one transaction: scoped UPDATE setting the old row's next_due_on = NULL, then INSERT the new row with the same vaccine; false when the UPDATE matched 0 rows).
- Routes (routes/web/health-vaccinations.php), `access:module,health,edit`, named throttles: `health.vaccinations.store` (POST /health/people/{person}/vaccinations), `health.vaccinations.update` (PATCH .../vaccinations/{vaccination}), `health.vaccinations.destroy` (DELETE), `health.vaccinations.given` (POST .../vaccinations/{vaccination}/given; body given_on required date <= today, next_due_on nullable after_or_equal given_on).
- Request rules: vaccine required max 120 + ValidUtf8 (`health.vaccination.err_vaccine`), given_on required date <= today (`err_given_on`), next_due_on nullable date after_or_equal given_on (`err_next_due`), notes nullable max 500.
- PersonPage props added: `vaccinations` (list of `{id: public_id, vaccine, givenOn, nextDueOn, notes, status, dueInDays}`), `vaccinationAttention` (int, this person only), timeline entries `{type: 'vaccination', id: public_id, date: givenOn}` and the `vaccinations` filter key when any exist; panel kinds `new-vaccination` (edit only) and `vaccination` with id (403 on miss).
