## Phase Goal

**As a** family member with Health access, **I want to** keep each person's visits, medications, allergies, vaccinations, documents, exports and emergency card in one private place, **so that** our medical history is at hand without any AI while people I may not see stay invisible to me.

<objective>
Secure document delivery and management: authenticated preview and file routes with the decided cache split and hardened headers, rename/attach/detach/delete, the daily orphan sweep, the `AiConsent::allowsDocument` contract, and the client upload/download helpers with the shared 423 refusal handler that the documents UI (07-14) and exports (07-16) use.

Purpose: MED-06 ("files are served only to authorized users"); CONTEXT "served only through an authenticated route with private no-cache and nosniff"; orchestrator decisions "PDFs, HEIC and downloads get no-store (only image derivatives get private, no-cache + ETag via a route-name exception in NoStoreDynamicResponses)", "securityDownload/securityUpload helpers and a shared handleHealthRefusal (423 mapping like the finance import wizard)", "Str::slug + HeaderUtils::makeDisposition filenames"; research Documents (Safety rules, Cache headers, ETag after access check, orphan sweep, Pitfalls 8 and 12), Code Examples (Authenticated file response); UI-SPEC securityDownload/securityUpload contract and Gate behavior.
Output: controller actions, request, query and system-query methods, routes, matrix rows, area file extension, middleware exception, prune command and schedule, two JS helpers, tests.
</objective>

## Contracts this plan creates

- Routes added to routes/web/health-documents.php:
  - `GET /health/people/{person}/documents/{document}/preview/{variant}` `health.documents.preview`, `access:module,health,view`; variant `thumb` or `view` (view = the full re-encoded JPEG); only kind image; any other variant or kind -> identical 403. Response: BinaryFileResponse, `Content-Type: image/jpeg`, inline, `X-Content-Type-Options: nosniff`, `Content-Security-Policy: default-src 'none'`, `Vary: Cookie`, `Cache-Control: private, no-cache`, `ETag: "<first 32 hex of sha256><variant>"`, `isNotModified($request)` evaluated only after the scoped lookup.
  - `GET /health/people/{person}/documents/{document}/file` `health.documents.file`, view: pdf -> original `application/pdf`; heic -> original with the stored mime; image -> the full JPEG; always `Content-Disposition` attachment via `HeaderUtils::makeDisposition(ResponseHeaderBag::DISPOSITION_ATTACHMENT, <slug>.<ext>)` where slug = `Str::slug($title)` cut to 60, fallback `document`; same nosniff/CSP/Vary headers; Cache-Control left to the middleware default (`no-store, private`).
  - `PATCH /health/people/{person}/documents/{document}` `health.documents.update`, edit, `throttle:60,1,health.documents.update`; body `title` required max 120 + ValidUtf8, `visit_id` nullable (same-person visit or 422 err_visit, identical for hidden/unknown); Inertia redirect back with toast `health.doc.saved`. UpdateDocumentRequest follows the phase-wide "authorize() first" rule (checker W1): `authorize()` resolves `{person}` with `SubjectQuery::findVisible(Viewer::for($this->user()), (string) $this->route('person'), AccessLevel::Edit)`, keeps the subject on the request (`subject(): MedicalSubject` accessor for the controller) and returns false on null, so hidden/unknown/malformed persons get the one identical Errors/Forbidden 403 (AuthorizationException and abort(403) render the same page in bootstrap/app.php) before any validation; the `{document}` id is still resolved in the controller via DocumentQuery::find (miss -> abort(403)).
  - `DELETE /health/people/{person}/documents/{document}` `health.documents.destroy`, edit, `throttle:60,1,health.documents.destroy`; row deleted in the scoped statement, files deleted after commit; toast `health.doc.deleted`.
- NoStoreDynamicResponses: keep `wishlist.images.show`; add `health.documents.preview` with status 200 or 304 only. Every other health response stays `no-store, private`.
- DocumentQuery additions: `find(Viewer, MedicalSubject, string $documentId, AccessLevel $min = View): ?MedicalDocument` (null without SQL for non-uuid; constrained to subject and scope), `update(...)`, `delete(...): ?array` (returns the paths to delete, or null when 0 rows).
- SystemQuery additions: `documentSubjectId(string $documentId): ?string` (Task 3), `knownPaths(array $relativePaths): array` (which of the given paths are referenced by a row) and `existingSubjectIds(array $subjectIds): array` (which of the given ids still exist) (Task 2); ids/paths only.
- AiConsent addition: `allowsDocument(string $documentId): bool` (resolve the subject via SystemQuery, then allows(); false on any miss or error).
- Command `medical:prune-orphans` (app/Console/Commands/PruneMedicalOrphans.php): never touches `Storage` directly (07-06 file-store scan); it reads `MedicalDocumentStore::files()` and `subjectDirectories()` (07-10 inventory), asks SystemQuery::knownPaths / existingSubjectIds, and removes through `MedicalDocumentStore::delete()` / `deleteSubjectDirectory()`; it deletes files on the medical disk older than `config('medical.orphan_grace_minutes')` that no row references, and subject directories whose subject no longer exists (after the grace); prints counts only. Scheduled daily in routes/console.php as `->daily()->name('medical-prune-orphans')`.
- JS: `resources/js/Security/securityTransfer.js` exports `securityDownload(url)` resolving `{ ok, status, blob?, filename?, error? }` and `securityUpload(url, formData, { onProgress, signal })` resolving `{ ok, status, data?, error? }` (XMLHttpRequest with upload progress; abort via signal); both accept same-origin relative paths only (anything else resolves `{ ok: false, error: 'invalid_url' }` without a request), send the XSRF header exactly like securityFetch, never reject, and map 423 bodies to `error` = confirm_required | reauth_required | second_factor_required, plus 413 -> too_large, 422 -> validation (with data), 429 -> throttled, network -> network. Filename from Content-Disposition (`filename=`) only. `resources/js/Health/healthRefusal.js` exports `handleHealthRefusal(code, { onBeforeLeave } = {})`: reauth_required/confirm_required -> call onBeforeLeave (sets allowLeave) then `router.visit('/confirm-access')`; second_factor_required -> same then `router.visit('/settings/security')`; returns true when handled, false otherwise.
