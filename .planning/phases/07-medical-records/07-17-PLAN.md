## Contracts this plan creates

- Table `medical_contacts`: id uuid PK (v4), subject_id uuid FK cascade, name varchar 120 NOT NULL, relation varchar 60 NULL, phone varchar 40 NOT NULL, sort smallint NOT NULL, timestampsTz; UNIQUE (subject_id, sort); max `config('medical.max_contacts')` (3) per subject enforced in the request and the query.
- `App\Medical\Queries\ContactQuery`: `forSubject(Viewer, MedicalSubject): Collection` (by sort), `replaceAll(Viewer, MedicalSubject, array $contacts): bool` (one transaction: scoped DELETE of the subject's contacts with the Edit predicate, then INSERTs with sort 0..n; false when the subject is not editable).
- SubjectQuery additions: `update(Viewer, MedicalSubject, array $data): bool` (single scoped UPDATE; contacts via ContactQuery in the same transaction), `delete(Viewer, MedicalSubject): bool` (one transaction: scoped DELETE of the subject (FK cascade removes members, visits, medications, allergies, vaccinations, contacts, documents) plus AuditEvent::MedicalSubjectDeleted meta {subject}; `DB::afterCommit` -> `MedicalDocumentStore::deleteSubjectDirectory($id)`; failing audit rolls back and keeps files).
- Requests: StorePersonRequest gains `contacts` (nullable array, max 3; each `name` required max 120 + ValidUtf8, `relation` nullable max 60 + ValidUtf8, `phone` required max 40 matching `^[0-9+()./\s-]{3,40}$`), message keys `health.person.err_contacts_max` and the existing person keys; SubjectQuery::create stores contacts in its transaction. UpdatePersonRequest extends StorePersonRequest (same rules) and overrides `authorize()` per the phase-wide rule below; StorePersonRequest (create, no `{person}`) keeps its module-level authorization.
- **authorize() first (phase-wide rule for every record FormRequest, checker W1):** the FormRequest's `authorize()` resolves `{person}` with `SubjectQuery::findVisible(Viewer::for($this->user()), (string) $this->route('person'), AccessLevel::Edit)`, stores the result on the request (a `subject(): MedicalSubject` accessor the controller uses instead of a second lookup) and returns false on null. A failed authorize() throws AuthorizationException, which bootstrap/app.php renders as the same Errors/Forbidden 403 page as abort(403), so a hidden, unknown or malformed person (and a View-only member) gets the one identical 403 before any validation runs and a validation error can never reveal that a hidden id exists. (health.people.update has no record id; health.people.destroy has no body and resolves the person in the controller.) Every slice adds a test: an invalid body (e.g. empty required field) sent to a hidden person id, the own_off person id, a random uuid and 'abc' gives the identical 403 (status and body equal to a valid body sent to a random uuid; no 302/422 validation response and no session errors).
- Routes added to routes/web/health.php: `PATCH /health/people/{person}` `health.people.update` (edit, `throttle:60,1,health.people.update`), `DELETE /health/people/{person}` `health.people.destroy` (edit, `throttle:10,1,health.people.destroy`).
- PersonPage: `person.contacts` (list of `{name, relation, phone}`, for visible viewers), panel kind `edit-person` (edit only, else 403).
