## Contracts this plan creates

- Table `medical_allergies`: id uuid PK (v4), subject_id uuid FK cascade, substance varchar 120 NOT NULL, reaction varchar 200 NULL, severity varchar 10 NOT NULL CHECK in (mild, moderate, severe, unknown), provenance columns and CHECK exactly as medical_visits, created_by, timestampsTz; index (subject_id).
- `App\Medical\Queries\AllergyQuery`: `forSubject(Viewer, MedicalSubject): Collection` (order: severe, moderate, mild, unknown, then lower(substance), id), `find`, `create`, `update`, `delete` with the VisitQuery semantics.
- Routes (routes/web/health-allergies.php): `POST /health/people/{person}/allergies` `health.allergies.store`, `PATCH /health/people/{person}/allergies/{allergy}` `health.allergies.update`, `DELETE ...` `health.allergies.destroy`; `access:module,health,edit`, named throttles like visits.
- Request accepts severity mild|moderate|severe only ('unknown' is reserved for Phase 8 AI rows; the UI requires a conscious choice); substance required max 120 + ValidUtf8; reaction nullable max 200 + ValidUtf8.
- PersonPage props added: `allergies` (list of `{id, substance, reaction, severity}`); panel kinds `new-allergy` (edit only, else 403) and `allergy` with id (must resolve in this person, else 403).
