## Phase Goal

**As a** family member with Health access, **I want to** keep each person's visits, medications, allergies, vaccinations, documents, exports and emergency card in one private place, **so that** our medical history is at hand without any AI while people I may not see stay invisible to me.

<objective>
The walking slice of the Health module: a member with Health edit creates a person (no account needed), is auto-granted "Can change", and opens that person's page; people switcher, header and the identical empty state work; every read goes through one two-branch visibility scope; hidden, unknown and malformed ids answer one identical 403.

Purpose: MED-01 (subject need not be an app user), MED-02 (per-subject access on top of the module grant); CONTEXT "per-person access on top of the module grant ... hidden people leave no trace ... admins do not automatically see medical records ... a member linked to a profile always sees and edits their own record unless the admin disables it"; orchestrator decisions "health module grant stays a prerequisite even for a linked member's own record", "creator is auto-granted Can change on creation (audited)", "child profile with own-record disabled and no other grants sees the standard empty state", "non-UUID segments give the same 403 as hidden ids ... ONE identical response (UI-SPEC 403 page) for all and test it"; research Pattern 1 (one scope, two branches), Pattern 2 (hidden equals unknown, resolve ids in the controller, never route model binding), Anti-patterns.
Output: schema for subjects and members, model, factory, config, Viewer/Visibility/SubjectQuery/PersonPage, three routes, controller, request, Person page with switcher, header and create panel, fixtures, matrix rows, tests.
</objective>

- SensitiveGateMatrixTest requires every route behind `access:module,health,*` to have a literal EndpointMatrix row with a success role (first non-guest role whose status < 400) and replays it stale (302 /confirm-access, 423 JSON, no audit row) and fresh (exact html status). So matrix `params` closures must grant the parent Health edit and create membership.
- AccessLevel ints: None 0, View 1, Edit 2. RequireAccess already audits `health_read`/`health_write` and runs SensitiveGate for Health. 403 for Inertia/html renders `Errors/Forbidden` (bootstrap/app.php); JSON clients get JSON 403.
- Route files under routes/web/*.php are globbed by routes/web.php. Finance routes use `whereUuid`; Health routes must NOT (UI-SPEC: non-UUID segments answer the same 403, never a route 404).
- AuditEvent::MedicalSubjectCreated exists after 07-01 (meta key `subject`). Lang keys exist after 07-01 (`health.*`; use only those).
