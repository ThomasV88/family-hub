## Decisions for this plan

- Linking a user to a subject grants that user own-record access, so linking lives ONLY here (admin + recent), not in the Health person panel. UI-SPEC Screen 5 lists "Linked account" in the person form "for creators/admins"; deviation recorded: a non-admin creator linking would mint access without the admin's recent confirmation (research Access Model: membership, linking and self_access are admin-only via settings). The neutral error text and "never marks members already linked elsewhere" rule apply to this select.
- There is no stored "child" concept on users (presets are applied as module grants only), so the own-record switch is offered for every linked person, default on, with the UI-SPEC hint "Turn off only if the child should not open their own record."
- No new GET route: the card data arrives as an admin-only `healthPeople` prop on the existing `settings.members` page (admin-only already). Therefore nothing is added to `allowlist()`/`grantAllowlist()`; both write routes go into `accessGranting()` and `'settings.health_people.'` into `grantPrefixes()`. The docblock records the PROVISIONAL admin-sees-names decision for owner confirmation in 07-20.
- Members whose Health module level is None cannot receive a per-person grant (422 `health.access.needs_module`), matching the disabled rows in the UI. Linking such a member is allowed (the UI shows the needs-module hint), since the module grant stays a prerequisite (orchestrator decision).

## Contracts this plan creates

- `App\Medical\Queries\AdminSubjectQuery` (docblock: unscoped by design, admin settings only, returns names, member levels and link flags, never record data or record counts): `listForAdmin(): array` (list of `{id, name, hasAccount, linkedUserId, selfAccessEnabled, members: array<int userId, 'view'|'edit'>}` ordered by lower(name), id), `find(string $id): ?MedicalSubject` (null without SQL for non-uuid), `syncMembers(MedicalSubject, array $levels, User $actor): void` (one transaction: upsert/delete rows, one audit row per changed member: MedicalAdminSelfAdded with meta {subject} when the actor adds themselves, otherwise MedicalAccessChanged with meta {subject, change: granted|revoked|level} and target = affected user), `link(MedicalSubject, ?int $userId, bool $selfAccess, User $actor): void` (one transaction; MedicalAccessChanged with change linked|unlinked|self_access_on|self_access_off; throws `ValidationException::withMessages(['user_id' => __('health.access.link_failed')])` for every refusal reason, so all refusals share one shape and text).
- Routes (routes/web/settings-health-people.php), group `access:admin` + `access:recent`: `PUT /settings/health-people/{person}/members` `settings.health_people.members.update` (body `levels`: present array, keys = active member user ids, values none|view|edit; `throttle:30,1,settings.health_people.members.update`), `PUT /settings/health-people/{person}/link` `settings.health_people.link.update` (body `user_id` nullable integer, `self_access_enabled` boolean; `throttle:30,1,settings.health_people.link.update`). Unknown person -> 404 (admin context). Success -> redirect back with toast `health.access.saved`.
