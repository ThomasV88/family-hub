Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Privacy contract (applies to every screen)

A viewer who cannot access a person gets an app that behaves exactly as if that person did not exist.

- The server returns only permitted people and only their data. No placeholders: no lock icon, no "restricted" tag, no "other people" line, no counts of hidden people, no hint text. A member with zero permitted people sees the same empty state as a family with no people.
- Person, visit, medication, allergy, vaccination and document ids are opaque UUIDs. `?panel=...&id=`, `/health/people/{uuid}` with a hidden or unknown id render the identical 403 `UiErrorState` (Phase 2 copy "You do not have access to this").
- Names never appear in: URLs, `<title>` (always "Health"), `document.title` updates, breadcrumbs of other pages, toasts for other people, Inertia shared props, Home card, global search, audit page text (content-free), service worker or `localStorage`/`sessionStorage`. Person selection is not remembered client-side. The server picks the first permitted person (alphabetical) when none is given.
- Admins have no automatic view. Exception (discretion, recorded): the Settings access admin lists people by name only (no records, no counts of records, no documents) so access can be granted, mirroring Finance account metadata. An admin never sees a person's records unless granted.
- Own-record rule: a linked member sees and can edit their own profile; the switch to disable this applies to child profiles only and is set by an admin (Screen 10).
- Reminders and push show the title only: "Vaccination due: {person}". No vaccine name, date or diagnosis in any notification or email subject.
- Home card is static (no names, no counts, no data) and the Health nav item shows no badge.
- Differential tests (Pest + Vitest), one per screen (Person page folders/timeline, side cards, documents, emergency card, export, access card, Home card): two viewers, one granted person X and one not; the not-granted viewer's Inertia props and rendered DOM equal those of a family where X never existed. Canary strings are a person name, doctor name, diagnosis and medication name; canaries never appear in any response or DOM for the not-granted viewer, including `aria-label`s, chip lists, selects (attach-to-visit, linked-account), toasts, the access card and the export screen.

## Gate behavior (Phase 6 idle gate and second factor)

Every Health page already sits behind `access:module,health`, the second factor and the 15-minute idle gate. The UI contract:

- Inertia visits and GETs: the server redirects stale sessions to `/confirm-access`, and a missing required factor to `/settings/security`. Pages add no handling and render nothing before redirect. Activity inside Health extends the window (06 rule). No countdown, no keepalive pings.
- JSON, file and fetch requests (document upload, document download, export download, AI-consent toggle if done via fetch, preview fallbacks) receive 423 with `error`. All go through `securityFetch` / `securityDownload` / `securityUpload`. Handler (shared `handleHealthRefusal(code)`, same logic as the finance import wizard): `reauth_required` or `confirm_required` -> `router.visit('/confirm-access')` after setting `allowLeave = true` so the unsaved-leave guard does not interrupt; `second_factor_required` -> `router.visit('/settings/security')`. The confirm page already shows the polite info alert "Your last change was not saved. Confirm it's you, then repeat it." Nothing is replayed automatically.
- Data discarded on redirect: picked files, form drafts and export blobs live in component memory only. No medical draft is written to `localStorage`, `sessionStorage` or IndexedDB (deliberate: shared family devices). Consequence stated in copy for the longest form (visit notes): none shown; the confirm alert is the notice.
- Non-GET Inertia form submits that the gate rejects are treated the same (Inertia error handler maps 423 to the same visit).
- `<img>` previews cannot read status codes: `DocumentPreview` handles `onerror` by showing an inline state "The preview could not be loaded." with secondary button "Confirm it's you" (links to `/confirm-access`) and ghost "Try again". It never loops reloads.
- Security-style confirm windows (10 minutes, `ReauthForm`) are not used in this phase: no Health action is a factor or credential change. Destructive deletes use the plain confirm dialog.
- All Health responses are `Cache-Control: private, no-store`; the service worker never caches `/health*` pages, document routes or exports (extends 01.1/02/05/06).

## Screens and Interaction Contract

Routes (Inertia pages, all `no-store`, health-ish names): `/health` (redirects to the first permitted person or shows the empty state), `/health/people/{person}` (person page), `/health/people/{person}/emergency-card` (print layout), `/health/people/{person}/export` (export form), `/health/people/{person}/export/print` and `/export/download` (generated on demand, never stored), document routes under `/health/people/{person}/documents/{doc}` (`/file`, `/preview`). Panels via `?panel=visit|medication|allergy|vaccination|document|person|new-visit|new-medication|new-allergy|new-vaccination|new-document|edit-person|new-person` plus `&id={uuid}`. Settings additions on `/settings/members`. Nav item "Health" (`HeartPulse`) already in `modules.js`.

### 1. People empty and zero-access state (`/health`)

Focal point: the single sentence "No people to show" with the next step.

- `UiEmptyState` (icon `HeartPulse` muted 32px), heading "No people to show", body "When a family member is added to Health and shared with you, their record appears here." Action "Add person" (primary) only for members who may create people (module edit); otherwise no action. Same copy for "no people exist" and "none shared with you" (no hint of the difference).
- A member with a linked profile never sees this state (their own record is always present).
- Loading: `UiSkeleton` (chip row plus two cards). Error: `UiErrorState` "Something went wrong" with "Try again".

### 2. Person page (`/health/people/{person}`)

Focal point: the person header and the first specialty folder, because the user came to answer "what is on record for this person".

Region order (16px gap): h1 "Health"; `PersonSwitcher` (plus ghost "Add person" chip-sized button at the end for creators); `PersonHeader`; two-column area.

- `PersonHeader` actions (wrap, 8px gap): primary "Add visit" (`Plus`, needs edit; phone: becomes FAB, and the header keeps the other actions), secondary "Add document" (`Upload`, needs edit), secondary "Emergency card" (`IdCard`, view is enough), secondary "Export records" (`FileDown`, needs edit (assumption, per sketch 008: export needs Edit)), `UiMenu` "More actions" (`MoreHorizontal`, aria-label "More actions for this person"): "Edit person", "Delete person" (danger text). View-only viewers see only "Emergency card" and a muted line "You can view this record but not change it."
- Two-column area: from content width >= 900px main column (flexible) plus side column 320px, 32px gap; below 900px a single column in this order: side cards first (Vaccinations with due items, Allergies, Medications), then the records views. (Safety info before history on phones.)
- Main column: `ViewSwitch` ("By specialty" default / "Timeline") then:
  - By specialty: stack of `SpecialtyFolder`s (only folders that have visits, newest activity first, then a "Documents without a visit" folder if any). First folder expanded, others collapsed; expansion is client state per page load. "Other" specialty shows its free-text label in the folder title.
  - Timeline: one `TimelineList` of all visits and unattached documents, newest first, with filter chip row above (`role="group"`, `aria-pressed`): "All", one chip per specialty used, "Vaccinations", "Documents". Vaccinations appear as entries (`Syringe`) only in this view. Filter changes are an Inertia partial reload with `aria-busy` on the list and previous items kept dimmed.
- Side column cards, in order: Emergency card summary (title "Emergency card", line with blood type and "{n} allergies" pipe plural, link "Open emergency card"), Allergies, Medications, Vaccinations.
- Panels open as `UiDetailPanel` (docked when content width >= 900px, otherwise overlay/sheet). Unsaved changes: closing with a dirty form opens "Discard changes?" ("Discard" danger, "Keep editing" default focus), from 02.
- Phone FAB label "Add visit" (aria-label), 56px, 16px above the bottom bar, hidden for view-only.

### 3. Specialty folders and timeline

Focal point: the date on each entry, because chronological order is the point.

- `TimelineList`: `<ol>`, each `<li>` a `TimelineEntry` = rail (dot 12px + 2px line) then a button row (min 44px, whole row opens the panel). Row content: line 1 `<time datetime>` (14/600, locale `Intl` medium date), line 2 title (16/600: visit = doctor name or, if empty, the specialty; document = document name; vaccination = vaccine), line 3 meta (14/400 muted: diagnosis excerpt clamped to 2 lines, "{n} documents" pipe plural with `Paperclip`). Icon by type (`Stethoscope`, `FileText`/`ImageIcon`, `Syringe`) at 20px before the title, `aria-hidden`.
- At 320px: single column, date above title, no side-by-side columns, text wraps (no ellipsis for titles in this list; long doctor names wrap), no horizontal scroll. Rail stays 16px.
- Folder header shows specialty name and "{n} visits" count; counts exist only for visits of the visible person.
- Empty folder body (cannot normally occur) and empty person state: `UiEmptyState` "No visits yet", body "Add the first visit to start this person's record.", action "Add visit" (edit only; viewers see no action).
- Timeline filtered empty: "Nothing matches this filter." with ghost "Clear filter".

### 4. Side cards: allergies, medications, vaccinations

Focal point: allergy severity tags (the one thing a clinician must not miss).

- Allergies card: rows (substance 16/600, reaction 14/400 muted, severity `UiTag`), severe first. Trailing ghost "Edit" opens `AllergyPanel`. Card action "Add allergy" (ghost, `Plus`). Empty: "No allergies recorded", body "Add one if this person has an allergy. If there are none, leave this empty." Explicit "no known allergies" status is not modeled (assumption: not in scope).
- Medications card: active medications first (name 16/600, "{dose}, {schedule}" 14/400 muted, tag "Ongoing" or none), disclosure button "Show ended medications" (`aria-expanded`) reveals ended ones with tag "Ended {date}". Action "Add medication". Empty: "No medications recorded".
- Vaccinations card: items with a next-due date sorted soonest first with due tags; then past vaccinations (name, date). Overdue/due-soon items appear at the top of the card. Action "Add vaccination". Empty: "No vaccinations recorded".
- Every row is a button (44px) opening its panel; view-only viewers get read-only panels (fields as text, no Save).

### 5. Record panels (forms)

Focal point per panel: the first required field (Visit: date; Medication: name; Allergy: substance; Vaccination: vaccine; Person: name).

Shared: `UiDetailPanel`, h2 titles ("Add visit"/"Edit visit", and so on), `UiField` labels above controls, required fields marked with text "(required)" in the label, hint text 14/400 muted, inline errors "{what is wrong}. {how to fix}." Footer: primary "Save {noun}" (loading state), secondary "Cancel", and for existing records ghost danger "Delete {noun}" at the start edge. Enter does not submit multi-field forms. Dates use native `<input type="date">` (16px, locale display by browser). Free text rendered as text only, never HTML, including toasts and aria-labels.

- Visit: Date (required), Doctor (text), Specialty (`UiSelect`: taxonomy list below, last option "Other"; selecting "Other" reveals required field "Specialty name (free text)", v-if not CSS), Diagnosis (text), Notes (`UiTextarea`, 4 rows). Below the fields, section "Documents" lists attached documents (`UiListRow` with name, ghost "Remove from visit" non-destructive) and buttons "Attach document" (opens a `UiDialog` "Attach a document": radio list of this person's documents not attached to any visit, plus secondary "Upload a new document" that opens the uploader preselected to this visit) .
- Medication: Name (required), Dose (text, hint "For example: 5 mg."), Schedule (text, hint "For example: one tablet in the morning."), Start date, End date (hint "Leave empty if the medication continues."). Validation: end not before start.
- Allergy: Substance (required), Reaction (text), Severity (`UiSelect`: Mild, Moderate, Severe; required, default none selected so it is a conscious choice).
- Vaccination: Vaccine (required), Date given (required), Next due (optional; hint "Members who can edit this record get a reminder before this date. The reminder names the person only.").
- Person (create/edit): Name (required), Birth date, Sex (`UiSelect`: Female, Male, Not specified), Blood type (`UiSelect`: Unknown, A+, A-, B+, B-, AB+, AB-, 0+, 0-), Notes (textarea), Emergency contacts (up to 3 rows, each Name, Relationship, Phone with `type="tel"` `autocomplete="off"`; ghost "Add contact" / "Remove contact"), and for creators/admins "Linked account" (`UiSelect` of active members plus "No account"; changes the "No account" marker). Linked-account select lists members by name (family-wide fact, not medical).
- Destructive confirms (dialog per 01.1 pattern, default focus on the safe button):

| Action | Title | Body | Danger / safe buttons |
|--------|-------|------|-----------------------|
| Delete visit | Delete visit | "Delete this visit? Attached documents stay in the record without a visit." | "Delete visit" / "Keep visit" |
| Delete medication | Delete medication | "Delete this medication from the record? This cannot be undone." | "Delete medication" / "Keep medication" |
| Delete allergy | Delete allergy | "Delete this allergy from the record? This cannot be undone." | "Delete allergy" / "Keep allergy" |
| Delete vaccination | Delete vaccination | "Delete this vaccination and its reminder? This cannot be undone." | "Delete vaccination" / "Keep vaccination" |
| Delete document | Delete document | "Delete this document? The file is removed from the server and cannot be restored here." | "Delete document" / "Keep document" |
| Delete person | Delete person | "Delete this person with every visit, medication, allergy, vaccination and document? This cannot be undone." | "Delete person" / "Keep person" |

Success toasts: "Visit saved", "Medication saved", "Allergy saved", "Vaccination saved", "Person saved", "Visit deleted" and so on (noun-bearing, no names).

### 6. Documents: upload, preview, attach

Focal point: the file picker (upload) and the preview image (view).

- Upload entry: header "Add document" button, visit panel "Upload a new document", and the folder "Documents without a visit" action. Opens `DocumentPanel` in create mode.
- `DocumentUploader`: `UiField` "Files" with native `<input type="file" multiple accept="application/pdf,image/jpeg,image/png,image/webp,image/heic,image/heif,.pdf,.jpg,.jpeg,.png,.webp,.heic,.heif">`, hint "PDF or photos, up to {max} MB each, {count} files at a time." (`{max}` and `{count}` come from the server limits; never hardcoded). On phones the browser offers camera and library natively. Client pre-check of extension and size only (server sniffs MIME from bytes and is authoritative). Optional field "Name" (single file only; for several files each uses its original name) and `UiSelect` "Attach to visit" (this person's visits by date and doctor/specialty, default "No visit").
- Queue: `<ul>` of rows (icon, file name, size, `UiProgress` with value, status text). Files upload one at a time via `securityUpload`; row states: waiting, uploading ("Uploading..."), done (`Check`, "Added"), failed (danger text with reason and ghost "Retry"). Footer: primary "Add document" (disabled until a file is chosen; label becomes "Add {n} documents" pipe plural when several), secondary "Cancel" (aborts the running upload via `xhr.abort()`; completed files stay). Leaving with an upload running opens the Inertia leave guard "Leave while uploading?" ("Leave" danger, "Keep uploading" default focus). 423 mid-upload: handled per Gate behavior; files already added stay.
- Errors (inline per file, `role="alert"` once): wrong type "This file type is not supported. Use a PDF, JPG, PNG, WebP or HEIC file."; too large "This file is larger than {max} MB. Choose a smaller file or reduce its size."; unreadable "This file could not be read. Try saving it again and upload the new copy."; server/network "We could not upload this file. Nothing was saved. Try again."
- Document panel (existing): h2 = document name (user text, escaped); fields Name (editable with edit), Attached visit select, then `DocumentPreview`, then actions "Open in new tab" (anchor, `target="_blank" rel="noopener"`), "Download document" (`securityDownload`, `Download`), ghost danger "Delete document".
- `DocumentPreview`:
  - Image or HEIC with server JPEG derivative: `<img>` of the authenticated derivative route, `alt` = document name, max height 480px, `object-fit: contain` on a surface-2 frame, no EXIF (stripped server side), width 100% of panel. Tap/click opens "Open in new tab".
  - PDF: file card (`FileText` 32px, name, "PDF, {size}") with "Open in new tab" and "Download document". No inline PDF embed (discretion: iframe sandboxing blocks viewers and phones render poorly).
  - HEIC the server cannot decode: file card with tag "No preview" and text "This photo format cannot be previewed here. Download the original to view it." and "Download document".
  - Load failure: inline state described in Gate behavior.
  - Loading: `UiSkeleton` block of fixed 240px height (no layout jump).
- Attach from visit panel and from document panel are the same relation; changing it saves with the panel form and shows toast "Document saved".

### 7. Upcoming vaccinations

Focal point: the due tag of the soonest item.

- Surfaced in the Vaccinations side card (Screen 4), sorted soonest first, overdue first. When at least one item is overdue or due within 30 days, a `UiAlert` warning (not `role="alert"`, page content) appears at the top of the person page: title "Vaccination due", body "{n} vaccinations need attention." (pipe plural; "{n}" counts this person's items only). No cross-person summary (a summary across people could count hidden people).
- Reminder channel copy lives in the form hint (Screen 5). No settings UI added; recipients are the Phase 3 outbox rules.

### 8. AI consent (`AiConsentControl`)

Focal point: the switch with its explanation directly beneath.

- Placed in `PersonHeader` below the name block. Layout: `UiSwitch` with visible label "Allow AI to read documents of this person" (`Bot` icon before the label), explanation paragraph (14/400 muted, always visible, linked by `aria-describedby`): "Off by default. When on, documents of this person can be sent to the AI agent your family admin set up, to suggest record entries. You check every suggestion before it is saved. Turning this off does not delete anything already saved." and a second muted line "AI reading is not available yet. Your choice is saved for when it is." (shown until Phase 8 ships; removable by flag).
- Interaction: turning on opens a confirm dialog (consent notice): title "Allow AI for this person?", body "Documents of this person will leave this server and be processed by an AI service. Only turn this on if the family agrees. You can turn it off at any time.", primary "Allow AI" (not danger; this is the consent), safe default focus "Keep AI off". Confirm saves (`aria-busy` on the switch, toast "AI is on for this person"). Turning off saves immediately without a dialog (toast "AI is off for this person"). Audited server side.
- Only editors can toggle. View-only viewers see the read-only tag "AI: on" / "AI: off" and the explanation without the switch. Failure: inline `UiAlert` danger "We could not save this setting. Try again." and the switch returns to its previous state.

## Interaction and Accessibility Contract (additions to 01.1 to 06)

- Semantics: person switcher `radiogroup` of chips; view switch `radiogroup`; folder headers are buttons with `aria-expanded`/`aria-controls` and body `role="region"` labelled by the header; timeline is `<ol>` with `<time datetime>`; side cards are `<section>` with h2; panels are `<aside aria-label="Visit details">` (or "New visit", "Medication details", and so on); one h1 "Health"; emergency card and export print views have a single h1 with the print title ("Emergency card", "Health records").
- Live regions: toasts `role="status"`; filter and view changes announce via a polite results line ("Showing {n} entries", pipe plural); upload queue status text `role="status"` per file, errors `role="alert"` once; AI save failure `role="alert"`.
- Keyboard: one Tab stop per timeline entry, per folder header, per chip group (arrow keys inside); Esc closes panels and dialogs; dialogs and panels trap and restore focus; Enter in multi-field forms does not submit; no keyboard traps in the uploader (native input).
- Touch: 44px hit areas for chips, folder headers, entry rows, switch, ghost actions, file picker.
- 320px and 200% zoom: no horizontal scroll anywhere. Timeline is a single column; side cards stack; `UiTable` in the print/export tables stacks label/value below 560px; chips and buttons wrap.
- Dates: `Intl.DateTimeFormat` in the active locale and family time zone with `<time datetime>`; ages, due status and overdue computed server-side and displayed only.
- Print: `PrintLayout` described in Screen 9. Print stylesheet is tested by a Vitest check that the layout renders no shell landmarks (`nav`, sidebar, bottom bar, FAB) and by a Playwright print-media screenshot on staging (discretion).
- Motion: durations 150-200ms; folder expand uses height/opacity only, disabled under `prefers-reduced-motion`.
- Color: never color alone; every status tag has text and icon; selected states use fill plus weight/border.
- Forced-colors: tags and timeline rail fall back to `currentColor` borders.
- Tests: Vitest + axe on person page (folders expanded and collapsed, timeline with filters, empty, loading, error, view-only), each panel (create, edit, read-only, delete confirm), uploader (each file state), document preview (image, PDF card, no-preview, load failure), emergency card (screen and print layout), export form (each format, scope select), AI consent (off, confirm dialog, on, read-only, failure), access card and panel (admin), Home card; each in light and dark (print views forced light) and en/sk/pl, plus a 320px viewport pass and a pseudo-long (+40%) text test on chips, folder headers, tags, buttons, panel titles and timeline rows. Gate tests: 423 responses to upload, download and export map to the confirm page and leave no file or draft in storage. Privacy differential tests per the Privacy contract.

### Plurals: pipe plurals (vue-i18n), not ICU

The sketch note says "ICU plurals"; this project uses vue-i18n pipe plurals with the `pluralRules` already in `resources/js/i18n.js`. English uses 2 segments (`one | other`). Slovak and Polish use 4 segments (`one | few | many | other`; the segment count must be exactly 4 for sk/pl, never 3). Call sites pass `t(key, { n }, n)`. Names are never concatenated into grammatical phrases: write copy so the name stands alone ("Person: {name}") and never needs a case form (sketch finding: name declension and "1 návštev"). Zero uses a separate key where the wording differs ("No visits yet"). A Vitest test asserts 0, 1, 2, 4, 5, 12, 22, 25 for sk and pl on every plural key (`health.folder.visits`, `health.age`, `health.docs.attached`, `health.vacc.due_days`, `health.vacc.attention`, `health.allergies.count`, `health.access.can_view`, `health.access.can_change`, `health.upload.add_n`, `health.results`).

Example (`health.folder.visits`): en `{n} visit | {n} visits`; sk `{n} návšteva | {n} návštevy | {n} návštevy | {n} návštev`; pl `{n} wizyta | {n} wizyty | {n} wizyt | {n} wizyty` (pl: index 2 = integers 0 and 5-21, index 3 = non-integers).
