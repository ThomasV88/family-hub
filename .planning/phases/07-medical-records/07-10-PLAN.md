## Phase Goal

**As a** family member with Health access, **I want to** keep each person's visits, medications, allergies, vaccinations, documents, exports and emergency card in one private place, **so that** our medical history is at hand without any AI while people I may not see stay invisible to me.

Purpose: MED-06 (upload part; serving, management and UI follow in 07-12 and 07-14); CONTEXT "Documents: PDF and images incl. ## Contracts this plan creates

- Table `medical_documents`: id uuid PK (v4), subject_id uuid NOT NULL FK medical_subjects cascade, visit_id uuid NULL, kind varchar 5 NOT NULL CHECK in (pdf, image, heic), title varchar 120 NOT NULL, mime varchar 40 NOT NULL, size_bytes integer NOT NULL CHECK > 0, sha256 char(64) NOT NULL, path varchar 200 NOT NULL, thumb_path varchar 200 NULL (CHECK: kind = 'image' iff thumb_path IS NOT NULL), width/height integer NULL, uploaded_by bigint NULL FK users nullOnDelete, timestampsTz; FOREIGN KEY (visit_id, subject_id) REFERENCES medical_visits (id, subject_id) ON DELETE SET NULL (visit_id) (Postgres 15+ column list, so deleting a visit keeps the document with its subject; UI-SPEC "Attached documents stay in the record without a visit"); index (subject_id, created_at desc), index (visit_id). No provenance columns (documents carry none in v1).
- `App\Medical\Documents\DocumentSniffer::sniff(string $bytes): array{kind: 'pdf'|'image'|'heic', mime: string, ext: 'pdf'|'jpg'|'heic'}` per research Code Examples: finfo(FILEINFO_MIME_TYPE) on the bytes; pdf only if mime application/pdf AND `str_starts_with($bytes, '%PDF-')`; heic only if mime in image/heic|image/heif|image/heif-sequence AND bytes 4..7 == 'ftyp' AND major brand in heic, heix, hevc, hevx, heim, heis, hevm, hevs, mif1, msf1; image only for image/jpeg|png|webp; anything else throws `DocumentRejected('unsupported_type')`. DocumentRejected carries a reason code: unsupported_type, too_large, too_many_pixels, unreadable, limit_reached, write_failed, busy.
- `App\Medical\Documents\MedicalDocumentStore` (the single file IO seam for a later encryption layer): `put(string $subjectId, string $bytes): array{kind, mime, ext, path, thumb_path, width, height, size_bytes, sha256}` (check order: size <= config('medical.document_max_bytes') else too_large; sniff; image -> ImageProcessor with `config('medical.image_full_px')`/`image_thumb_px` (pixel cap and decode lock come from ImageProcessor) -> write `{subject}/{ulid}-full.jpg` and `{subject}/{ulid}-thumb.jpg`; pdf/heic -> write original bytes to `{subject}/{ulid}.{ext}`; verify every write returned true, else delete what was written and throw write_failed), `absolutePath(string $relative): string`, `delete(array $paths): void`, `deleteSubjectDirectory(string $subjectId): void`, plus the read-only sweep inventory used by 07-12's prune command so no other class touches the disk: `files(): list<array{path: string, modifiedAt: int}>` and `subjectDirectories(): list<array{subjectId: string, modifiedAt: int}>`. Path-shape guard (checker W3): one private `assertPath(string $relative)` requires `^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}/[0-9A-Z]{26}(-full|-thumb)?\.(jpg|pdf|heic)$` (lower-case v4-style uuid directory, ULID name, optional variant suffix, the three stored extensions) and throws `InvalidArgumentException` otherwise; `absolutePath()` and every entry of `delete()` pass through it before touching the disk, and `deleteSubjectDirectory()` requires a lower-case uuid (no `..`, no slash, no empty string). `Storage::disk('medical')` appears only in this class (07-06 file-store scan).
- ImageProcessor generalisation: its processing entry point gains optional `?int $fullPx = null, ?int $thumbPx = null` (null -> the current `config('wishlist.*')` values), so wishlist callers and ImageProcessorTest stay unchanged.
- `App\Medical\Queries\DocumentQuery`: `countForSubject(Viewer, MedicalSubject): int`, `create(Viewer, MedicalSubject, array $stored, string $title, ?string $visitId): MedicalDocument` (visit must belong to the same subject: checked via VisitQuery::find, any miss -> validation error `visit_id` with `health.upload.err_visit`, identical for hidden/unknown/other person's visits; insert follows a scoped subject lookup), `forSubject(Viewer, MedicalSubject): Collection` (newest first). 07-12 adds find/update/delete.
- Route (routes/web/health-documents.php): `POST /health/people/{person}/documents` `health.documents.store`, `access:module,health,edit`, `throttle:30,1,health.documents.store`. StoreDocumentRequest::authorize() resolves the person with `SubjectQuery::findVisible($viewer, $person, AccessLevel::Edit)` and returns false on null (403 before validation, like UploadWishImageRequest). Rules: `file` required|file|max:<document_max_bytes in KiB>, `title` nullable string max 120 + ValidUtf8, `visit_id` nullable string. JSON (securityUpload/XHR) success: 201 `{document: {id, kind, title}}`; refusals: 422 `{errors: {file: [<translated health.upload.err_* text>]}}` mapping too_large->err_size (with {max}), unsupported_type->err_type, unreadable/too_many_pixels->err_read, limit_reached->err_limit, write_failed/busy->err_failed. HTML requests (matrix fresh replay without a file) get the normal validation redirect (302).
- Title default: the client basename without extension, control characters stripped, cut to 120; used only as the editable title (escaped by Vue). The client filename is never stored, logged or used in a path.
