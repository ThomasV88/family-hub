## Shared rules

Same as 07-05/07-08 (resolve via Queries, identical 403, no binding/whereUuid, Edit-scope single-statement writes, named throttles, lang-key toasts, no remember/v-html). Area contract as in 07-06, parameter name `medication`. "Today" is `now(config('family.timezone'))->toDateString()` computed in PHP, never CURRENT_DATE.

**authorize() first (phase-wide rule for every record FormRequest, checker W1):** the FormRequest's `authorize()` resolves `{person}` with `SubjectQuery::findVisible(Viewer::for($this->user()), (string) $this->route('person'), AccessLevel::Edit)`, stores the result on the request (a `subject(): MedicalSubject` accessor the controller uses instead of a second lookup) and returns false on null. A failed authorize() throws AuthorizationException, which bootstrap/app.php renders as the same Errors/Forbidden 403 page as abort(403), so a hidden, unknown or malformed person (and a View-only member) gets the one identical 403 before any validation runs and a validation error can never reveal that a hidden id exists. Record ids (`{visit}`, `{allergy}`, `{medication}`, `{vaccination}`, `{document}`) are still resolved in the controller through the record query (miss -> abort(403)). Every slice adds a test: an invalid body (e.g. empty required field) sent to a hidden person id, the own_off person id, a random uuid and 'abc' gives the identical 403 (status and body equal to a valid body sent to a random uuid; no 302/422 validation response and no session errors).

## Contracts this plan creates

- Table `medical_medications`: id uuid PK (v4), subject_id uuid FK cascade, name varchar 120 NOT NULL, dose varchar 120 NULL, schedule varchar 160 NULL, started_on date NULL, ended_on date NULL, notes varchar 1000 NULL, CHECK (ended_on IS NULL OR started_on IS NULL OR ended_on >= started_on), provenance columns and CHECK as medical_visits, created_by, timestampsTz; index (subject_id).
- `App\Medical\Queries\MedicationQuery`: `forSubject(Viewer, MedicalSubject, string $today): Collection` (ongoing first by lower(name), then ended by ended_on desc), `current(Viewer, MedicalSubject, string $today): Collection` (ended_on IS NULL OR ended_on >= today; used by 07-18 emergency card and 07-16 exports), `find`, `create`, `update`, `delete` with VisitQuery semantics.
- Routes (routes/web/health-medications.php): `health.medications.store` (POST /health/people/{person}/medications), `health.medications.update` (PATCH .../medications/{medication}), `health.medications.destroy` (DELETE); `access:module,health,edit`, named throttles.
- Request: name required max 120 + ValidUtf8 (`health.medication.err_name`), dose nullable max 120, schedule nullable max 160, started_on/ended_on nullable dates, ended_on after_or_equal started_on (`health.medication.err_end_before_start`), notes nullable max 1000; ValidUtf8 on text.
- PersonPage props added: `medications` (list of `{id, name, dose, schedule, startedOn, endedOn, notes, ongoing}`; `ongoing` computed server-side); panel kinds `new-medication` (edit only) and `medication` with id (403 on miss).
