## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| internet -> nginx | request bodies of any size arrive here |
| app container -> medical volume | only PHP writes and reads medical files |
| server -> restic repos (local, off-site) | medical bytes leave the volume only inside encrypted snapshots |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-04 | Information disclosure | medical volume | mitigate | Volume mounted only into app/worker/scheduler (check-compose.sh asserts nginx/postgres never mount it); disk root outside public and outside app/private; `serve => false`; files 0600, dirs 0700 (MedicalDiskTest) |
| T-07-05 | Denial of service | nginx body limit | mitigate | 12m only on the exact upload URL regex; all other routes keep 1m (check-nginx-template.sh) |
| T-07-06 | Information disclosure | backups | mitigate | restic encryption with password files; streaming tar, never a plaintext tar on disk; separate tags so retention cannot delete the wrong snapshot |
| T-07-07 | Repudiation / availability | backup failure | mitigate | MFAIL flag fails the run after the other snapshots finish; freshness check alerts on a missing medical-nightly |
| T-07-08 | Information disclosure | file encryption at rest | accept | PROVISIONAL decision: no app-level encryption in v1 (APP_KEY lives on the same host; restic + 0600/0700 instead); recorded in docs/ops/server.md for owner confirmation in 07-20 |
| T-07-09 | Information disclosure | slow erasure | accept | Deleted medical data stays in snapshots for the retention window (daily 14, weekly 8, monthly 6); documented in the runbook |
</threat_model>
