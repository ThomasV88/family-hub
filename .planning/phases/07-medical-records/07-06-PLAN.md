## Harness contract (fixed here; slice plans only add area files)

- Scenario: viewer V and co-member O (both `Preset::Parent` plus `MedicalFixtures::grantHealth(..., Edit)`); visible subject A (V and O Edit members) at `$ctx['person']`; hidden subject B (O only) at `$ctx['hidden']['person']`; subject C linked to V with `self_access_enabled = false` and no membership at `$ctx['hidden']['own_off']`. Names: A "Visible Person", B and C contain `ZxCanaryMed`. Constants: `CANARY = 'ZxCanaryMed'`, `CANARY_NEEDLES` (CANARY plus `'+421 777 777'` and `'Dr ZxCanaryMed'` used by later area files).
- Area file contract (identical to the one quoted in 07-05): keys `visible`, `hidden`, `params`, `hiddenParams`, `panels`, `payloads`; lists concatenate, maps keep the first definition (sorted file order), panels per route concatenate. Fixed route parameter names: person, visit, medication, allergy, vaccination, document, variant.
- Surfaces: every GET route whose name starts with `health.` plus `home`, `settings.index` and `settings.members` (V is not admin, so settings answers 403 identically) and every `panels` variant; a route with an unknown parameter makes `urls()` throw (so a new route without area params fails loudly). Responses are normalised like FinancePrivacy::normalise (md5 of BinaryFileResponse/StreamedResponse bodies; CSRF tokens, timestamps, `generated_at`-like fields stripped by a documented list), headers compared: status, Content-Type, Content-Disposition, ETag, Cache-Control.
- READ_TABLES: medical_subjects, medical_visits, medical_medications, medical_allergies, medical_vaccinations, medical_contacts, medical_documents. FAMILY_WIDE_TABLES: `medical_subject_members` => 'the membership table itself is the scope'. Classification test fails for any existing `medical_%` table (information_schema) not listed. MUTATION_TABLES: all READ_TABLES plus medical_subject_members (settings writes are admin-only and tested in 07-07).
- MEMBERSHIP predicate regex (to be self-tested against literal SQL Laravel generates for Visibility::subjectIds): `medical_subject_members` (optional alias) followed by `where` ... `user_id = ?` without crossing a parenthesis. Mutation rules per shape (WR-12): UPDATE/DELETE and INSERT ... SELECT need the predicate in the statement; INSERT ... VALUES needs an earlier statement in the same request with the predicate.
- Write parity covers every non-GET route whose name starts with `health.`: hidden id (from hiddenParams), random uuid, the string 'abc', and for nested routes a mismatched pair (visible person with a hidden record id) must give identical status and body; the malformed id request issues zero statements on medical tables.
- Arch allowlists: Medical models (`App\Models\Medical*`) may be used only in `App\Medical`, `App\Http\Controllers\Health`, `App\Models`, `Database\Factories`, `Tests`. `App\Medical\Queries` may be used only in `App\Medical`, `App\Http\Controllers\Health`, `App\Http\Controllers\Settings\HealthPeopleController`, `App\Console\Commands`, `Tests`. `App\Http\Controllers\HomeController`, `App\Http\Middleware\HandleInertiaRequests` and `App\Notifications` must not use `App\Medical` at all (the outbox registry references `App\Medical\Reminders\VaccinationDueHandler` from `App\Notifications\Outbox\OutboxHandlers`: allow exactly that class in OutboxHandlers, nothing else). Missing namespaces match nothing (rules hold before later plans add code).
- Static scans: table names `medical_` and `DB::table('medical_` / raw SQL with `medical_` may appear only in `app/Medical/Queries`, `app/Medical/Visibility.php` and `database/migrations`; mutation calls (`->update(`, `->delete(`, `->forceDelete(`, `->increment(`, `->decrement(`, `->updateQuietly(`, `->deleteQuietly(`, `upsert(`, `updateOrInsert(`, `updateOrCreate(`, `DO UPDATE`) on medical tables/models only in `app/Medical/Queries` and each such method body must contain `Visibility::`; explicit allowlist with reasons: `AdminSubjectQuery` (admin settings by design, 07-07) and `SystemQuery` (no viewer, ids/bool only, 07-09/07-12/07-15). Allowlisted classes that do not exist yet are skipped.
- `Rule::exists(` and `exists:medical_` are forbidden in app/Http/Requests/Health and Settings/HealthPeople* (existence checks would be an oracle; resolve through Queries instead).
