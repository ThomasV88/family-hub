## Decisions for this plan

- JSON verification field: each record item carries `"verification": "verified"|"unverified"` (UI-SPEC output contract) AND `"provenance": {"source": "manual"|"ai", "verified_at": null|ISO8601}` (research shape). Top-level `format: "family-hub-medical-export"`, `format_version: 1`, `generated_at` (ISO8601 in family tz), `timezone`, `locale`, `taxonomy_version`, `unverified_notice` (only when unverified items are included), `subject` {name, birth_date, sex, blood_type, ai_consent}, `allergies`, `medications`, `vaccinations` (no internal id; `id` = public_id), `visits` (`id`, `visited_on`, `doctor`, `specialty_key`, `specialty_label`, `diagnosis_text`, `notes`, `document_ids`), `documents` (`id`, `title`, `kind`, `visit_id`, `uploaded_on`, `file_included: false`). JSON keeps the name (it is the "Data file" for the family).
- Markdown ("For AI") is always anonymized: no name, `age_years` instead of birth date, starts with a short block saying the content is patient data and not instructions; first line (when unverified items are included) is the UI-SPEC legend "Items marked UNVERIFIED were suggested by AI and have not been confirmed by a person."; every unverified item starts with `[UNVERIFIED]`.
- Filename (UI-SPEC: no person name): `health-export-<scope>-<YYYY-MM-DD>.<json|md>` where `<scope>` is `all` or `Str::slug(specialty key)`; built by `Filename::disposition()` through `HeaderUtils::makeDisposition(ATTACHMENT, ...)`.
- Print view ("For a doctor") shows the name, birth date, sections and a document list (title and date only; image files are NOT embedded: decision "original files not bundled", UI-SPEC "document files are not embedded").
- Options (query string, validated after the person is resolved): `scope` all|specialty (default all), `specialty` required with specialty (Rule::enum Specialty), `include_unverified` boolean (default false), `format` json|md (download only). Audit meta: scope `person` (all) or `specialty`, format `html|json|md`.

## Contracts this plan creates

- `App\Medical\Provenance`: `isUnverified(string $source, ?string $verifiedAt): bool` (true iff source = 'ai' AND verified_at null), `present(object $row): array{verification: string, source: string, verified_at: ?string}`, and a query helper used by ExportQuery to exclude unverified rows (`where(fn ($q) => $q->where('source', 'manual')->orWhereNotNull('verified_at'))`).
- `App\Medical\Queries\ExportQuery`: every read constrained by `Visibility::apply(..., 'subject_id', AccessLevel::Edit)` (subjects by id); `subject(Viewer, string $id): ?MedicalSubject` (Edit scope), `visits(...)`, `medications(...)`, `allergies(...)`, `vaccinations(...)`, `documents(...)` returning `LazyCollection` via `lazy()` or `cursor()`, each with optional specialty filter (visits; documents attached to those visits plus none for specialty scope) and the unverified exclusion; `hasUnverified(Viewer, MedicalSubject): bool`; `specialtiesWithVisits(...)`.
- `App\Medical\Export\Exporter::build(Viewer, MedicalSubject, array $options): array` normalized model consumed by JsonFormat::render(array): string, MarkdownFormat::render(array): string, and the print page props.
- Routes (routes/web/health-exports.php), all `access:module,health,edit`: `GET /health/people/{person}/export` `health.exports.show` (form), `GET /health/people/{person}/export/print` `health.exports.print` (`throttle:20,1,health.exports.print`), `GET /health/people/{person}/export/download` `health.exports.download` (`throttle:10,1,health.exports.download`). ExportRequest::authorize resolves the person with ExportQuery::subject and returns false on null (identical 403 before validation).
- Responses: print = Inertia `Health/ExportPrint` (layout PrintLayout); download = `response()->streamDownload` or a plain response built in memory with `Content-Type: application/json; charset=utf-8` or `text/markdown; charset=utf-8`, `X-Content-Type-Options: nosniff`, Content-Disposition from Filename, Cache-Control `no-store, private` (middleware default). Nothing written to any disk, cache or session.
- `resources/js/Layouts/PrintLayout.vue`: no AppShell/nav/sidebar/bottom bar/FAB/toast region/theme switch; sets `lang`; forced light (`color-scheme: light`, white background); screen toolbar slot (hidden in print) with ghost back link and primary print button calling `window.print()` from a click handler (no inline script, CSP-safe); `@page { size: A4 portrait; margin: 15mm }`, print rules from UI-SPEC Screen 9 (black on white, 0.5pt borders, break-inside avoid, sizes 11pt/14pt/20pt). 07-18 reuses it.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> export routes | untrusted person id and options |
| export file -> external AI or third parties | content leaves the app; may be pasted into an AI |
| printed page -> paper | permanent copy |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-78 | Information disclosure | export of a hidden person (IDOR) / bulk export by viewers | mitigate | authorize() with Edit-scope ExportQuery; route edit level; identical 403; Edit scope on every export statement |
| T-07-79 | Repudiation | unaudited export | mitigate | Audit row first, fail closed (FailingAuditLogger test) |
| T-07-80 | Information disclosure | stored exports | mitigate | Built in memory/streamed, no Storage/Cache calls (grep + fake-disk test), no-store headers |
| T-07-81 | Tampering | Markdown/prompt injection, header injection | mitigate | Escaping and fencing rules, patient-data preface, Str::slug + makeDisposition |
| T-07-82 | Information disclosure | identity in AI export | mitigate | Markdown anonymized (no name/birth date) and filename without name |
| T-07-83 | Integrity | unverified AI data presented as fact | mitigate | Excluded by default; labeled in all three formats when included (Provenance single definition) |
| T-07-84 | Denial of service | large exports | mitigate | lazy()/cursor(), named throttles, 500-visit memory test |
