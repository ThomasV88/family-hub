## Phase Goal

**As a** family member with Health access, **I want to** keep each person's visits, medications, allergies, vaccinations, documents, exports and emergency card in one private place, **so that** our medical history is at hand without any AI while people I may not see stay invisible to me.

<objective>
Vaccination due reminders through the Phase 3 outbox: an hourly enqueue command with lead days and grace, per-recipient dedupe, a `vaccination_due` handler that re-checks everything at send time, title-only push and a vaccine-free mail.

## Contracts this plan creates

- SystemQuery additions (docblock updated: ids, dates and booleans, plus `subjectDisplayName` used only for the owner-accepted reminder title): `dueVaccinations(string $fromDate, string $toDate): list<array{id: int, public_id: string, subject_id: string, next_due_on: string}>`, `vaccinationDue(int $id): ?array{public_id, subject_id, next_due_on}`, `reminderCandidateIds(string $subjectId): list<int>` (members with level 2 UNION the linked user when self_access_enabled), `isEditor(string $subjectId, int $userId): bool` (same predicate for one user), `subjectDisplayName(string $subjectId): ?string`.
- `App\Medical\Reminders\VaccinationReminderPlanner::run(string $today): int` (enqueued count): for each due vaccination in [today, today + max lead] and each lead in `config('medical.vaccination_lead_days')` apply the occasions condition (fire when daysAway is lead or lead-1 within the grace day, never when daysAway < 0); recipients = reminderCandidateIds filtered by `AccessGate::allows($user, Module::Health, AccessLevel::Edit)` and active accounts; channels per NotificationPreferences and push subscriptions exactly as EnqueueOccasionReminders does; `OutboxWriter::enqueue('vaccination_due', $user, $channel, 'vaccination', $vaccinationBigintId, "vaccination_due:{id}:{next_due_on}:{lead}:{user_id}:{channel}", ['person' => subject uuid, 'vaccination' => public_id, 'date' => 'YYYY-MM-DD', 'lead' => N])`.
- Command `medical:enqueue-reminders` (thin; app/Console/Commands/EnqueueVaccinationReminders.php): runs the planner only when the family-local hour equals `config('medical.reminder_hour')` (same gate shape as occasions), `--force` option for tests/ops; scheduled `->hourly()->withoutOverlapping()->name('medical-enqueue-reminders')`.
- `App\Medical\Reminders\VaccinationDueHandler implements OutboxHandler`: `stillRelevant($item, $user)` returns false (row skipped) unless: the vaccination still exists (vaccinationDue by subject_id column of the outbox row), its next_due_on equals payload date, the date is not past (family today), payload lead is still in config, the subject exists, `AccessGate::allows($user, Health, Edit)` and `SystemQuery::isEditor($subjectId, $user->id)`; never calls Viewer::for, abort or anything that throws for a refusal. Mail message via VaccinationDueNotification (localized to the recipient: subject = `notifications.vaccination_title` with the person name; body = person, due date formatted in the recipient locale, `vaccination_due_in` for the lead; action `vaccination_action` -> `/health/people/{uuid}`; NO vaccine name; explicit text/plain part from unescaped strings via the shared trait, Markdown part escaped). Push message: title = `notifications.vaccination_title` only, url = `/health/people/{uuid}`, tag per vaccination.
- `App\Notifications\Concerns\PlainTextMail` trait extracted from WishOccasionNotification::plain (behaviour unchanged for wish mails; WishOccasionOutboxTest must stay green).
