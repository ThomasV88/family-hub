## Server rules (owner's global instructions)

Access with `ssh my-server-agent`; files in /opt belong to `deploy`, so use sudo (`sudo -u deploy ...`); send complex commands as a script over stdin (`cat s.sh | ssh my-server-agent 'sudo bash -s'`). Never print `.env`, `app.env`, `migrate.env` or `secrets/*`. Back up a file before changing it (`*.pre-zmena`). Run `nginx -t` before any reload. Do not restart other stacks (edge, mail, work-tracker). Test on staging first; production only via PR to main. Staging holds synthetic data only (staging:audit must pass).

## PROVISIONAL decisions to confirm (from the orchestrator and plans)

Two of them are presented FIRST and prominently in Task 3, because they touch a locked CONTEXT line or are irreversible (plan-checker W8):

- **Decision A (narrows a locked CONTEXT line):** CONTEXT says "A member linked to a profile always sees and edits their own record unless the admin disables it for a child profile." As implemented (item 1), a linked member additionally needs the Health module grant (View or Edit) before they see their own record; without the grant they see nothing in Health, even their own profile. This is narrower than the locked wording and needs explicit owner confirmation. Options: A1 confirm the narrowing (module grant stays a prerequisite; CONTEXT wording is updated to say so); A2 restore the locked wording (own-record access works without the module grant; follow-up quick task changes Visibility's own branch, RequireAccess on health routes for linked members, the nav/Home visibility rule and the leak-net scenarios).
- **Decision B (irreversible delete):** as implemented (item 5), any member with Edit on a person can hard-delete that person with every record and every file (data survives only in backups for the retention window). Options: B1 confirm (Edit member, hard delete); B2 stricter level (only admins, or only admins plus the linked member, may delete; quick task changes the destroy route and policy); B3 soft delete / trash (deleted people are hidden and purged after N days, restorable by an admin; quick task adds a `deleted_at` column, scopes every query, a purge command and a restore action, and extends the leak net).


1. Health module grant stays a prerequisite even for a linked member's own record.
2. Export needs Edit; emergency card needs View.
3. PDFs, HEIC and downloads are no-store; only image previews are private, no-cache + ETag.
4. Admin sees person names and member lists on Settings > Members only (no records, no counts).
5. Deleting a person needs Edit and is a hard delete (data persists in backups for the retention window).
6. No app-level file encryption in v1 (restic encryption + 0600/0700).
7. Original files are not bundled in the all-records export.
8. Linking accounts and the own-record switch live only in Settings (admin + recent), not in the person form; the own-record switch is offered for every linked person (no stored child flag).
9. Reminder leads 14 days and on the day; mail omits the vaccine name; push title names the person.
10. Specialty taxonomy v1 = 30 keys; JPEG/PNG/WebP originals are not kept (sanitized re-encode only).
