## Contracts

- Routes (no binding): `GET /health/people/{person}/documents/{document}/review` `health.documents.ai.review` (`access:module,health,edit`, `throttle:60,1,health.documents.ai.review`; query `extraction` optional uuid, `pane` passthrough); `POST /health/people/{person}/ai/{extraction}/entries/{entry}/accept` `health.ai.entries.accept`; `POST .../entries/{entry}/reject` `health.ai.entries.reject`; `DELETE .../entries/{entry}/reject` `health.ai.entries.undo` (all edit, `throttle:60,1,<name>`, JSON). There is no separate edit-accept route: accept with a `values` object is edit-accept (`edited` true when any value differs from the proposal).
- `AiDecisionRequest` (authorize first: findVisible Edit, identical 403 before validation); body `values` optional array; per-type keys are filtered by the query, not trusted.
- `AiReviewQuery::review(Viewer, MedicalSubject, string $documentId, ?string $extractionId): ?array`: scoped (membership predicate in the same select). Without extraction id -> the document's ready extraction; with id -> that extraction if it belongs to this document. Returns null for hidden/unknown (-> 403). Status not ready/superseded -> `['redirect' => true]` (controller redirects to `health.people.show` with `panel=document&id=<doc>`, where the status block lives). Props: `person {id}`, `document {id, kind, title, pageCount}` (pdf: min(PdfRasterizer::pageCount, ai.pdf.view_max_pages); image: null), `extraction {id, status, runAt (ISO), pagesRead, pagesTotal, documentDate, specialtyKey, readOnly (status superseded), pending, sections: {visits|medications|allergies|vaccinations: list{key, fields, state: pending|accepted|rejected, recordId, edited}}}`, `newestExtractionId` (ready one when this is superseded), `consentOn` (AiConsent::allows), `specialties`. Response `Cache-Control: no-store, private` (middleware default).
- `AiReviewQuery::accept(Viewer, MedicalSubject, string $extractionId, string $entryKey, ?array $values, User $user): array` in one transaction: lock the extraction `FOR UPDATE` through the Edit scope (null -> denied/403); status superseded -> `{state: 'superseded'}` 409; other non-ready -> 403; `ProposalEntries::isKey` and entry exists else 403; an existing decision row -> return its current state (200, no write); map fields to record data (values filtered to the type's allowed keys when given); `Validator::make($data, XRequest::fieldRules(), XRequest::fieldMessages())` failing -> 422 errors, nothing written; `XQuery::create($viewer, $subject, $data, 'ai')`; visit: link the document via DocumentQuery::update(changeVisit: true) only when the document's visit_id is null; insert decision (accepted, record_type, record_id (vaccination public id), edited, decided_by) catching 23505 -> current state; audit `MedicalAiEntryDecided` {subject, document, decision: accepted}. Returns `{state: 'accepted', recordType, recordId, edited, pending}`.
- `reject(...)`: same lock and checks; existing decision -> current state; insert rejected; audit decision rejected; `{state: 'rejected', pending}`. `undo(...)`: delete only a rejected decision; accepted stays (returns accepted); audit decision undone when a row was deleted; `{state, pending}`.
- zz_ai.php additions: `params` `entry` => 'visit-0', `hiddenParams` `entry` => 'visit-0'; `payloads` for accept (`{}` — the seeded visit entry carries a valid visited_on and specialty_key so the visible accept succeeds), reject `{}`, undo `{}`.
