## Contracts this plan creates

- Schema v1 (all properties required; optional = `["type","null"]` union; every object `additionalProperties: false`; no allOf/not/if; no minLength/maxLength): top level `schema_version` (integer enum [1]), `document_date` (string format date or null), `specialty_key` (enum Specialty values + `other`, or null), `visits[]`, `medications[]`, `allergies[]`, `vaccinations[]` (each `maxItems` 25). visit: visited_on, doctor, specialty_key, specialty_other, diagnosis, notes (all nullable). medication: name (string), dose, schedule, started_on, ended_on, notes. allergy: substance (string), reaction, severity (enum mild, moderate, severe, unknown, or null). vaccination: vaccine (string), given_on, next_due_on, notes. No confidence, no source quotes.
- `FailureCode` (string enum): timeout, idle_timeout, no_output, invalid_output, output_too_large, cli_error, auth, worker_lost, unreadable_document, unsupported_document, preflight. (Phase 9 adds quota.) Docblock: "Content-free by design; the only failure detail ever stored or shown."
- `ExtractionSchema` (final): `SCHEMA_VERSION = 1`, `PROMPT_VERSION = 1`, `path(): string` (resources/ai/extraction.v1.schema.json), `decoded(): array`.
- `ExtractionOutcome` (final readonly): `ok(bool)`, `payload(?array)`, `entryCount(?int)`, `failure(?FailureCode)`; named constructors `success(array, int)` and `failed(FailureCode)`.
- `ExtractionValidator` (final): `fromFile(string $path): ExtractionOutcome` (missing file -> no_output; size 0 -> no_output; size > `config('ai.caps.result', 262144)` -> output_too_large, checked with filesize BEFORE reading; then validate), `validate(string $json): ExtractionOutcome` (json_decode depth 8 with JSON_THROW_ON_ERROR; exact key sets; types and enums; strings at most 4000 chars else invalid_output; arrays at most 25; schema_version must equal SCHEMA_VERSION; dates strict Y-m-d + checkdate, outside 1900-01-01 .. today+10y become null; strings normalised by PlainText::clean, trimmed, '' -> null; a required non-null string (medication name, allergy substance, vaccine) that normalises to null -> invalid_output). Phase 7 field length caps are NOT checked here (accept re-runs the real form rules, research Q4 step 4).
- `ProposalEntries` (final): `keys(array $payload): list<string>` in fixed order visits, medications, allergies, vaccinations (`visit-0`, `medication-0`, `allergy-0`, `vaccination-0`), `entry(array $payload, string $key): ?array{type: string, fields: array}`, `isKey(string): bool` (regex `^(visit|medication|allergy|vaccination)-(0|[1-9][0-9]?)$`).
- `PlainText` (final): `clean(?string): ?string` = the control/format/bidi stripping MarkdownFormat::line already does (move the character-class logic here; MarkdownFormat::line calls it, its tests stay green).
- `PromptBuilder` (final): `build(): string` = resources/ai/prompt.v1.md with the specialty enum list and severity list substituted; no per-run data at all (images carry the document).
