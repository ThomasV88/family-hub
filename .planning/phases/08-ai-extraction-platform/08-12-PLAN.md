## Phase Goal

**As a** family member who can change a person's health record, **I want to** have a medical document read by AI into suggested entries that I check side by side with the document, **so that** I fill the record faster while nothing enters it unchecked and no document leaves the server without my explicit action.

The background job that turns a queued extraction into a ready proposal or a content-free failure, as a state machine over one row with run-time re-verification, abort, supersede-on-ready and cleanup.

## Contracts

- `AiJobQuery` (final, App\Medical\Queries; docblock "Unscoped by design: runs in the ai-worker without a viewer, after run-time re-verification. Lifecycle columns only; never returns names."): `claim(string $id): ?array{subject_id, document_id, started_by}` (UPDATE ... SET status='running', started_at=now() WHERE id=? AND status='queued' RETURNING; also moves the matching ai_calls row to running); `document(string $id): ?array{path, kind}` (joins medical_documents on (document_id, subject_id)); `abortReason(string $id): ?string` ('user' when cancel_requested_at set, 'consent' when AiConsent off, null otherwise; access is rechecked by the job itself); `finishReady(string $id, array $payload, int $entryCount, ?int $pagesRead, ?int $pagesTotal, string $model, int $durationMs): void` (one transaction: UPDATE previous ready row of the same document to superseded, UPDATE this row to ready with payload, schema/prompt version, finished_at; ai_calls -> succeeded with duration and model); `finishFailed(string $id, FailureCode $code, string $model, int $durationMs): void`; `finishCancelled(string $id, string $reason, string $model, int $durationMs): void` (reason user|consent|access; ai_calls -> cancelled). Model rule: both medical_ai_extractions.model and ai_calls.model are NULL from queue time and are written exactly once, in the finish call, as AgentOutcome::model when the agent ran, else the configured model or 'default' (runs ended before any spawn). Each finish only acts when status is running (guards against races); `reapStuck(int $runningOlderThanSeconds, int $queuedOlderThanHours): int` marks running rows older than the first bound and queued rows older than the second (worker down for hours) as failed(worker_lost) with model 'default', closing their call rows.
- `MedicalDocumentStore::copyTo(string $relativePath, string $destination): bool` (reads through the medical disk root, copies, chmod 0600; false on any failure).
- `RunExtractionJob` (App\Medical\Ai, implements ShouldQueue): constructor `(public string $extractionId)` only, and it calls `$this->onConnection('database')->onQueue(config('ai.queue'))` so the job always goes to the Postgres jobs table served only by the ai-worker (also under phpunit's sync default: tests never run it implicitly); `$tries = 1; $maxExceptions = 1; $timeout = config ai.timeouts.job (330); $failOnTimeout = true`. `handle()` steps: (1) claim, null -> return; (2) recheck: starter user exists and active, `AccessGate::forget($user)` then allows Health Edit, `SystemQuery::isEditor`, `AiConsent::allows`, no cancel request; failure -> finishCancelled(access|consent|user) and return without spawning; (3) `Preflight::envKeysClean()` false -> finishFailed(preflight); (4) WorkDir::create; kind image -> copyTo `doc.jpg`; pdf -> copyTo `doc.pdf`, `PdfRasterizer::pages(.., ai.pdf.max_pages)`, delete doc.pdf before spawning, total 0 -> unreadable_document; heic/other -> unsupported_document; (5) agent = AgentRegistry::primary(); outcome = extract(input, fn () => $this->abortReason()) where abortReason also re-runs the access check at most every 10 s; (6) after return re-check consent/cancel/access; if any -> finishCancelled and DROP the outcome; aborted -> finishCancelled(reason); ok -> finishReady + AgentHealth::recordSuccess; failure auth -> AgentHealth::recordAuthFailure + finishFailed(auth); other failure -> finishFailed(code); (7) audit `MedicalAiRunFinished` {subject, document, status: succeeded|failed|cancelled} with the starter as actor (null if deleted); (8) finally WorkDir cleanup and `WorkDir::sweepStale()`. `failed(Throwable)` marks the row failed(worker_lost) via finishFailed if still running and rethrows nothing with content (exceptions thrown inside handle are content-free RuntimeExceptions only).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| queue -> ai-worker job | job runs without a viewer, long after the request |
| ai-worker -> OpenAI (via CLI) | document pages leave the server |
| CLI result -> proposal table | untrusted data written after validation |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-50 | Elevation | hidden person access at job run time (starter lost access) | mitigate | AccessGate::forget/allows + SystemQuery::isEditor + active user check before spawn, every 10 s during the run and before persist; cancelled(access), nothing sent (tested) |
| T-08-51 | Elevation | consent bypass (consent turned off after queueing) | mitigate | AiConsent::allows before spawn, in the abort loop and before persist; cancelled(consent) and result discarded (tested) |
| T-08-52 | Tampering | duplicate upload on redelivery | mitigate | Atomic claim; tries 1; retry_after 900 (08-07); redelivery test |
| T-08-53 | Information disclosure | content in logs, failed_jobs, audit, ai_calls | mitigate | ids-only job payload, content-free exceptions, FailureCode only, canary tests across all sinks |
| T-08-54 | Information disclosure | document copies after crash | mitigate | tmpfs WorkDir cleanup in finally, sweepStale, PDF original deleted before spawn |
| T-08-55 | Tampering | prompt-injected output written directly | mitigate | Only ExtractionValidator output is persisted, via bound parameters into a proposal table; never into record tables |
| T-08-56 | Elevation (cost) | key present at spawn time | mitigate | Preflight::envKeysClean before each spawn -> failed(preflight) |
| T-08-57 | Denial of service | stuck running or long-queued rows | mitigate | ai:reap-stuck (scheduled by 08-14) closes running rows past the job timeout and queued rows older than 6 h; job timeout above process timeout |
