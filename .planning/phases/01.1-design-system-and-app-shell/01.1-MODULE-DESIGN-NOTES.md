# Phase 01.1: Module Design Notes

Status: chosen direction, not built. No module UI is implemented in Phase 01.1; these notes carry the sketch outcomes (004 to 008) forward to the phases that build each module. Source of truth: the skill `sketch-findings-family-hub` (`.claude/skills/sketch-findings-family-hub/references/*.md`, sketches under `.claude/skills/sketch-findings-family-hub/sources/`). Anything marked "(note)" is an inference, not a sketch decision.

## Tasks (To-do)

Chosen sketch: 004, winner B (one column per family member). Source: `.claude/skills/sketch-findings-family-hub/sources/004-todo-module/index.html`.

Builds in: Phase 3 (To-Do).

Decisions:
- One column per family member; cards with checkbox, title, recurrence icon, lock icon for personal tasks, due and overdue tags. No avatar on cards (the column is the assignee).
- Quick add (Enter) and filter chips (All / Mine / Shared / Personal) above the columns.
- Detail panel: title, assignee, due, repeat (none, daily, weekly, monthly, after completion), visibility shared/personal with an explanation, notes, delete. Docked at 900 px and wider, overlay on iPad, bottom sheet on phone.
- Columns adapt to the content width: 3 from 700 px, 2 from 440 px, else 1, using `grid-template-columns: repeat(n, minmax(0, 1fr))` with container queries. On phone the current user's column comes first.

Avoid: due-date groups as the main layout (candidate for a phone or dashboard card only); a dense table.

Open questions: many members (scroll or "my column first"); an unassigned column; multiple assignees; custom recurrence.

Components from 01.1: UiCheckbox (task done, indeterminate not needed), UiTag (due, overdue), UiChip (filters), UiDetailPanel (docked, overlay, sheet), quick add built from UiInput with a visually hidden label (`labelVisuallyHidden`) and `focus()` exposed for the floating add button, UiField, UiSelect, UiTextarea, UiRadio (visibility), UiButton (delete as danger).

## Wishlist

Chosen sketch: 005, winner D (A + C). Source: `.claude/skills/sketch-findings-family-hub/sources/005-wishlist-module/index.html`.

Builds in: Phase 4 (Wishlist).

Decisions:
- From the top: shopping summary card (the viewer's reservations for OTHER people; a co-buy counts only the own share; Show/Hide; a click jumps to that person's wish), person chips (own list marked "(mine)"), occasion strip, banner on the own list, card gallery (2 columns phone, 3 tablet, 4 wide).
- Cards: image, title, price, link count, and a status tag on other people's lists (free, reserved by name, reserved by you, co-buy with contributors).
- Secrecy rule (WISH-04): the own list shows no status tags, no reservation counts, no notifications about reservations, and nothing in exports or search. Enforce server-side.
- Detail panel: image, "load image from link", title, price, multiple URLs, notes, reservation box (reserve, cancel, propose or join co-buy, share per person). Images need an og:image job with a manual upload fallback and SSRF protection.

Avoid: (note) the reference lists no explicit avoid items for the wishlist; the secrecy rule above is the one hard constraint, and UI hiding alone is not enough because it must hold server-side.

Open questions: occasions as first-class objects; giver reminders; a "bought" state; what a child sees on parents' lists.

Components from 01.1: UiCard (gallery), UiAvatar, UiTag (status), UiChip (person chips), UiDetailPanel, UiField, UiInput, UiTextarea, UiButton, UiAlert (banner on the own list, (note)).

## Finance

Chosen sketch: 006, winner D (A + C). Source: `.claude/skills/sketch-findings-family-hub/sources/006-finance-module/index.html`.

Builds in: Phase 5 (Finance).

Decisions:
- Account chips and month switcher on top, tabs Overview / Transactions / Recurring, actions "Import CSV" and "+ Entry".
- Overview: income, expense and balance cards, a "still to pay" card (sum, count, overdue), budgets by category with over-budget in red, monthly spending bars. It could also show the next 2 to 3 upcoming payments.
- Recurring tab: the same still-to-pay card, Calendar (default) / List switch, a month grid with payments per day (overdue in red), day detail with "Paid" that records the matching transaction.
- State rule: a payment is paid if a matching transaction exists this month, overdue if the due day passed without one, otherwise waiting. Matching compares amount, date window and payee, and the same rule applies to bank import so manual payments are not duplicated.
- A restricted account has a lock; visibility is enforced server-side including totals, recurring items and charts.
- Add panel (docked or sheet): expense/income, amount, description, category, account, "repeat every month". Import panel: file, recognized bank profile, preview with duplicates struck through, account, explicit confirm; nothing is saved otherwise.
- Money: whole euros with a thin minus and Slovak formatting in the UI; store minor units plus a currency code.

Avoid: one-page month (too dense on phone); the calendar alone as the module home. Deferred: multi-currency, savings goals, categories and rules.

Open questions: (note) the reference lists none; deferred items above are the known gaps.

Components from 01.1: UiTabs (Overview / Transactions / Recurring), UiTable (responsive transactions), UiProgress (budgets), UiTag (danger for overdue, success for paid, warn for waiting), UiChip (account chips), UiDetailPanel (add and import panels), UiCard, UiSelect, UiField, UiInput, UiRadio or UiChip (expense/income), UiCheckbox ("repeat every month"), UiButton.

## Medical

Chosen sketch: 007, winner D (C + timeline from B). Source: `.claude/skills/sketch-findings-family-hub/sources/007-medical-records/index.html`.

Builds in: Phase 7 (Medical Records); the AI flow arrives in Phases 8 and 9.

Decisions:
- Person chips (people need no account); person header with age, a "no account" marker, a per-person AI consent flag (default off), access list, Export.
- Default view is specialty folders (accordion); a folder body is a chronological timeline (dots, dates; visits and documents). A switch "By specialty / Timeline" shows the full feed with specialty and vaccination filter chips. Emergency card plus medications and allergies in a side column.
- AI flow: blocked without per-person consent; consent notice; running; quota wait with fallback agent and time; proposal with sure/check field markers; accept / reject / re-run; only accepted data is stored as verified. Manual entry is primary.
- Export: scope is one specialty or all; format for the doctor (PDF) or for AI (Markdown, person name omitted); unverified AI data is excluded unless chosen, then labelled.
- Review screen proposal (not sketched): wide screen on desktop and iPad with the document left and fields right, document above fields on phone. A 440 px docked panel is too small.
- i18n: plural and name forms through ICU plurals, never string concatenation (found in testing: "1 navstev", name declension).

Avoid: a 440 px docked panel for the AI review screen; string-concatenated plurals and names.

Open questions: (note) the reference lists none for medical beyond the unsketched review screen.

Components from 01.1: UiChip (person chips and filter chips), UiAlert (AI consent notice and quota wait), UiDetailPanel, UiTag (sure/check markers, verified state), UiTabs or a segmented switch (view switch, (note)), UiCard (emergency card), UiButton, UiSwitch (consent flag), UiField.

## Settings

Chosen sketch: 008, winner A (section list left, content right). Source: `.claude/skills/sketch-findings-family-hub/sources/008-settings/index.html`.

Builds in: Phase 2 (Identity and Authorization Core) for members, permissions, appearance, language and account; Phases 8 and 9 for the AI agents section.

Decisions:
- Section list on the left (Members and permissions, AI agents, Appearance and language, My account), content on the right.
- Permission matrix member by module (Tasks, Wishlist, Finance, Health) with None / Read / Edit / Manage; admin is locked; phone shows cards. Finance and Health default to None. Health grants open a per-person panel (None / Read / Edit per person, including people without accounts); export and running AI need Edit. Finance account visibility stays in the module.
- Invite: email, template (Adult, Child, Wider family) fills only Tasks and Wishlist; language; valid for 7 days.
- AI agents: ordered list (Codex primary, Copilot fallback), switch, login status, model, "check login" button; on an expired login show the server command, the app never stores tokens; Claude and Antigravity are not offered in v1; never per-token keys. Bulk regeneration: scope (failed / unverified / all), pace (overnight / now), confirmation, skips people without AI consent, one document at a time.
- Language SK/PL/EN and light/dark/system per user; account: password, Google, TOTP (required for Health and Finance).

Avoid: using `[data-theme]` as a click-delegation selector (the `<html>` element carries it, so every click matches); this bug appeared in the sketches and must not reach the app. Also avoid offering per-token API keys or storing agent credentials.

Open questions: bulk regeneration admin-only (assumed); notification preferences; session and device management.

Components from 01.1: UiTable or a card list (permission matrix, cards on phone), UiSwitch (agent on/off, TOTP-style toggles), UiRadio (None / Read / Edit levels, pace), UiSelect (model, language, template), UiField, UiInput, UiButton, UiTag (login status), UiAlert (expired login with the server command), ThemeSwitch and LanguageSwitcher (already built).
