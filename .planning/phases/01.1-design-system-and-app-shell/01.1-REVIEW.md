# Phase 01.1: Code Review Report

**Reviewed:** 2026-11-13
**Depth:** standard
**Files Reviewed:** 33 (StyleGuide.vue and tokens.css were not read line by line)

## Summary

The security surface is small and mostly sound.
- The theme cookie is allowlisted server-side with a strict `is_string` plus `in_array` check, so array-valued cookies are rejected.
- It is escaped in Blade.
- It is excluded from encryption on purpose.
- There is no `v-html`, `innerHTML` or `eval` anywhere in the reviewed code.
- No inline scripts are used, and Vue style bindings go through the CSSOM, so a strict CSP is compatible.
- The `/_style` route is gated by both a route-registration check and a controller guard.

The real defects are in the interaction layer:
- The focus trap and scroll lock break in several situations (docked panel, nested overlays, hidden tab panels).
- Toast timers are paused and resumed incorrectly.
- `initialFocus` is resolved incorrectly for plain elements.
- Theme state can drift between localStorage and the cookie.

No critical issues were found.

## Warnings

### WR-01: Body scroll lock is not re-entrant, so the page can stay locked permanently

**File:** `resources/js/Components/ui/UiDialog.vue:19-36` (same pattern in `UiDetailPanel.vue:21-40`)
**Issue:** Each instance saves `document.body.style.overflow` and restores it on close. With two overlays open (for example the coming-soon overlay panel and then a confirm dialog), the second saves `'hidden'` as its "previous" value. If the first closes before the second, overflow becomes `''` while the second is still open. When the second closes, it restores `'hidden'`, and the page never scrolls again.
**Fix:** Use a shared module-level lock counter (`lockScroll()` / `unlockScroll()`) that saves the original value only on the 0 to 1 transition and restores it on the 1 to 0 transition. Put it in a shared `useScrollLock.js`.

### WR-02: Docked (non-modal) detail panel still traps Tab

**File:** `resources/js/Components/ui/UiDetailPanel.vue:42-55,63`
**Issue:** The watcher calls `trap.activate()` for every mode, including `docked`, where `modal` is false (no `role="dialog"`, no `aria-modal`, no scrim). Keyboard users cannot Tab from the docked panel back to the main content or navigation. Only Esc or Close gets them out, which closes the panel.
**Fix:** Activate the trap only when `modal.value`. For docked mode, move focus to the panel heading on open without trapping, and return focus on close.

### WR-03: Panel mode change while open leaves a stale trap and scroll lock

**File:** `resources/js/Components/ui/UiDetailPanel.vue:62-86`, `resources/js/Layouts/AppShell.vue:30`
**Issue:** `mode` is reactive to window and container width. Rotating an iPad or resizing while a panel is open switches between the `<aside v-if>` branch and the teleported-dialog branch. This has three effects.
- The element is replaced, and the trap's keydown listener stays on the old, detached node.
- If the change is overlay to docked, `previousOverflow` stays `'hidden'`, so a non-modal panel locks the page.
- Focus drops to `<body>`.

**Fix:** Watch `[() => props.open, modal]` together. On a mode change, deactivate and unlock, then re-lock and re-activate on the new container after `nextTick`.

### WR-04: Focus trap includes hidden or non-visible elements

**File:** `resources/js/Components/ui/useFocusTrap.js:1,7,16-17`
**Issue:** `FOCUSABLE` matches elements regardless of visibility. Examples are `UiTabs` panels (`v-show`, `tabindex="0"`, `display:none`) and anything under `hidden`, `inert` or `visibility:hidden`. If the first or last match is invisible, `first.focus()` or `last.focus()` is a silent no-op after `preventDefault()`. The keyboard user is stuck. Tab can also land on an invisible element in the middle of the cycle. There is also no `[contenteditable]`, `summary`, `audio[controls]` or `input[type=hidden]` handling.
**Fix:** Filter the list with a visibility check, for example `el.offsetParent !== null || el.getClientRects().length`, and exclude `[hidden]`, `[inert]` and `input[type=hidden]`.

### WR-05: `resolve(initialFocus)` mishandles plain DOM elements

**File:** `resources/js/Components/ui/useFocusTrap.js:46-50`
**Issue:** `'value' in value` is true for `HTMLInputElement`, `HTMLButtonElement`, `HTMLSelectElement`, `HTMLTextAreaElement` and others, because they have a `.value` property. A consumer following the documented contract ("element or component instance") and returning an `<input>` gets its string value back. `target.focus?.()` is then a no-op, and `?? items()[0]` is never reached because the string is non-null. The dialog opens with no focus at all. It only works today because `UiConfirmDialog` passes a Vue ref. It also throws a TypeError on a primitive return.
**Fix:** Import `isRef` from `vue` and use `const el = isRef(value) ? value.value : value; return el?.$el ?? el ?? null;`. Also verify `target instanceof HTMLElement`.

### WR-06: Toast pause/resume timing bugs

**File:** `resources/js/Components/ui/UiToastRegion.vue:22-33,52-55`
**Issue:**
- `pause()` is not idempotent. Hovering and then focusing the same toast (`mouseenter` plus `focusin`) subtracts the elapsed time twice. `remaining` goes negative and is clamped to 1 s on resume, so the toast vanishes early.
- `mouseleave` resumes the timer even when keyboard focus is still inside the toast. The toast can disappear from under a focused user, and focus is lost.
- `focusout` fires when focus moves between children, which causes pause/resume thrash.

**Fix:** Add `if (!entry || entry.paused) return;` in `pause`. Track hover and focus separately (two flags per toast) and resume only when both are false. Check `event.relatedTarget` in `focusout`.

### WR-07: Theme preference can drift between localStorage and cookie

**File:** `resources/js/theme.js:12-20,63-65`, `resources/views/app.blade.php:1-3`
**Issue:** `getThemePreference()` prefers localStorage, but the server renders from the cookie. `initTheme()` never re-syncs the cookie. If the cookie is cleared or expired, or was set on a different path or subdomain, while localStorage keeps `dark`, every load renders the server's `system` first. It then flips after the deferred module executes, which is a visible flash of the wrong theme on every navigation. The "Secure" decision is also made once per write, so an old non-Secure cookie from http staging persists.
**Fix:** In `initTheme()`, if the stored preference differs from the `data-theme-pref` attribute, rewrite the cookie (extract the cookie write into a helper). Consider an inline-nonce head script if the flash matters.

### WR-08: PwaUpdateBanner and the toast region overlap

**File:** `resources/js/Components/PwaUpdateBanner.vue:35-43`, `resources/js/Components/ui/UiToastRegion.vue:64-74`, `resources/js/Layouts/AppShell.vue:55`
**Issue:** Both are `position: fixed` at the same `bottom: var(--fh-toast-offset)` and are centered. When a toast and the update banner are visible together they stack on top of each other, and the banner (z-index 50 against 60) is partly covered. The banner also uses physical `left: 50%` and `translateX(-50%)`, inconsistent with the logical properties used elsewhere (RTL).
**Fix:** Render the banner inside a shared bottom stack container, or offset one of them. Use `inset-inline-start: 50%` with an RTL-aware transform.

## Info

### IN-01: Style-guide link and route use different environment predicates

**File:** `resources/js/Shell/AccountMenu.vue:26`, `routes/web.php:17`, `app/Http/Controllers/StyleGuideController.php:12`
**Issue:** The menu shows "Style guide" whenever `env !== 'production'`. The route exists only for `local`, `staging` and `testing`. Any other APP_ENV (`development`, `stage`, `qa`) shows a link that 404s. Registration in `web.php` is evaluated at route-cache time. Any future `php artisan route:cache` in the image build would bake in the build environment's APP_ENV. The Dockerfile has none today, but this is fragile. The controller guard is a redundant duplicate of the route condition.
**Fix:** Define one allowlist (for example `config('app.style_guide_enabled')`), expose a boolean prop from `HandleInertiaRequests`, and use it for the route, the controller and the menu. The `app.env` prop also shares the raw environment name with all clients, which is low-value disclosure.

### IN-02: UiMenu Escape does not stop propagation

**File:** `resources/js/Components/ui/UiMenu.vue:54`
**Issue:** The menu's Escape handler calls `preventDefault` only. A UiMenu inside a `UiDialog` or `UiDetailPanel` closes both the menu and the dialog on one Esc, because those listeners are on ancestors.
**Fix:** Call `event.stopPropagation()` for Escape (and the other handled keys) in `onKeydown`. Closing on focusout, or returning focus on item selection from a menu that unmounts, is also worth covering.

### IN-03: UiTabs has no focusable tab when `modelValue` matches nothing

**File:** `resources/js/Components/ui/UiTabs.vue:50`
**Issue:** `tabindex` is 0 only for the tab equal to `modelValue`. If `modelValue` is stale or empty, every tab gets `-1` and the tablist is unreachable by keyboard. Also, `select()` with zero tabs computes `% 0` (NaN).
**Fix:** Compute the effective index as `Math.max(0, tabs.findIndex(...))` and guard `count === 0`.

### IN-04: AppShell is wrapped per page instead of used as a persistent layout

**File:** `resources/js/Pages/Home.vue:49` (and `Layouts/AppShell.vue`)
**Issue:** Because each page renders `<AppShell>` itself, the whole shell (sidebar, observers, toasts, panel state, online listeners) is unmounted and remounted on every Inertia visit. Panel and toast timer state is lost, and the shell measures width again each time. Listener cleanup is correct, so this is not a leak, but it defeats the persistent-layout pattern and will cause flicker.
**Fix:** Use `defineOptions({ layout: AppShell })`, or `Home.layout = ...`, and pass `current` through page props.

### IN-05: Smaller items

**File:** `resources/js/Shell/ComingSoonPanel.vue:12-17`, `resources/js/app.js:9-12`, `resources/js/Components/ui/UiField.vue:29`, `resources/js/Dashboard/QuickAdd.vue:15-20`
**Issue:**
- `shell.closePanel()` nulls `panelModule` immediately, so during the leave transition the title becomes `''` and the dialog briefly has an empty accessible name.
- `import.meta.glob` is called inside `resolve` on each call, and a missing page returns `undefined` with no helpful error.
- The `required` asterisk in UiField is `aria-hidden`, so required state is conveyed to assistive tech only if the control sets `required`.
- QuickAdd silently discards the user's typed text. The code documents this as intentional until Phase 3, but it is a data-loss UX that should be visible (placeholder copy or disabled state).

**Fix:** Keep the last module key during the leave transition, hoist the glob and throw a clear error for a missing page, make the control read `required` from the field context, and tell users the quick add is not saved yet.
