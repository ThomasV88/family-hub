# Phase 01.1: Design System and App Shell - Context

**Gathered:** 2026-11-13
**Status:** Ready for planning

<domain>
## Phase Boundary

One shared minimalist visual language and a responsive app shell: design tokens with light/dark theme, a core Vue component library shown on a living style page, shell with navigation for phone/iPad/desktop adapting to SK/PL/EN text lengths, an accessibility baseline, and the recorded per-module design direction (sketches 001-008) for later phases. No module features (to-do, wishlist, finance, medical, settings content) are built here.
</domain>

<decisions>
## Implementation Decisions

### Visual language (locked by sketch 003 and wrap-up)
- Neutral off-white palette with one restrained blue accent; tokens from `.claude/skills/sketch-findings-family-hub/sources/themes/default.css`, light and dark.
- 8-12 px radii, 1 px borders, minimal shadows, thin dividers rather than heavy frames, generous whitespace.
- Controls at least 36-40 px high; touch targets large enough for older family members.
- References: Notion (clean pages), Apple Reminders (simple lists, quick add).

### Shell and navigation (locked by sketches 001, 002)
- Phone: bottom bar with 5 modules plus floating add button; detail panels as bottom sheets.
- iPad/desktop: toggleable sidebar (64 <-> 232 px); detail panels docked right on wide screens, overlay otherwise.
- Layouts respond to container width (container queries), not only viewport.
- Short nav labels (Wishlist, Financie, Zdravie); layouts must not depend on short text, SK/PL/EN lengths tested.
- Home is an overview dashboard of module tiles with the to-do list first; quick add always within reach.

### Components and style page
- Core Vue components: buttons, inputs, forms, lists, dialogs, tables, empty and error states, ported from sketch patterns to Vue 3 + Inertia.
- A living style page (dev/staging only route) shows every component, token and state in both themes.
- Theme switch: light, dark, follows system by default, persisted per user (cookie/localStorage for now; per-user storage arrives with Phase 2).

### Accessibility baseline
- Keyboard navigation, visible focus ring, WCAG AA contrast, 44 px minimum touch targets on touch layouts; automated checks (axe or equivalent) on style page and shell.

### Module design direction (recorded, not built)
- Record sketches 004-008 outcomes (tasks, wishlist, finance, medical, settings) as per-module design notes in the phase directory for later phases.

### Claude's Discretion
Component API naming, file layout under resources/js, icon set, animation details, test tooling choices (Vitest + a11y checks), as long as they follow the locked stack in CLAUDE.md and the existing i18n/PWA setup from Phase 1 (no runtime caching of private data).
</decisions>
