## Facts the executor needs (verified during planning)

- nginx CSP (docker/nginx/snippets/security-headers.conf) is `script-src 'self'`: inline scripts are blocked. UI-SPEC asks for "an inline script in the root Blade view"; that would be blocked, so the no-flash requirement is met without any script: Blade renders `data-theme` from the cookie, and a `prefers-color-scheme: dark` media block covers System before JS runs. The CSP file is NOT changed.
- Laravel encrypts all cookies by default; the JS-written `fh_theme` cookie must be excluded via `$middleware->encryptCookies(except: ['fh_theme'])` in bootstrap/app.php, and its value must be allowlisted server-side.
- `lucide-vue-next` is deprecated on npm ("Please use @lucide/vue instead", same lucide-icons/lucide repo). `vitest-axe` is at 0.1.0 and unmaintained. This plan therefore installs `@lucide/vue` (dependency) and `axe-core` (devDependency) and writes a local axe helper instead of vitest-axe (UI-SPEC allows "or equivalent").
- Registry metadata seen during planning (2026-11-13): `@lucide/vue` 1.72.0, ISC, github.com/lucide-icons/lucide, peer vue >=3.0.1; `axe-core` 4.14.0, MPL-2.0, github.com/dequelabs/axe-core.
- Message files are `lang/en.json`, `lang/sk.json`, `lang/pl.json` (UI-SPEC's `en-GB.json` naming is wrong); tests/js/i18n.test.js enforces identical keys and no empty values.
- Pest runs in the container: `docker compose run --rm app ./vendor/bin/pest`. Vitest runs on the host: `npx vitest run`. Environment switching in Pest: assign `app()['env']` directly (do not declare a global helper named `setEnv`; tests/Feature/StagingSeedTest.php already declares one and Pest loads all files).
