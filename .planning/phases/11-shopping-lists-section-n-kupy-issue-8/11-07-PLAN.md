## Decisions applied

- Who may send (orchestrator, overrides UI-SPEC screen 8 "viewers included"): `ShoppingAccess::canMail` (creator, effective responsible, contributors with Shopping edit, any list status). Viewer -> 403, no role -> 404.
- Limits (research A1): config `shopping.mail.per_send` 5, `per_user_hour` 10, `per_user_day` 30, `per_recipient_day` 5. A named limiter `shopping-mail` in AppServiceProvider with `Limit::perHour(10)->by(user id)` and `Limit::perDay(30)->by(user id)` and a translated 429 response following the existing limiter response convention in AppServiceProvider (flash or JSON error key `shopping.mail.err_limit`). The per-recipient cap is checked inside the mailer with `RateLimiter::attempt('shopping-mail-to:' . sha1($address), 5, ..., 86400)` before anything is queued; if any address is over its cap the whole send is refused with the same 429 key and nothing is queued.
- Content (research D11, UI-SPEC screen 8): subject "{list name} — shopping list" (localised, CR and LF stripped); body lines "Store: …" (omitted when none), "Responsible: {name}", blank line, one line per item "- {quantity} {unit} {name}" with the note in parentheses, plus "(bought)" or "(unavailable)" markers when the list is locked or finished; no link into the app, no member e-mail, no Reply-To; From is the app default. Built in the sender's locale at request time as a string snapshot; the Mailable has a text view only, rendered from that string through `HtmlString` or `{!! !!}` so `&` and `<` are not escaped (research Pitfall 8).
- One queued Mailable per address so recipients never see each other.
- Audit: new `AuditEvent::ShoppingListMailed = 'shopping_list_mailed'`, group `account`, metaKeys `['recipient_count']`, actor = sender, no target user, no addresses anywhere in the audit row or logs.

## Contracts

- Route `routes/web/shopping-mail.php`: POST `/shopping/lists/{list}/mail` name `shopping.lists.mail`, `whereNumber('list')`, middleware `access:module,shopping,edit` and `throttle:shopping-mail`. Body `{addresses: string[]}`. Response 303 back with flash toast key `shopping.mail.toast_sent` and flash data `mail_sent_count`.
- `MailListRequest`: `addresses` required array 1 to 5; each item trimmed, lower-cased, de-duplicated in `prepareForValidation`, rule `email:rfc` and `max:254`; error keys `shopping.mail.err_invalid` and `shopping.mail.err_too_many`.
- `ShoppingListText::for(ShoppingList $list, string $locale): array{subject: string, body: string}`; `ShoppingListMailer::send(User $sender, ShoppingList $list, array $addresses): int`.
