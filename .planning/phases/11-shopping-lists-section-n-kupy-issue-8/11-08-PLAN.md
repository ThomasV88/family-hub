## Contracts

- Command `shopping:enqueue-reminders` (mirror `EnqueueReminders`): in a transaction select lists with `remind_at <= now()`, `reminder_enqueued_at is null`, `status <> 'done'`, ordered by remind_at, limit 200, `lock('for update skip locked')`; for each, recipient = `ResponsiblePerson::effective($list)`; if that user `canSignIn()`, holds Shopping view or edit, has push enabled (`NotificationPreferences::enabled($user, 'push')`) and has a `PushSubscription`, call `OutboxWriter::enqueue('shopping_reminder', $user, 'push', 'shopping_list', $list->id, "shopping_reminder:{$list->id}:{$remindAtTs}:{$user->id}:push", ['list_id' => $list->id, 'remind_at' => $remindAtTs])` (payload ids and timestamps only); then always set `reminder_enqueued_at = now()`. Scheduled in routes/console.php: `Schedule::command('shopping:enqueue-reminders')->everyMinute()->name('shopping-enqueue-reminders')->withoutOverlapping();`
- `ShoppingReminderHandler` implements `OutboxHandler`: `kind()` 'shopping_reminder'; `stillRelevant($item)` = list exists, status not done, `remind_at` timestamp equals the payload, the recipient is still the effective responsible, `canSignIn()` and holds Shopping view or edit; `pushMessage($item, $user)` returns title and body from `notifications.shopping_reminder.*` in the recipient's locale built from the list name and store at send time, url `/shopping/lists/{id}`; `sendMail()` throws `LogicException` (only push rows are written). Registered in `OutboxHandlers::HANDLERS`.
