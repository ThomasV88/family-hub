<objective>
Teach the existing Phase 8/13 run job (D-07: reuse, do not rebuild) two things a batch re-scan needs: apply the member's brightness, contrast and black-and-white settings to the copy sent to the AI only (D-04), and read the pages afresh instead of reusing stored text.

Decisions (Claude's discretion, recorded):
- Black and white means grayscale, not a 1-bit threshold: 13-EVALUATION showed that our own contrast/levels pre-processing hurt low-contrast pages, and a hard threshold destroys faint strokes. The member chooses it deliberately; default stays off.
- Ranges (percent, CSS filter semantics): brightness 50..150, contrast 50..200, defaults 100/100/false. Server maths equal the CSS `brightness()` then `contrast()` then `grayscale()` chain: per channel c' = (c * b - 127.5) * k + 127.5 with b = brightness/100, k = contrast/100, done in C by one GD `imageconvolution` with centre weight b*k, divisor 1 and offset 127.5*(1-k), then `imagefilter(IMG_FILTER_GRAYSCALE)` when bw is on.
- An adjusted copy is first fitted to 2048 px on the long edge (13-EVALUATION: Codex downsizes to 2048 itself, larger only costs quota) and written back under the same file name and format (JPEG quality 92 for .jpg, PNG for .png pages). Neutral settings skip the adjuster entirely.
- The adjustment itself never counts as an AI run; only the run that sends the copy is logged (one ai_calls row as today).

Purpose: BULK-06 server half and the fresh-read half of BULK-05.
Output: Adjustments value object, AiCopyAdjuster, job and claim changes, two Pest test files.
</objective>
