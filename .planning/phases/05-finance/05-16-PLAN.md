## Commit / undo / discard contract (implemented by 05-18)

- POST /finance/import/{batch}/commit body {include: list<rowId>, categories: {rowId: categoryId|null}} → 303 to /finance/import/{batch} which then has status 'committed' and result {added, matched, kept: 0}; 422 with error key finance.imp.select_one when include is empty; any other failure leaves nothing saved (alert finance.imp.err_commit).
- POST /finance/import/{batch}/undo → 303 back with flash toast finance.toast.imp_undone and, when rows were kept because they were edited, a second flash finance.toast.imp_undone_kept with count `kept`.
- DELETE /finance/import/{batch} (draft only) → 303 to /finance/import (used when leaving the wizard).
- Rows gain `matchName: ?string` (recurring item an imported row would auto-match), shown as "Matches {name}".
- The "earlier imports" history row has `canUndo` = status committed and the viewer has finance edit.

## Client limits

Client checks mirror the server (never authoritative): extensions .csv/.txt, size <= import.limits.maxBytes (2 MiB). The preview call re-sends the File object held in memory on each settings change; nothing is stored in localStorage or IndexedDB.
