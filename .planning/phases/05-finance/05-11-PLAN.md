## Rules

- Auto matching considers only occurrences that are unmatched, on or after schedule_effective_from, within the overdue lookback, and up to today + window_days; candidates are transactions of the same account not already matched (UNIQUE transaction_id) and not rejected for that occurrence. Inserts use insertOrIgnore (ON CONFLICT DO NOTHING) so re-runs are no-ops; manual matches are never replaced by auto.
- Runs: after TransactionWriter create/update (on that transaction), after RecurringWriter create/update (backfill for that item), after import commit (05-15). Never on page load.
- Unmatch deletes the match row and inserts a rejection row for (recurring, date, transaction).
- Manual match replaces the occurrence's existing match; a transaction already matched to another occurrence is rejected with finance.error.transaction (identical to hidden/unknown).
- recordPayment creates an expense on the recurring item's account via TransactionWriter with automatic matching disabled for that call, then inserts the manual match, all in one DB transaction; default amount = expected, date = due date (user may change), description = recurring name, category = recurring category.
