## Rules

- Commit is allowed only for a draft owned by the viewer on a visible account (viewer needs finance edit); a commit on an already committed batch redirects to the batch page without changes (idempotent); anything else is 404 identical to a random id.
- Included rows: state new or probable_duplicate → insert with the staged import_hash; state duplicate (ticked "import anyway") → insert with import_hash = sha256(staged hash . '|' . batch id); invalid rows can never be included (422). Inserts use INSERT ... ON CONFLICT (account_id, import_hash) WHERE import_hash IS NOT NULL DO NOTHING; source 'import', import_batch_id = batch, category from the request overrides (expense/income category of matching kind, else null), description = first 160 characters of the staged description (transactions column limit), created_by = viewer.
- Unticked probable_duplicate rows reconcile: the referenced manual transaction (still visible, still import_hash NULL) gets import_hash = staged hash and reconciled_batch_id = batch.
- After inserts: RecurringMatchService::matchTransactions(viewer, new ids); batch becomes committed with added_count, matched_count, committed_at; staged rows of the batch are deleted (only the counts remain).
- Undo (finance edit + visible account, committed batches only): delete batch transactions with edited_at IS NULL and transfer_id IS NULL; detach the rest (import_batch_id = NULL) and count them as kept; clear import_hash and reconciled_batch_id on transactions reconciled by this batch; status undone, undone_at, kept_count; matches cascade with deleted rows. One DB transaction.
- Discard: DELETE on a draft owned by the viewer deletes it (rows cascade).
- matchName on review rows: RecurringMatchService::previewMatches(Viewer, accountId, list of staged rows) runs Matcher::assign on the account's visible recurring items with the staged new rows as pseudo-candidates and returns rowId => recurring name; nothing is written.
