## Contracts this plan creates (consumed by 05-15, 05-17 and 05-19)

- `DisplayKind::sql(Viewer $v, string $alias = 't'): array{0: string, 1: array}` returns the CASE/EXISTS fragment and bindings: a transfer leg counts as income/expense (by sign) when its counterpart account is not visible to the viewer; fully visible transfers are excluded from income, spending, category spending and budgets. Identical to 05-08's display-kind rule; the EXISTS is built with Visibility so every statement carries finance_account_members.
- `BudgetQuery`: `forMonth(Viewer, string $month, ?string $accountId): array<string currency, list<BudgetRow>>` (only currencies of the viewer's visible accounts, or the selected account's currency); `find(Viewer, string $id): ?FinanceBudget` (null unless the budget currency is among the viewer's visible-account currencies; null for non-UUID strings without SQL); `activeFor(string $categoryId, string $currency, string $month): ?FinanceBudget`; `upsertVersion(Viewer, string $categoryId, string $currency, string $fromMonth, ?int $amountMinor): void` and `deleteVersion(Viewer, string $id): int`, both writing with a WHERE/guard predicate `currency IN (select currency from finance_accounts where id in Visibility::accountIds)` so the arch rule from 05-04 (every finance mutation carries the membership predicate) holds.
- BudgetRow: {id, categoryId, limitMinor: string, spentMinor: string, percent: int, state: 'ok'|'near'|'over', overMinor: string|null, effectiveFrom: 'YYYY-MM'}.
- Routes (`access:module,finance,edit`, whereUuid('budget'), `throttle:60,1,<route name>`): finance.budgets.store POST /finance/budgets {category_id, currency, amount, from_month}; finance.budgets.update PATCH /finance/budgets/{budget} {amount, from_month}; finance.budgets.destroy DELETE /finance/budgets/{budget} {from_month}; all redirect 303 back with flash finance.toast.budget_saved / finance.toast.budget_removed. Controllers take `string $budget`.

## Rules

- Budget limit for month M and currency C: the row with greatest effective_from <= first day of M for (category, C); amount_minor NULL is a tombstone (no budget from that month). No copy rows and no carry-over of unspent amounts (decision).
- spent = magnitude of display-expense rows of that category and currency in the month, on visible and selected accounts. percent = intdiv(spent * 100, limit); state over when spent > limit, near when spent * 100 >= limit * 90, else ok; overMinor = spent - limit when over.
- Months are 'YYYY-MM' strings converted to date boundaries; never date_trunc on a date column without ::timestamp; every SUM cast ::bigint and to int in PHP.
- Budget edits go through BudgetQuery mutation methods only (no `->update(`/`->delete(` in BudgetWriter), so FinanceMutationScanTest and the runtime mutation-statement check from 05-04 cover them.
