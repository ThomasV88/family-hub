## Props contract (Settings/FinanceAccounts page)

`sections` (SettingsSections::for), `accounts`: list of {id, name, type, currency, memberIds: list<int>, memberCount: int, sharedWithMe: bool, opening: null | {minor: string, asOf: 'Y-m-d', currencyLocked: bool}} where `opening` is non-null only when the admin is a member of that account AND has finance view or edit; `members`: list of {id, name, financeAccess: bool} (all members, financeAccess = finance level view or edit); `panel`: null | 'new' | account id (from `?acct=`; an unknown id renders the same 403 Forbidden page as any refusal). No balance, no transaction count, no "has transactions" flag for accounts the admin is not ticked on.

## Rules

- Store: name required max 60; type in bank|cash|savings|card; currency in Currency::codes(); opening_balance optional string parsed with MoneyParser::manual(allowNegative: true) (blank = 0); balance_as_of required date (default today in the form); member_ids array of user ids each with finance view or edit (else error key finance.error.members); creator is not added unless ticked.
- Update: name, type, member_ids always. currency: for an admin not ticked on the account the key is `prohibited` (always, regardless of data, so nothing leaks); for a ticked admin it is allowed only when the account has no transactions, else error key finance.acc.currency_locked. opening_balance and balance_as_of: `prohibited` for a non-ticked admin; for a ticked admin balance_as_of may not move after the earliest transaction date (error key finance.error.date_before_open).
- Validation messages are translation keys (project convention).
