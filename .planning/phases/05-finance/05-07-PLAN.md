## Props contract (consumed by 05-08 and every later finance page)

`finance` (FinancePage::props): {accounts: [{id, name, type, currency}] (visible only, ordered by name), selectedAccount: 'all' | id, month: 'YYYY-MM', today: 'Y-m-d' (family time zone), timezone, canEdit: bool, isAdmin: bool, categories: [{id, kind, defaultKey: ?string, name: ?string}] (family-wide, all), currencies: list<string> (AccountQuery::currencies order)}. `?account=` with a hidden or unknown id aborts 403 (same Forbidden page as module none); a malformed `?month=` falls back to the current month.

Transactions page `Finance/Transactions`: `finance`, `filters` {q, type: 'all'|'income'|'expense'|'transfer', category: 'all'|'none'|id, source: 'all'|'manual'|'import'}, `transactions` {items: [Row], total: int, page: int, hasMore: bool} (page size config finance.transactions.page_size = 50; `?page=N` returns rows 1..N*50 cumulatively so a reload never loses rows), `panelTransaction`: null | Panel (from `?tx=new` → {mode:'new'}; `?tx=<id>`: visible → Panel, hidden/unknown → 403 page; `?tx=new` without edit → 403).
Row: {id, kind: 'income'|'expense'|'transfer' (display kind), amountMinor: string (signed for income/expense; absolute for transfer), currency, bookedOn, description, categoryId: ?string, accountId, accountName, transfer: null | {fromId, fromName, toId, toName}, source: 'manual'|'import', createdAt}. Panel: Row + {note, editable: bool, match: null} (05-11 fills match).
Accounts page `Finance/Accounts`: `finance`, `accounts`: [{id, name, type, currency, balanceMinor: string}] (balance as of today).

## Behaviour rules (Claude's discretion where marked)

- Display kind: a transfer leg whose counterpart account is visible is 'transfer'; otherwise income (amount > 0) or expense (amount < 0). With selectedAccount 'all', only the outgoing leg of a fully visible transfer is listed (one row per transfer); with a single account selected, that account's leg is listed.
- Kind is fixed after creation (discretion: to change kind, delete and re-create; avoids revealing hidden counterparts).
- Update of a transfer propagates amount magnitude, date and description to both legs (the counterpart leg is updated even when hidden from the editor, without revealing it); note and category are per leg. Delete of a transfer leg deletes both legs.
- Any user edit of amount, date, description, category or account sets edited_at = now() (needed by import undo).
- booked_on must be on or after the account's balance_as_of (error finance.error.date_before_open).
- Transfer: from and to must be different visible accounts with the same currency (errors finance.error.transfer_same, finance.error.transfer_currency); cross-currency transfers deferred.
