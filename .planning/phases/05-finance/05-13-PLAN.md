Finance/Overview: `finance` (FinancePage), `overview`: {hasRecurring: bool, blocks: [Block]} where blocks follow AccountQuery::currencies order (or only the selected account's currency) and are empty when the viewer has no visible accounts. Block: {currency, summary: {incomeMinor, spendingMinor, balanceMinor} (strings; spending is a positive magnitude; balance = opening balances + all rows up to the month end), stillToPay: null | RecurringQuery block (null when hasRecurring is false), budgets: [{id, categoryId, limitMinor, spentMinor, percent: int, state: 'ok'|'near'|'over', overMinor: string|null, effectiveFrom}], categorySpending: {totalMinor, top: [{categoryId: ?string, amountMinor, percent}] (max 7), other: null | {amountMinor, percent}, all: [{categoryId, amountMinor, percent}]}, balanceSeries: [{month: 'YYYY-MM', balanceMinor}] (12 entries ending at the selected month)}; `panelBudget`: null | {mode:'new', currency} | budget row (from `?budget=`; unknown id or a budget in a currency the viewer has no visible account in renders the 403 page).
Home: prop `financeCard` = {paymentsCount, overdueCount} present ONLY when the user has finance view/edit and at least one visible recurring item; otherwise the key is absent from the props (not null).

## Rules

- Display kind (identical to 05-07): a transfer leg counts as income/expense (by sign) when its counterpart is not visible to the viewer; fully visible transfers are excluded from income, spending, category spending and budgets. DisplayKind::sql(Viewer) returns the shared CASE/EXISTS fragment and bindings for BudgetQuery and OverviewQuery.
- Budget limit for month M and currency C: the row with greatest effective_from <= first day of M for (category, C); amount_minor NULL is a tombstone (no budget from that month). No copy rows and no carry-over of unspent amounts (decision).
- spent = magnitude of display-expense rows of that category and currency in the month, on visible and selected accounts. percent = intdiv(spent * 100, limit); state over when spent > limit, near when spent * 100 >= limit * 90, else ok; overMinor = spent - limit when over.
- Percent of category spending = intdiv(amount * 100 + intdiv(total, 2), total) (half up); no division anywhere else.
- Months are 'YYYY-MM' strings converted to date boundaries; never date_trunc on a date column without ::timestamp; group with to_char(booked_on, 'YYYY-MM') and a SUM(...) OVER (ORDER BY month) window for the running balance; every SUM cast ::bigint.
