## Decisions taken here

- `wish_occasions`: id, owner_id FK users nullable cascade (null = whole family), kind CHECK in (nameday, custom), title varchar(100) null, month smallint CHECK 1..12, day smallint CHECK 1..31, year smallint null, calendar char(2) null CHECK in (sk, pl), name varchar(60) null, created_by_id FK users nullable nullOnDelete, timestamps; CHECKs: nameday requires owner_id, calendar, name and year null; custom requires title; partial unique index on owner_id where kind = 'nameday' (one name day per member). The name-day row stores a snapshot (calendar, name, month, day), so a later data update never moves a stored date (research Pitfall 10).
- Christmas comes from config('wishlist.christmas') and is family-wide. Birthdays come from `users.birth_date` for members with wishlist view access.
- Who edits dates of member M: M, a designated manager of M, or an admin, in each case with wishlist edit level (UI-SPEC "member themselves and admins" plus the research recommendation to include managers). Who edits a custom occasion: its creator or an admin with wishlist edit level.
- The occasion panel's secondary button is "Close" (occasions.close) with a discard dialog when dirty (orchestrator flag: never "Cancel" next to "Discard").

## Contract consumed by plans 04-10, 04-11, 04-12

- `OccasionOccurrence` (readonly): type (birthday|nameday|christmas|custom), ownerId (?int), ownerName (?string), title (?string, custom only), occasionId (?int), date (CarbonImmutable, family tz, 00:00), daysAway (int), subjectType (user_birthday|wish_occasion|christmas) and subjectId (owner id, occasion id, or the year for Christmas).
- `OccasionCalendar::upcoming(CarbonImmutable $today, int $horizonDays): list<OccasionOccurrence>` sorted by date then type; `occurrenceOn(string $subjectType, int $subjectId, string $date): ?OccasionOccurrence` (used by the reminder handler's send-time re-check).
- Page `Wishlist/Occasions` props: `upcoming` [{key, type, owner {id, name} | null, title, date 'YYYY-MM-DD', days_away, occasion_id}], `members` [{id, name, is_viewer, birth {month, day} | null, birth_date 'YYYY-MM-DD' | null (only when can_edit_dates), nameday {calendar, name, month, day} | null, can_edit_dates}], `custom` [{id, title, month, day, year | null, owner {id, name} | null, can_edit}], `can_add` bool, `today` 'YYYY-MM-DD'. Plan 04-10 inserts ShoppingSummary above "Upcoming" (no placeholder element now).
