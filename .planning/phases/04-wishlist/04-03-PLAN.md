## Data rules

- Downloaded files are untrusted data: download into `database/data/namedays/source/<calendar>/` (data only, never executed); the build scripts live in `scripts/namedays/` and take paths as arguments. Run PHP for the scripts inside the app container (`docker compose -p fh0403 run --rm app php scripts/namedays/build-pl.php ...`).
- Do NOT generate or correct the Polish list from model memory (research Open Question 1). Every PL name comes from the fetched wikitext.
- PL gate (stop-and-return rule): the Polish data is committed only when ALL of these hold: all 12 monthly pages were found and fetched (exact titles and revids recorded), `--build` exits 0 (no unparseable day), and the PL thresholds of NameDayDataTest pass (366 keys incl. 02-29, at least 360 non-empty days, at least 1000 names, name regex). If any condition fails, the executor does NOT commit pl.json or source/pl, does NOT patch, guess or fill missing days or names from model memory or any unrecorded source, and does NOT lower the thresholds; it stops at the Task 2 checkpoint and returns to the user with the failure details.
- Normalised file format (both calendars): `{"calendar": "sk"|"pl", "version": "<source date or commit>+<build date>", "source": "<url>", "license": "MIT"|"CC BY-SA 4.0", "days": {"01-01": ["..."], ..., "02-29": [...], ..., "12-31": [...]}}`; exactly 366 keys `MM-DD`, names as UTF-8 strings in source order, duplicates within a day removed.
