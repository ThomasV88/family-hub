## Contract (from 04-05, repeated so this plan is self-contained)

Props `members` [{id, name, is_viewer}], `list` {owner {id, name}, viewer_is_recipient, viewer_is_manager, can_edit, wishes: Wish[], received?: Wish[]}, `selected` null | 'new' | int. Wish {id, title, notes, price ("12.50" | null), currency, size_notes, priority (top|love|nice), urls [{id, url, label, host}], image {status none|pending|ready|failed, thumb_url, full_url, source, host}, received}. Endpoints: POST /wishlist/wishes (owner_id for managers), PATCH and DELETE /wishlist/wishes/{id}, POST and DELETE /wishlist/wishes/{id}/received, PUT /settings/members/{id}/wishlist-managers {manager_ids}. Toasts come from the server flash (`toast.key`), as in Phase 3.

## Component rules (UI-SPEC)

- Icons from `@lucide/vue` (the project package), 20px, stroke 1.75.
- Region slots: `OwnListView` and `GiftListView` both take a named slot `context` that Index.vue fills with `PersonChips` (plan 04-12 appends the occasion strip into the same slot). `GiftListView` renders, in order: an empty spot where plan 04-10 inserts `ShoppingSummary` (no placeholder element now), the `context` slot, the list header ("{name}'s wishlist", "{n} wishes"), the gallery. `OwnListView` renders: the `context` slot, the banner (own: info "This is your wishlist..." dismissible per session; manager: "You are managing {name}'s list."), the gallery with the Add tile first (only when can_edit), the Received group.
- `OwnWishCard` and `OwnWishPanel` accept only the Wish keys of the contract (declare props explicitly; never v-bind a whole object with unknown keys onto DOM; never render `data-*` from wish data).
- Copy uses wishlist.* keys from plan 04-01; panel secondary button is `wishlist.close` (opens the discard dialog when dirty), never "Cancel". Delete button text `wishlist.delete.action`, mark received `wishlist.received.mark`.
