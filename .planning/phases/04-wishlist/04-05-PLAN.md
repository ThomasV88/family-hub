## Phase Goal

**As a** family member, **I want to** keep a gift wishlist that relatives can reserve from and chip in on, **so that** I get gifts I actually want while I never learn who is buying what.

<objective>
Backend of the first vertical slice: wishes with multiple links on a per-member list, the per-list manager designation, the reservation-blind `Catalog` layer, `ViewerContext`/`WishAccess`, routes, matrix rows and the privacy arch test. The Vue side of the same slice is plan 04-06 (same wave, contract below).

Purpose: CONTEXT decisions "Wish fields: title, notes, price (amount + currency, default EUR), size/variant notes, priority, multiple URLs (optional label), image", "Everyone with wishlist view access sees every member's list. Owners edit their own list; a member with an edit grant may add wishes on a child's behalf if the admin allows it", "A parent/manager who manages a child's list is treated like the recipient", "Enforcement: reservation data in separate tables; owner/manager endpoints never select reservation columns". Orchestrator decision: managers in a `wishlist_managers` table, admin-edited in Settings > Members (multi-select).
Output: schema, models, factories, Catalog services, controllers, routes, matrix files, tests.

## Contract shared with plan 04-06 (Vue) and later plans (do not change shape without updating both)

Page `Wishlist/Index` props:
- `members`: list of `{id, name, is_viewer}`: users whose wishlist level is view or edit; the viewer first, the rest sorted with a `Collator` for the app locale.
- `list`: `{owner: {id, name}, viewer_is_recipient: bool, viewer_is_manager: bool, can_edit: bool, wishes: Wish[], received?: Wish[]}`. `viewer_is_recipient` is true only when the viewer is the owner or a designated manager of THIS list (UI-SPEC recipient-equivalent definition; an edit grant or admin role never sets it). `viewer_is_manager` is true only for a designated manager who is not the owner. `received` exists only when `viewer_is_recipient`. Non-recipient views never contain received wishes.
- `selected`: `null | 'new' | int` from `?wish=`; `'new'` only when `can_edit`.
- `Wish`: `{id, title, notes, price, currency, size_notes, priority, urls, image, received}` with `price` a decimal string ("12.50") or null, `priority` one of `top|love|nice`, `urls` list of `{id, url, label, host}`, `image` `{status: none|pending|ready|failed, thumb_url: null, full_url: null, source: null|fetched|uploaded, host: null|string}` (plan 04-07 fills the URLs), `received` bool. No timestamps, no owner ids, nothing else (explicit allowlist).
- Giver views get extra keys from plan 04-08 (`list.viewer_can_reserve`, per-wish `reservation`); owner views never do.
- Settings `Settings/Members` props: each member gains `wishlistManagerIds: int[]`.

Endpoints:
- GET `/wishlist` (`wishlist.index`, view): query `member` (int, default viewer), `wish` (int or `new`). An unknown member, a member without wishlist access, `new` without `can_edit`, or a wish id not in this list's visible wishes all return the same 403 (no existence leak). Any other query parameter (for example `available`) is ignored.
- POST `/wishlist/wishes` (`wishlist.wishes.store`, edit, throttle 60/min): `{owner_id?, title, notes?, price?, currency, size_notes?, priority, urls?: [{url, label?}]}`; 303 to `/wishlist?member={owner_id}` with toast `wishlist.toast.saved` and `flash_data.wishId`.
- PATCH `/wishlist/wishes/{wish}` (`wishlist.wishes.update`, edit, 120/min): same fields without owner_id; 303 back, toast `wishlist.toast.saved`.
- DELETE `/wishlist/wishes/{wish}` (`wishlist.wishes.destroy`, edit, 60/min): 303 to `/wishlist?member={owner}`, toast `wishlist.toast.deleted`.
- POST and DELETE `/wishlist/wishes/{wish}/received` (`wishlist.wishes.received.store|destroy`, edit, 60/min): 303 back, toast `wishlist.toast.received` on store.
- PUT `/settings/members/{user}/wishlist-managers` (`settings.members.wishlist_managers.update`, `access:admin`, whereNumber + findOrFail): `{manager_ids: int[]}`; redirect back with toast `members.wishlist_managers.saved`.

Validation (FormRequest, config/wishlist.php values): title required max 120; notes max 2000; size_notes max 200; price optional regex `^\d{1,9}([.,]\d{1,2})?$` converted by `Money::toMinor` (comma or dot); currency in EUR, PLN, CZK, USD, GBP (default EUR); priority in top, love, nice (default love); urls max 5 items, each url required max 2048 with scheme http or https only (reject javascript:, data:, file:), label max 100; blank url rows are dropped before validation. Error messages map to the lang keys wishlist.error.* (title_required, url_invalid, price_invalid).
