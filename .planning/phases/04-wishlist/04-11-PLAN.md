## Rules

- Givers for an occurrence: users with wishlist level edit (re-read with AccessGate::forget per user, as ReminderRecipients does in a long-lived process), minus the occurrence owner and minus every designated manager of that owner. Christmas and family-wide custom occasions (owner null): all givers.
- Lead days per giver from `wish_reminder_settings.lead_days` (jsonb, subset of config('wishlist.allowed_lead_days') = [14, 7, 3, 1], default [14, 3] when no row). An empty array means no gift reminders.
- Fire for occurrence date D and lead L when D minus L <= today <= D minus L plus 1 and today <= D (one day of grace after an outage, never a stale reminder). The scan runs hourly and acts only when the family-zone local hour >= config('wishlist.reminder_hour') (8).
- Channels exactly as EnqueueReminders: mail when the mail preference is on; push only when push is on and the user has a subscription.
- dedupe_key `wish_occasion:{type}:{subjectId}:{date}:{lead}:{userId}:{channel}`; subject_type user_birthday | wish_occasion | christmas; payload `{type, subject_id, date: 'YYYY-MM-DD', lead}` (ids and dates only, no names).
- Push: `{title, url}` with title from notifications.gift_title / gift_title_family and url `/wishlist?member={ownerId}` or `/wishlist` (relative). Mail subject equals the title; body notifications.gift_body / gift_body_family; action button notifications.gift_action to the same URL; greeting notifications.reminder_greeting. "When" is gift_today or trans_choice gift_in_days with the days remaining at send time. Escape names and custom titles for markdown as in Phase 3 WR-04.
