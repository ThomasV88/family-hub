# Phase 03 — UI Design Contract

> Visual and interaction contract for the To-do module: person columns board, task detail panel, quick add, recurrence/reminder/visibility fields, notification preferences. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Sources: 03-CONTEXT.md (locked), 01.1-UI-SPEC.md (design system, extended and not redefined), 02-UI-SPEC.md (settings shell, confirm/discard patterns, copy tone), sketch 004 winner B (columns per person + detail panel). Items marked "(discretion)" were decided here under Claude's Discretion.

Inherited unchanged from 01.1 and 02. Do not redefine tokens or `Ui*` components.

## Typography

Exactly the 01.1 set: 4 sizes (14, 16, 20, 24), 2 weights (400, 600). Do not use `--text-xs`, `--text-lg`, `--text-3xl`.

| Role | Size | Weight | Line Height | Used for in this phase |
|------|------|--------|-------------|------------------------|
| Body | 16px | 400 | 1.5 | Task titles on cards, input text, notes, hints inside panel when longer than one line, notification section body |
| Label | 14px | 600 (hints, meta, counts 400) | 1.4 | Field labels, buttons, tags (due, overdue, status), chips, column count, recurrence summary line, history entries |
| Heading | 20px | 600 | 1.2 | Page h1 "Tasks", panel title, empty state title, notification section title |
| Display | 24px | 600 | 1.2 | not used here |

Column person name is 16/600 (Body size at semibold weight, allowed within the two weights). Done tasks keep 16/400 with `text-decoration: line-through` and `--color-text-muted`; strikethrough is not the only done signal (checked checkbox also present).

## Color

Reuse 01.1 values. 60/30/10 holds: dominant `--color-bg` (board background), secondary `--color-surface` (columns, cards, panel) and `--color-surface-2` (column header band, hover), accent `--color-primary`, destructive `--color-danger`.

Accent reserved for (this phase, subset of the 01.1 closed list):
1. Primary button, one per view region: "Save task" (panel), "Add task" (quick add submit and empty state action when it is the only action in view; when the quick add bar is visible the empty-state action is secondary)
2. Floating add button (FAB) fill on phone (opens create panel)
3. Checked state of task checkbox, switch ON (Email, Push), selected filter chip, selected status chip, selected weekday chip, selected radio
4. Focus ring, "Open tasks" link on the dashboard card, links in the iOS install hint
5. Selected settings section item (Notifications) as in Phase 2

Not accent: task titles, column headers, card borders, selected card (selected card uses `--color-surface-2` fill plus a 2px start-edge border in `--color-border-strong`), due tags, recurrence icon, lock icon.

Semantic tags (always text, optionally icon):
- Due soon/today: `warn` tag with `Clock` ("Today", "Tomorrow" use `neutral`; only "Today" is `warn`)
- Overdue: `danger` tag with `AlertCircle`, text "Overdue, {date}"
- In progress: `neutral` tag with `CircleDot`
- Done: no tag in list (checked checkbox and strikethrough); in panel the Done status chip is selected
- Recurrence: `Repeat` icon, muted, with `aria-label` "Repeats"
- Personal: `Lock` icon, muted, with `aria-label` "Personal task"; Selected members: `Users` icon, muted, `aria-label` "Shared with selected members"; Family: no icon (default)

Destructive (`--color-danger`) reserved for: "Delete task" button and confirm, "Discard" in discard dialog, overdue tag, field error text/border, push-failed alert. Never for "Skip this occurrence" (neutral secondary).

## Screens and Interaction Contract

Routes (Inertia pages): `/todo` (board, panel via `?task=`; `?task=new` opens create mode), `/settings/notifications` (new section in the Phase 2 settings shell). Dashboard To-do card and QuickAdd are changes to the existing Home page. All routes `no-store`; nothing from these screens enters the service worker.

### 1. Board (`/todo`)

Focal point: the current user's column at the top left with the quick add field directly above it, so "what do I have to do" and "add one" are the first things seen.

- Page header: h1 "Tasks" (Heading) and, at container width >= 640px, the shell topbar "Add task" primary button (01.1); phone uses the FAB.
- Quick add bar (`UiCard`, padding 12px): visually hidden `<label>` "New task title", `UiInput` placeholder "Add a task and press Enter", and a secondary-size primary `UiButton` "Add task" (leading `Plus`; the button makes the action discoverable without keyboard Enter; stays one primary per region). Enter or button creates the task immediately: title only, status To do, assignee = current user, visibility Family, no due date; `UiToast` "Task added" with action "Open task" (opens panel). Input clears and keeps focus. Empty title: no request, inline error "Enter a task title." with `aria-invalid`. Loading: button `aria-busy`, width stable. No natural-language date parsing (discretion: avoids silent misparses in SK/PL).
- Filter chips (`UiChip` group, `role="group"` labelled "Filter tasks"): All, Mine, Shared, Personal. Default All. Semantics: All = every visible task in all columns; Mine = only the current user's column (assigned to me); Shared = Family and Selected tasks in all columns (Personal hidden); Personal = my personal tasks only, in my column. Filter in URL query.
- Column grid (container query on `.content`, `grid-template-columns: repeat(n, minmax(0, 1fr))`, gap 16px): 3 columns from content width 700px, 2 from 440px, else 1. More members than columns: grid wraps into further rows (no horizontal scroll). Order: current user first, then other members alphabetically by locale collation, then "Unassigned" last (only rendered if it has tasks). Only members with at least View on To-do get a column.
- Phone (1 column): current user's column first. Each column header is a disclosure button (`aria-expanded`, `ChevronDown`): own column always expanded by default; other columns expanded when 3 members or fewer, collapsed (showing name and count) when more. Expanded state not persisted.
- Column contents sort: overdue first, then by due date/time ascending, then tasks without due date by creation time. Done tasks are hidden in a per-column group toggle "Show done ({n})" (`aria-expanded`), sorted by completion time descending, max 20 shown with "Show older" omitted in this phase (discretion; history stays in panel).
- Card meta line (14px): due tag (see Color), `Repeat` icon, `Lock`/`Users` icon, In progress tag. Time shown with date when due has a time ("Today 18:00" via `Intl`). No avatar on cards (column is the assignee).
- Card actions: checkbox toggles Done immediately (optimistic, `aria-label` "Mark done: {title}" / "Mark not done: {title}"). Completing a recurring task creates the next occurrence and shows toast "Done. Next one is due {date}." Failure reverts the checkbox and shows toast "We could not update the task. Try again." Clicking the card body opens the panel; the selected card has the selected style.
- "Add task for {name}" ghost button at the bottom of each person column opens create panel with that person preselected as assignee. Hidden for view-only users.
- No drag and drop between columns (discretion: not keyboard accessible; reassignment is via panel "Assigned to").
- View-only users: no quick add, no FAB, no add buttons, checkboxes disabled with tooltip-free `aria-disabled`; an info line under h1 (`UiAlert` info, dismissible per session): "You can view tasks but not change them." Creator or assignee of a task can still toggle and edit that task (server decides; UI follows an `abilities` flag per task).
- States: Loading = 3 `UiSkeleton` columns of 3 cards. Empty board (no tasks at all) = `UiEmptyState` "No tasks yet" with action "Add task". Empty column = muted 14/400 text "No tasks". Empty filter result = `UiEmptyState` "No tasks match" with action "Show all tasks". Error = `UiErrorState` "Something went wrong" with "Try again". Module access none = 403 `UiErrorState` (Phase 2).

### 2. Task panel (`DetailPanel`, create and edit)

Focal point: the Title field at the top with the "Save task" button pinned at the bottom, so a task can be created with two actions and refined only if needed.

Presentation per 01.1: docked 360px at content width >= 900px, overlay on iPad, bottom sheet (max 85%) on phone. Footer is sticky inside the panel. Close button always present; Esc closes. Panel h2: "New task" in create mode, "Task details" in edit mode. Focus goes to Title on open (create) or to the panel heading (edit); closing returns focus to the card or button that opened it.

Field order (single column, 16px gap):
1. Title (`UiInput`, required).
2. Status: `StatusChips` (To do / In progress / Done), label "Status".
3. Assigned to (`UiSelect`): members who can see the task plus "Unassigned". Default current user. Options are restricted by visibility: Personal forces current user (select disabled, hint "Personal tasks stay with you."); Selected members limits options to creator and chosen members.
4. Due date (`type=date`) and switch "Add a time" revealing Time (`type=time`). Hint under both: "Times use the family time zone ({tz})." Clearing the date clears time, repeat and reminder.
5. Repeat (`RecurrenceFields`): `UiSelect` "Repeat" with Does not repeat (default) / Every day / On chosen weekdays / Every month / Custom interval. Disabled with hint "Set a due date to make this task repeat." when no due date. Conditional fields:
   - Weekdays: group of 7 toggle `UiChip`s (visible short weekday from `Intl`, `aria-label` full weekday name, `aria-pressed`), legend "Weekdays"; week starts per locale (Monday for SK/PL/EN-GB). Error if none: "Choose at least one weekday."
   - Every month: `UiSelect` "Day of month" with "On day {n}" (n from due date, fixed) and "On the last day of the month"; hint "In shorter months this happens on the last day."
   - Custom interval: `UiInput` number "Interval" (1 to 99, `inputmode="numeric"`) and `UiSelect` "Unit" (Days / Weeks / Months). Weekly-chosen weekdays pattern is not offered inside custom (discretion: custom is "every N units" only).
   - For any repeat: `UiRadio` group "Repeat from" with "The schedule" and "When I complete it" and a hint explaining both. Under the group, a live summary line (14/400 muted, `aria-live="polite"`), e.g. "Repeats every 2 weeks".
6. Reminder (`ReminderField`): `UiSelect` "Remind me": At due time (default), 15 minutes before, 1 hour before, 1 day before, No reminder. Disabled with hint "Set a due date to get a reminder." when no due date. 15 minutes and 1 hour options are disabled with hint "Add a time to remind minutes or hours before." when date-only. Hint always shown: "Tasks without a time remind at 08:00."
7. Who can see this task (`VisibilityField`): radio cards Personal / Family / Selected members, each with a one-line explanation. Default Family. Selecting Selected members reveals a `UiCheckbox` list of members (avatar, name), legend "Choose members". Only the creator can change visibility; others see a read-only line with the current value (discretion, aligned with Personal hidden even from admins).
8. Notes (`UiTextarea`, 4 rows, grows to 12, 16px).
9. History (only for recurring tasks in edit mode): collapsible group "Completed history" (`aria-expanded`), list of "Completed {date}" and "Skipped {date}" entries (14/400), empty "No completions yet."

Footer: primary "Save task", secondary "Cancel" (reverts and closes). In edit mode additionally: secondary "Skip this occurrence" (only for recurring tasks; applies immediately, toast "Skipped. Next one is due {date}.") and danger ghost "Delete task" (leading `Trash2`) separated at the start edge. View-only: fields read-only, footer shows only "Close".

Behavior:
- Single save path: edits to fields apply only on "Save task" (status changes inside the panel also save with it; the card checkbox is the immediate path). Save enabled only when dirty and valid. Success: toast "Task saved", panel closes in create mode, stays open in edit mode.
- Validation: errors inline per field (`UiField` error line with icon), focus to first invalid field; Title required, valid date, interval 1 to 99, weekdays at least one, Selected members at least one.
- Unsaved changes: closing with dirty state opens the confirm dialog "Discard changes?" (Discard danger, Keep editing secondary and default focus).
- Server error: danger `UiAlert` at panel top "We could not save the task. Nothing was changed. Try again." Selections kept.
- Delete: confirm dialog "Delete task" (see Copywriting), default focus "Keep task".
- Deep link `?task={id}` for a task the user cannot see renders the same 403 `UiErrorState` (no existence leak: same for unknown ids).
- Phone: bottom sheet scrolls internally, footer stays visible above `env(safe-area-inset-bottom)`.

### 3. Quick add on Home and FAB

Focal point: one input on top of the Overview where typing a task and pressing Enter really creates it.

- The existing shell `QuickAdd` now calls the same create endpoint as the board quick add (same defaults, same "Task added" toast with "Open task" action). The dashboard stays in place.
- FAB (phone) and topbar "Add task" button open `/todo?task=new` (create panel over the board).
- Users without To-do edit access: QuickAdd, FAB and topbar button are hidden, not disabled. Users with none access: To-do card, nav item and quick add hidden.

### 4. Dashboard To-do card

Focal point: the card's "Due soon" list showing overdue items first, so the one thing needing action today stands out.

- Heading "Due soon" with "Open tasks" link (01.1 pattern). Up to 5 rows (`UiListRow`): checkbox-free (read-only, link to `/todo?task={id}`), title, due tag, `Lock` icon for personal. Scope: tasks assigned to the current user that are not done, overdue first then by due date, only tasks with a due date. More than 5: footer text "and {n} more".
- Empty (no tasks at all): 01.1 copy "No tasks yet" with "Add task". No tasks due: muted text "Nothing is due soon." with link "Open tasks".

### 5. Notification preferences (`/settings/notifications`)

Focal point: the Push switch and the "Enable push on this device" button, because push is the only channel that needs a device-level step.

- New section in the Phase 2 settings shell: item "Notifications" (`Bell`), visible to all members (admins and non-admins). Non-admins now see "Notifications" and "Appearance and language". Section order: Members and access, Audit log, Notifications, Appearance and language. Below 640px it follows the Phase 2 landing-list pattern.
- Page: h1 "Notifications", intro line, one `UiCard` titled "Task reminders" (Heading) containing:
  1. `UiSwitch` "Email reminders" with hint "Sent to {email}."
  2. `UiSwitch` "Push notifications" with hint "Short alerts with the task title only. Notes are never shown."
  3. `PushDeviceRow` (shown under the Push switch, indented 24px) titled "This device" with state text and one button.
- Switches save immediately (low-risk, reversible; discretion, differs from the Phase 2 explicit-save pattern): optimistic, toast "Notification settings saved", on failure the switch reverts and a danger alert shows "We could not save this setting. It was not changed. Try again."
- Both channels off: info `UiAlert` "Both channels are off. You will not get task reminders."
- `PushDeviceRow` states (one visible at a time, announced in a `role="status"` region):
  - Unsupported browser: neutral text "This browser does not support push notifications. Email still works." No button.
  - iOS Safari not installed as PWA (detect `navigator.standalone` false on iOS): info `UiAlert` with `Share` icon, title "Install the app to get push on iPhone and iPad", body "On iPhone and iPad, push works only after you add Family Hub to your Home Screen. Tap Share, choose Add to Home Screen, then open the app from there." No enable button until running installed.
  - Permission not yet asked or off: text "Push is off for this device." and secondary button "Enable push on this device" (calls permission request from a click, never on page load).
  - Permission denied: warning `UiAlert` "Notifications are blocked for this site. Allow them in your browser settings, then try again." plus `BellOff` icon.
  - Enabled: text "Push is on for this device.", buttons "Send test notification" (secondary) and "Turn off push on this device" (ghost). Test success toast "Test notification sent."; failure danger text "We could not send the test. Try again."
- Push payload contract (for planner, UI-visible): notification title "Task due: {title}" in the member's locale, no body text, no notes, click opens `/todo?task={id}`. Reminder email subject "Task due: {title}"; body contains title, due date/time in the family time zone and a link, never notes (discretion).
- The service worker gains only a `push` and `notificationclick` handler; no runtime caching.

## Interaction and Accessibility Contract (additions to 01.1 and 02)

- Board semantics: each column is a `<section aria-labelledby>` with the person's name as `<h2>`; task lists are `<ul>`; the card checkbox and card button are two separate focusable elements in DOM order (checkbox, then button). Panel is `<aside aria-label="Task details">`.
- Live regions: toasts `role="status"`; panel server errors `role="alert"`; recurrence summary and push device state `aria-live="polite"`. After completing a task via checkbox, focus stays on the checkbox.
- Keyboard: arrow keys move between status chips and between weekday chips only as a roving group is not required for weekdays (each is an independent toggle in Tab order); filter chips are Tab-reachable toggles. Enter in quick add submits. Esc closes the panel and dialogs.
- Never color alone: overdue pairs color with `AlertCircle` and text "Overdue"; done pairs color with checked box; visibility icons carry `aria-label`.
- Touch: 44px hit areas for all new controls on phone and iPad.
- Dates and times: `Intl.DateTimeFormat` in the active locale and the family time zone; `<time datetime>` for due tags; relative words "Today"/"Tomorrow" computed in the family time zone. Recurrence, month-end and DST behaviour is server-side; the UI only displays the next due date returned by the server and never computes occurrences itself.
- Plurals through ICU (SK and PL have `one/few/many/other`); no string concatenation; names and titles inserted as parameters. Task titles are user content: rendered as text only, never as HTML, in toasts, aria-labels and push text.
- Long text: titles wrap up to 2 lines on cards (ellipsis after), buttons and tags may wrap to 2 lines (01.1 rule). Pseudo-long (+40%) test covers card meta line, panel footer buttons and notification hints.
- Privacy: Personal tasks never appear in another member's board, dashboard card, search or push, including admins; a Personal task the user created is shown with the `Lock` icon. Board responses are `no-store`.
- Tests: Vitest + axe on board (empty, populated, filtered, view-only), panel (create, edit, recurring, each visibility), notifications page (each push state), in light and dark and en/sk/pl; contrast tokens already covered by the 01.1 test; Pest feature tests cover 403 for deep links.
