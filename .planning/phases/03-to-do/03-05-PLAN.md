## Contracts

TaskAccess (App\Tasks\TaskAccess, constructor-injected AccessGate; every method assumes the task was loaded through Task::visibleTo($user)):
- canEdit(User, Task): todo edit grant AND (creator_id = user OR assignee_id = user)
- canChangeStatus(User, Task): todo edit grant (visible is implied by how the task was loaded)
- canDelete(User, Task) and canChangeVisibility(User, Task): todo edit grant AND creator_id = user
- abilities(User, Task): array{edit: bool, status: bool, delete: bool, visibility: bool}
No is_admin anywhere. Note: CONTEXT requires the edit grant, so a view-only assignee cannot edit (the UI-SPEC sentence "Creator or assignee can still toggle" is subordinate to CONTEXT; the server decides via abilities).

TaskService (App\Tasks\TaskService): create(User $creator, array $validated): Task (forceFill creator_id, timezone = config('family.timezone'); defaults visibility family, assignee = creator when the key is absent; explicit null = Unassigned), update(Task, array $validated): Task, setStatus(Task, TaskStatus, User): Task (Done sets completed_at = now and completed_by; leaving Done clears both), delete(Task). Clearing due_date also clears due_time (plans 03-09 extend: recurrence and reminder). All writes in DB::transaction. Plans 03-08 and 03-09 extend this class; keep methods small.

Validated fields (StoreTaskRequest extends the 03-03 title rule; UpdateTaskRequest same rules with title required): title required|string|max:200 (trimmed) -> todo.error.title_required / todo.error.title_long; notes nullable|string|max:5000 -> todo.error.notes_long; status in TaskStatus values; assignee_id nullable|integer + HasTodoAccess rule (user exists and holds todo >= view) -> todo.error.assignee; due_date nullable|date_format:Y-m-d -> todo.error.date_invalid; due_time nullable|date_format:H:i and only with due_date -> todo.error.time_invalid. Unknown keys ignored (validated() only).

Routes added to routes/web/todo.php (all whereNumber('task'); controllers load with Task::visibleTo($request->user())->findOrFail($id) so invisible = 404, never route-model binding before access):
- PATCH /todo/tasks/{task} -> TaskController@update, name todo.tasks.update, access:module,todo,edit; 403 unless canEdit
- PATCH /todo/tasks/{task}/status -> TaskStatusController, name todo.tasks.status, access:module,todo,edit; 403 unless canChangeStatus
- DELETE /todo/tasks/{task} -> TaskController@destroy, name todo.tasks.destroy, access:module,todo,edit; 403 unless canDelete
All respond 303 back with toast keys (todo.toast.saved, todo.toast.deleted); store also flashes flash_data.taskId.

Index props added: tasks[].abilities (per contract), selectedTaskMissing (bool: query ?task is numeric and not found via visibleTo; 'new' is allowed).

Matrix rows (params closure: a Family task created by $users['parent'] and assigned to them):
- todo.tasks.update data {title: 'Changed'}: guest 302, admin 403, parent 303, child 403, grandparent 403, guestPreset 403, noGrants 403
- todo.tasks.status data {status: 'done'}: guest 302, admin 403, parent 303, child 303, grandparent 303, guestPreset 403, noGrants 403
- todo.tasks.destroy: guest 302, admin 403, parent 303, child 403, grandparent 403, guestPreset 403, noGrants 403
