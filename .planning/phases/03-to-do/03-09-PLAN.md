## Contracts

Request fields (Store and Update): recurrence nullable array in the RecurrencePattern::toArray shape (kind, interval, unit, weekdays, monthDay); requires due_date (error key todo.repeat.need_date); validated by RecurrencePattern::fromArray inside a closure rule mapping failures to todo.error.interval (interval) and todo.error.weekdays (weekdays); for monthly_day the server ignores the posted monthDay and uses the due date's day (UI shows "On day {n}" from the due date). recurrence_mode required with recurrence, in schedule|completion. remind_before_minutes nullable in 0,15,60,1440 (null = No reminder); non-null requires due_date (todo.reminder.need_date); 15 and 60 require due_time (todo.reminder.need_time). Raw RRULE strings are never accepted from the client.
TaskService: recurrence present -> recurrence_rule = RuleBuilder::toRrule(pattern), recurrence_mode, series_id = existing or a new uuid; recurrence null -> rule and mode null (series_id kept so history stays linked); due_date cleared -> due_time, recurrence_rule and recurrence_mode cleared.
TaskCompletionService (App\Tasks): complete(Task, User): ?Task and skip(Task, User): ?Task, each in DB::transaction with the row re-read via lockForUpdate. complete on an already completed task is a no-op returning null. Sets status done, completed_at, completed_by (skip sets skipped_at only). For a recurring task computes next = app(RecurrenceEngine::class)->next(rule, LocalTime::at(due_date, due_time ?? '00:00', tz), RecurrenceMode::from(mode), completed local instant, tz, now) and creates the next occurrence: same title, notes, visibility, creator_id, assignee_id, timezone, remind_before_minutes, recurrence_rule, recurrence_mode, series_id, task_members; due_date = next date; due_time = original time (null for date-only); status todo. A UniqueConstraintViolationException from tasks_one_open_per_series (concurrent completion) rolls back the duplicate and counts as a no-op. remind_at of the new row is set by the 03-07 observer.
TaskAccess change: status ability is false for a completed or skipped occurrence of a recurring task (history rows cannot be un-done; discretion, avoids two open occurrences); TaskStatusController returns 422 for that case.
Routes: POST /todo/tasks/{task}/skip -> TaskSkipController, name todo.tasks.skip, access:module,todo,edit, whereNumber; 404 invisible, 403 without status ability, 422 for non-recurring. Status done and skip redirect 303 with flash_data.nextDue ('Y-m-d' or 'Y-m-d H:i', family-local) and toast key todo.toast.done_next / todo.toast.skipped.
Matrix row todo.tasks.skip (params: a recurring daily Family task by parent due tomorrow): guest 302, admin 403, parent 303, child 303, grandparent 303, guestPreset 403, noGrants 403.
Board props per task add: recurrence (pattern array or null), recurrenceMode (string or null), remindBefore (int or null). Index prop history (only when ?task=<visible recurring id>): list of {kind: completed|skipped, at: ISO} for rows of the same series visible to the viewer, newest first, max 50.
