<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Actions runner -> VPS (SSH) | Deploy key grants shell as deploy user |
| PR authors (public repo) -> CI | Untrusted code runs in the check job |
| GHCR -> VPS | Images pulled and executed |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-37 | Elevation of privilege | deploy job secrets | mitigate | Deploy job only on `push` to main/develop; no `pull_request_target`; fork PR workflows need approval; production environment requires owner review |
| T-01-38 | Spoofing | SSH host | mitigate | DEPLOY_KNOWN_HOSTS with StrictHostKeyChecking yes, fingerprint checked against the server |
| T-01-39 | Tampering | third-party actions | mitigate | docker/* actions pinned to full SHAs; top-level permissions contents: read; packages: write only in deploy |
| T-01-40 | Information disclosure | committed secrets | mitigate | check-secrets.sh runs first in every CI run |
| T-01-41 | Information disclosure | GHCR token on server | mitigate | docker login per deploy with GITHUB_TOKEN, logout afterward (task-tracker pattern) |
| T-01-42 | Information disclosure | provisioning output | mitigate | Script generates secrets into 0600 files and never prints values; dry-run test asserts .env holds no password |
</threat_model>
