<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| postgres container -> host pipe -> restic repo | Full database content in transit on the host |
| restic repo on disk / off-site | Backup at rest |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-27 | Information disclosure | backup at rest | mitigate | restic repository encryption (AES-256); dump streamed via stdin, no plaintext file; tested wrong-password and no-plaintext cases |
| T-01-28 | Information disclosure | restic password | mitigate | password only in secrets/restic_password (0600, deploy) and owner's off-server store; scripts use `--password-file`, never echo |
| T-01-29 | Denial of service | unrecoverable backup | mitigate | Monthly scripted restore drill, weekly `restic check`, daily freshness check, pg tools from the same postgres:18 image |
| T-01-30 | Tampering | silent partial dump | mitigate | `set -o pipefail` so pg_dump failure fails the backup; tested |
| T-01-31 | Information disclosure | cross-environment restore | mitigate | Drill restores only into a scratch DB in the same stack; refuses DRILL_DB equal to live DB; documented rule "never restore production into staging" |
| T-01-32 | Information disclosure | .env parsing | mitigate | Scripts read only named keys from .env instead of sourcing the whole file |
</threat_model>
