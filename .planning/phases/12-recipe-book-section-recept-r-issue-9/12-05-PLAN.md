- `routes/web/recipes-state.php` (all `access:module,recipes,view`, `throttle:240,1,recipes.state`): PUT `/recipes/{recipe}/ingredients/{ingredient}/tick` `recipes.ingredients.tick` `{ticked: bool}`; PUT `/recipes/{recipe}/steps/{step}/done` `recipes.steps.done` `{done: bool}`; PUT `/recipes/{recipe}/favourite` `recipes.favourite` `{favourite: bool}`; PUT `/recipes/{recipe}/note` `recipes.note` `{note: string|null}`; PUT `/recipes/{recipe}/servings` `recipes.servings` `{servings: int|null}`; DELETE `/recipes/{recipe}/progress` `recipes.progress.reset`.
- Responses: Inertia requests get 303 (store and update to `/recipes/{id}` with flash `recipes.toast.saved`; destroy to `/recipes` with `recipes.toast.deleted`; visibility back with `recipes.toast.visibility_changed`; state endpoints back without a toast, reset with `recipes.toast.progress_reset`). A plain JSON request (`expectsJson()` and no `X-Inertia` header) gets: store 201 `{id}`, update 200 `{id}`, state endpoints 204. The create form uses the JSON store so it can upload queued photos to the new id (12-08).
- RecipeIndexRequest: `q` max 100, `ingredient` max 100, `categories[]` max 10 strings max 90, `author` integer, `show` in all|mine|shared (default all), `favourites` boolean, `page` integer >= 1.
- StoreRecipeRequest (UpdateRecipeRequest extends it and allows `id` on lines): title required max 120 (trim, collapse whitespace), description nullable max 1000, servings nullable integer 1..99, prep_minutes and cook_minutes nullable integer 0..1440, source_url nullable max 2000, must be http or https with a host (error `recipes.error.source_url`), visibility required private|shared, categories array max 3 of strings max 30 (error `recipes.error.categories`), ingredients array 1..80 of `{id?, name required max 120, quantity nullable, unit_id nullable exists:shopping_units,id, note nullable max 80}`, steps array 1..60 of `{id?, body required max 1000}`. `quantity` normalised in prepareForValidation: strip spaces at the ends, comma to dot, vulgar fractions (¼ ½ ¾ ⅓ ⅔) and `a/b` or `n a/b` to a decimal rounded half-up to two places; then rule regex `^\d{1,4}(\.\d{1,2})?$` plus > 0 and <= 9999 (error `recipes.error.quantity`). Missing ingredients or steps -> `recipes.error.ingredients_required`, `recipes.error.steps_required`.
- `RecipePayload::index(User, array $filters, int $page)`: `recipes [{id, title, mainPhoto: {id, version}|null, prepMinutes, cookMinutes, servings, visibility, categories: [name], author: {id, name, isMe} (plus the avatar fields existing payloads use, grep "photoVersion" or useAvatarUrl), favourite}]`, `hasMore`, `page`, `filters` (echo of normalised filters), `filterOptions {categories [{name, key}], authors [{id, name}]}`, `canCreate` (recipes edit).
- `RecipePayload::show(User, Recipe)`: `recipe {id, title, description, servings, prepMinutes, cookMinutes, visibility, sourceUrl, sourceHost, createdVia, author {id, name, isMe + avatar fields}, categories [name], ingredients [{id, name, quantity (string|null), unitId, note}], steps [{id, body}], photos [{id, position, isMain, version, thumbUrl, fullUrl}]}` (URL strings built here as `/recipes/{id}/photos/{photo}/thumb?v={version}` and `/full?v=`), `state` (RecipeStateService::stateFor), `abilities` (RecipeAccess::abilities), `units [{id, key|null, names {en, sk, pl}|null}]` (same shape as the Shopping payload). Never another member's state, never file paths.
