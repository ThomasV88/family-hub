## Contracts

Routes in `routes/web/recipes-shopping.php` (`whereNumber`):
- GET `/recipes/{recipe}/shopping` `recipes.shopping.preview`: middleware `access:module,recipes,view` and `access:module,shopping,edit` (the button is shown only with Shopping edit, so preview needs the same; check that the middleware stacks two module gates the way existing routes do, otherwise check the shopping level in the controller and answer 403). Response JSON:
  `{baseServings, lists: [{id, name, storeName|null, updatedAt, pending: [{catalogItemId, unitId|null, quantity}]}], stores: [{id, name}], catalog: [{id, name, defaultUnitId|null, imageVersion|null}], units: [{id, key|null, names}], rows: [{ingredientId, name, quantity (string|null, base), unitId|null, note|null, match: {tier: 'exact'|'suggested'|'none', catalogItemId|null, catalogName|null}, suggestedUnitId|null}], canCreateList, limits {nameMax, itemsMax}}`.
  Lists offered: `ListQuery::visibleTo($actor)` with status open, filtered in PHP by `ShoppingAccess::mayEditItems`, ordered by updated_at desc. `pending` holds only pending catalog lines (for the "Already on the list" hint). `suggestedUnitId` = the ingredient's unit, else the matched catalog item's default unit, else the built-in `pcs` when quantity is null.
- POST `/recipes/{recipe}/shopping` `recipes.shopping.store`: `access:module,recipes,view` + `access:module,shopping,edit`, `throttle:20,1,recipes.shopping`. Body (AddToShoppingRequest): `target` new|existing; `list_id` required when existing; `name` required when new, max 80 after whitespace collapse; `store_id` nullable integer; `items` array 1..80 of `{catalog_item_id?: int, name?: string max 80, quantity: string, unit_id?: int|null}` with exactly one of catalog_item_id or name. Quantity is normalised like Shopping (comma to dot) and must match Shopping's rule (`^\d{1,3}(\.\d{1,2})?$`, > 0, <= 999.99), error `shopping.error.quantity`.
  Commit (RecipeShoppingBridge::commit) runs in one `DB::transaction`: recipe through visibleTo (404), optional `ListService::create($actor, $name, $storeId, null)` (actor responsible), then `ItemService::add($actor, $listId, $chunk)` in chunks of at most 50. No notes are sent. Any ValidationException, 403 or 409 rolls back everything and passes through (409 for a list locked meanwhile, key from ItemService). Success JSON 200 `{listId, listName, count}` where count = rows sent.
- CatalogMatcher::match(string $ingredientName, Collection $catalog): tier exact = catalog `name_key` equals `NameKey::from($name)`; tier suggested = exactly one catalog item whose key equals the ingredient key without a trailing plural ending (strip one of `s`, `es`, `y`, `e`, `i`, `a` only when the remaining key has at least 3 characters) or whose words are a whole-word subset of the ingredient's words ("red onion" -> "Onion"); more than one candidate or none -> tier none. Pure, unit-tested with sk, pl and en names (A6: reviewable, conservative).

RecipeShoppingFixtures (new file, do not edit RecipeFixtures): open list with a contributor, locked list, done list, catalog items with units, member with Shopping edit and with Shopping view only.
