- `NewRecipeDialog`: "New recipe" (Index header and empty state) opens `UiDialog` (bottom sheet on phone) with two 64 px rows: "Type it in" (PencilLine, "Fill in a blank form.") -> `/recipes/create`; "Read from a web page" (Link, "Paste a link and the app fills in the form for you to check.") -> URL step in the same dialog. When `import.available` is false the dialog is skipped and the button links straight to `/recipes/create` (12-07 behaviour kept).
- `ImportFromUrlDialog`: field "Web page address" (`type="url"`, `inputmode="url"`, placeholder "https://", required, max 2000, client check http/https; invalid -> "Enter a web address that starts with http:// or https://."), helper "Works with most recipe pages.". Notice when `import.acknowledged` is false: `UiAlert` info with the UI-SPEC title, body and button "Got it" -> POST `/recipes/imports/notice` with `import.providers`; 204 reveals the field; 409 updates the providers and shows the notice again. After acknowledgement: muted one-line hint with Info icon "The text of the page is sent to the AI provider." and `HelpTip` `recipes.import`. Footer ghost Cancel, primary "Read recipe" (disabled when empty or invalid).
- Start: POST `/recipes/imports` `{url}`; 202 -> loading (field read-only, `UiProgress` indeterminate, "Reading the page. This can take a minute.", ghost Cancel = POST cancel then close); 409 notice_required -> show the notice with the new providers; 409 unavailable -> warn "Reading pages is not available right now. You can type the recipe in yourself."; 429 or limit -> warn "You have read too many pages today. Try again later."; 422 -> the URL error.
- `useImportStatus(id)`: GET `/recipes/imports/{id}` every 2 s (UI-SPEC), paused while `document.hidden`, gives up after 3 minutes with the generic failure; ready -> `router.visit('/recipes/create?import={id}')`; failed -> reason `fetch` "We could not open that page. Check the address, or type the recipe in yourself.", `no_recipe` "We could not find a recipe on that page. Try the page with the full recipe, or type it in yourself.", `unavailable` the warn text; cancelled -> close. Completion announced with `aria-live="polite"`. Each failure shows primary "Try again" (or "Change address") and secondary "Type it in" -> `/recipes/create?source={encoded url}`. Escape does not close while the start request runs.
- Closing the dialog during loading keeps the import running; `ImportDraftAlerts` on the overview renders `drafts`: active -> info "Reading {site}..." (from `recipes.drafts.*`), ready -> info "Your recipe from {site} is ready to review." with "Review" (-> create?import) and ghost "Discard" (danger confirm "Discard this draft?" / "Discard draft" / "Keep draft", DELETE), failed -> warn "Reading {site} did not work." with "Try again" (reopens the URL step) and "Type it in". Active drafts are polled with `useImportStatus` and reload the overview `drafts` prop on change.
- Form review mode (prefill prop): page title "Check the recipe"; top `UiAlert` info "Check everything the app filled in from the page. Nothing is saved until you press Save recipe."; fields listed in `aiFields` carry `UiTag` "From the page" (Sparkles) next to the label until edited; empty AI fields show muted "Not found on the page."; each ingredient shows its `original` line as muted helper text (never sent on save); "Source" shows the link (ExternalLink, host) with ghost "Edit" making it editable; `textCut` shows "The page was long, only the beginning was read." Save sends `import_id`. `?source=` prefill fills only the Source field. Leaving asks "Leave without saving?" (12-08 dialog).
- AiCalls.vue: rows with `kind === 'recipe'` show "Recipe import" where the person name is shown; nothing else changes; test that no URL-like text is rendered.
