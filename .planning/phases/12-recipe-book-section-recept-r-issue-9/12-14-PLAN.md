## Contracts

Routes in `routes/web/recipes-import.php` (all `access:module,recipes,edit`; `{import}` with `whereUuid`; names `recipes.imports.*`):
- POST `/recipes/imports/notice` `recipes.imports.notice` body `{providers: string[]}` -> 204, or 409 `{outcome: 'notice_changed', providers}` when the set is stale (`throttle:10,1,recipes.imports.notice`).
- POST `/recipes/imports` `recipes.imports.store` body `{url}` (`throttle:10,1,recipes.imports.start`) -> 202 `{outcome: 'started'|'reused', id}`; 422 `{errors: {url: ['recipes.import.err_url']}}`; 409 `{outcome: 'notice_required', providers}`; 409 `{outcome: 'unavailable'}`; 429 `{outcome: 'limit'}` (the throttle's own 429 is the same outcome for the UI).
- GET `/recipes/imports/{import}` `recipes.imports.show` (`throttle:120,1,recipes.imports.status`) -> `{id, status, reason, host, textCut}`; `reason` is null unless failed: `fetch` for fetch_failed, `no_recipe` for no_recipe, invalid_output, no_output, output_too_large, cli_error, timeout, idle_timeout and worker_lost, `unavailable` for quota_exhausted, quota_timeout, no_agent, auth, notice_required and preflight. Never the URL path, the text or the raw code.
- POST `/recipes/imports/{import}/cancel` `recipes.imports.cancel` (`throttle:30,1,recipes.imports.cancel`) -> 204.
- DELETE `/recipes/imports/{import}` `recipes.imports.destroy` (discard, same throttle) -> 204.
- Another member's import id or an unknown id -> 404 (service scopes by user_id).

Overview and form payload additions (RecipePayload::index and ::form): `import {available, acknowledged, providers}` from `RecipeImportService::noticeState`; index also `drafts [{id, status, host, reason}]` from `RecipeImportQuery::draftsFor`.

Prefill (`ImportPrefill::fromPayload(RecipeImport): array`): maps the validated payload to the form shape: title, description, servings, prep_minutes, cook_minutes, categories (names), ingredients `[{name, quantity (string|null), unit_id (Shopping unit id looked up by built-in key, never a hard-coded id), note, original}]`, steps `[{body}]`, plus `aiFields` (list of top-level fields that were filled), `sourceUrl` (the normalised URL the member typed), `sourceHost`, `textCut`, `importId`. `RecipeController::create` reads `?import={uuid}`: the member's own import with status ready -> `prefill` prop; another member's or unknown -> 404; own but not ready -> the plain form. `?source={url}` (from "Type it in" after a failed import) -> `prefill.sourceUrl` when ImportUrl::normalise accepts it, else ignored.

Save rule: StoreRecipeRequest accepts `import_id` nullable uuid. `RecipeService::create(User $actor, array $data, ?string $importId = null)`: inside the same transaction, lock the import row `where user_id = actor and status = 'ready'`; when found set status used, payload null, and the recipe `created_via = 'url'`; when not found the recipe saves as manual (no error: a draft pruned while the member was editing must not lose the typed recipe). The member's edited `source_url` is what is stored.

Maintenance:
- `recipes:reap-imports` every five minutes (`withoutOverlapping`): fetching older than `reap_fetching_minutes`, queued older than `reap_queued_minutes`, running older than `reap_running_minutes` -> failed worker_lost (fetching -> fetch_failed with fetch_reason network), source_text null, the open ai_calls row closed as failed worker_lost through the same finish path the medical reaper uses.
- `recipes:prune-imports` daily: ready rows older than `ready_ttl_hours` -> cancelled with payload null; delete rows in a terminal status older than `retention_days`. Never touches medical tables or ai_calls (ai_calls has its own prune).
- Register both in routes/console.php with names `recipes-reap-imports` and `recipes-prune-imports`; update AiScheduleTest if it pins the schedule list.

Leak canary (ImportLeakTest): a fetched page contains a unique canary string in the title, an ingredient and a hidden element; run FetchRecipePage and RunRecipeImportJob with FakeCodex for (a) success, (b) invalid output, (c) a thrown exception inside the agent; then assert the canary is absent from: every file under the test log path, `failed_jobs` (payload and exception), `jobs` payloads, the audit log table, every column of `ai_calls`, the status JSON, the admin AI calls page props (GET the settings AI calls route as an admin), and `recipe_imports.source_text` after the terminal state. The ready payload may contain the visible title (it is the draft) but not the hidden element's canary.
