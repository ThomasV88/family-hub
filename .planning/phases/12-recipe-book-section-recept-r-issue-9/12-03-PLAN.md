## Contracts

RecipeAccess (constructor-injected AccessGate, no admin bypass, TaskAccess/ShoppingAccess style):
- `mayView(User, Recipe)`: author, or visibility shared (module view is enforced by the route middleware; the service methods also call AccessGate so they are safe outside HTTP).
- `mayEdit(User, Recipe)`: author AND AccessGate level recipes = edit. A view-only member never writes; an author who lost edit still reads own recipes.
- `abilities(User, Recipe)`: `{edit, delete, changeVisibility, addToShopping}`; addToShopping = AccessGate shopping level is edit (12-06 enforces the commit again). `import` is added by 12-14.
- Loading rule: every method that takes an id loads through `Recipe::query()->visibleTo($actor)->findOrFail($id)` (hidden = 404 identical to unknown); a visible recipe the actor may not edit = 403 (`AuthorizationException` or `abort(403)` consistent with ShoppingAccess).

RecipeService (every write in `DB::transaction` with `lockForUpdate` on the recipe row for update/visibility/delete):
- `create(User $actor, array $data): Recipe` with `$data = {title, description?, servings?, prep_minutes?, cook_minutes?, source_url?, visibility, categories: list<string>, ingredients: list<{name, quantity?, unit_id?, note?}>, steps: list<{body}>, created_via?}`. Requires recipes edit. Positions assigned from array order. `source_host` derived from a validated http(s) source_url (lower-cased host, no port, no userinfo). Categories trimmed, whitespace-collapsed, deduplicated by NameKey keeping the first spelling, max `recipes.categories_max`. Rebuild `search_key` and `title_key` with RecipeSearchKey. At least one ingredient and one step (ValidationException keys `recipes.error.ingredients_required`, `recipes.error.steps_required`). The optional import argument is added by 12-14; keep the signature open for a trailing nullable parameter.
- `update(User $actor, int $id, array $data): Recipe` same shape; ingredients and steps carry an optional `id`. Ids of this recipe are updated in place (position from array order), unknown or foreign ids are refused with 422 `recipes.error.unknown_line`, rows without id are inserted, rows of the recipe missing from the payload are deleted (their ticks and done marks cascade). Never delete-and-reinsert (Pitfall 5). Categories replaced as a set.
- `setVisibility(User $actor, int $id, RecipeVisibility $v)`; other members' state rows stay (hidden by visibleTo, back when re-shared).
- `delete(User $actor, int $id)`: author with edit; deletes the row (cascades) and registers `DB::afterCommit` -> `RecipeImageStore::deleteDirectory($id)`.

RecipeImageStore (this plan only): `directory(int $recipeId): string` = `wish-images/recipes/{id}` on the private `local` disk and `deleteDirectory(int $recipeId): void`. 12-04 adds the write methods and the sweeper.

RecipeStateService (absolute state, research Pattern 2; recipe loaded through visibleTo, child row checked with `where recipe_id`; 404 otherwise; requires recipes view only):
- `tick(User, int $recipeId, int $ingredientId, bool $ticked)`, `stepDone(User, int $recipeId, int $stepId, bool $done)`: insertOrIgnore / delete by composite key.
- `favourite(User, int $recipeId, bool)`, `note(User, int $recipeId, ?string)` (trim; empty -> null; max `recipes.member_note_max`), `servings(User, int $recipeId, ?int)` (1..99 or null = base): upsert into recipe_member_states with updated_at.
- `reset(User, int $recipeId)`: deletes the actor's ticks and done marks for this recipe's lines only; favourite, note and servings stay.
- `stateFor(User, Recipe)`: `{favourite, note, servings, tickedIngredientIds, doneStepIds}`.

RecipeQuery:
- `index(User, array $filters, int $page)` with filters `q` (string), `ingredient` (string), `categories` (list of name_keys, any-of), `author` (user id), `show` (all | mine | shared, where shared = visibility shared AND author not the actor), `favourites` (bool). Tokens of q and ingredient are NameKey-folded, split on spaces, AND-ed, `ILIKE '%token%'` with `\`, `%`, `_` escaped (copy the TransactionQuery escape). q matches `search_key`; ingredient matches EXISTS on recipe_ingredients.name_key. Order: when q is present, rows whose title_key contains every token first; then created_at desc, id desc. Page size `recipes.per_page`; return `{items, hasMore}` (fetch per_page + 1).
- `filterOptions(User)`: `categories` = distinct `{name, key}` used in visible recipes (most used first), `authors` = distinct authors of visible recipes `{id, name}` (never authors of hidden recipes).
- `categorySuggestions(User)`: used category names in visible recipes (12-08 merges them with the localised starter set).
- `find(User, int $id): Recipe` (visibleTo + findOrFail with ingredients, steps, photos, categories, author).
