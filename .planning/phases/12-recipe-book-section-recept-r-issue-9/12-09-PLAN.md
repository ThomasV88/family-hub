Actions: author secondary "Edit"; overflow `UiMenu` "Change visibility" (author; shared->private uses the confirm from 12-08's texts), "Reset my progress" (everyone; non-danger confirm per UI-SPEC), "Delete recipe" (author; danger confirm with the exact UI-SPEC text). - Servings (`ServingsControl`, `role="group"` labelled "Servings"): Minus/Plus 44 px with aria-labels, numeric input 64 px wide (1..99), default = member's stored servings or the recipe's; a change rescales at once, shows `UiTag` "Scaled" and ghost "Reset to {n}", announces "Quantities updated for {n} servings." (`aria-live`), and saves through PUT `/recipes/{id}/servings` debounced 600 ms (null when equal to the base). Hidden when the recipe has no servings (D3).
- `recipeScale.js`: `scaleQuantity(quantity, base, target)` = quantity x target / base (null quantity or null base -> unchanged); `displayQuantity(value, unit, locale)`: for units tbsp and tsp and for no unit, a value whose fractional part is within 0.01 of 1/4, 1/3, 1/2, 2/3 or 3/4 shows as whole part plus that fraction ("1/2 tsp", "1 1/2"); pcs and every other unit show up to 2 decimals with the locale separator ("1,5 ks"), never rounded silently; g and ml are never converted to kg or l in the recipe view. Unit labels through `unitLabel` of `resources/js/Shopping/units.js`.
- Ingredients (`IngredientRow`): `UiCheckbox` with 44 px hit area labelled "Prepared: {name}", quantity and unit (`--text-sm` 600, ~96 px column), name, muted note; ticked rows `--color-surface-2`, never struck through, never reordered. Header progress "{x} of {y} prepared" with `UiProgress` 4 px.
- Steps (`StepRow`): `UiCheckbox` "Done: step {n}", 28 px number badge replaced by Check when done, text `--text-base` 1.5, progress "{x} of {y} steps done"; all done -> muted `UiAlert` "All steps done. Enjoy your meal." with ghost "Reset my progress". No forced order.
- `useRecipeState.js`: JSON `fetch` PUT/DELETE with the XSRF header (204 expected) to the 12-05 state endpoints, one request in flight per recipe, absolute target states, per-row override until its own request settles, rollback of only the failed row and toast "Could not save. Try again." (copy the semantics of `resources/js/Shopping/useMarkQueue.js`, adapted from router.put to fetch so the page does not reload).
- Notes (`RecipeNotes`): label "My notes (only you can see them)", placeholder, max 2000, auto-grow, autosave 800 ms after typing stops with "Saving..."/"Saved" (`aria-live="polite"`), failure "Could not save your notes" plus "Try again"; help tip `recipes.notes`.

State local to the device, default off.
- `useWakeLock.js`: when supported (`'wakeLock' in navigator`), request a `screen` lock while cooking mode is on, release on off, on `visibilitychange` to hidden and on unmount, re-acquire on visible; unsupported or rejected -> silent no-op; the hint "The screen stays on while you cook." only when supported.
- Delete success navigates to `/recipes` (server flash `recipes.toast.deleted`); a 403 shows "You are not allowed to do that with this recipe."; the 404 Inertia error for a hidden recipe is the standard error page, and the page component also renders the `recipes.unavailable` empty state when the server answers with a missing recipe prop.
