## Contracts this plan creates

- `config/security.php`: `idle_seconds` (env SECURITY_IDLE_SECONDS, default 900), `confirm_window_seconds` (env SECURITY_CONFIRM_WINDOW_SECONDS, default 600), `challenge_ttl_seconds` (default 600), `passkeys_enabled` (env SECURITY_PASSKEYS_ENABLED, default true), `google_reauth` (env SECURITY_GOOGLE_REAUTH, default false; gates the "Sign in with Google again" re-auth fallback until 06-13 records Google's observed behaviour, per revision decision on Blocker 2).
- `App\Security\SensitiveSession` (not final; container `scoped`; reads the session from the current request at call time): `fresh(): bool` (now - `sensitive.active_at` <= idle_seconds and the key is set), `touch(): void` (sets `sensitive.active_at` = now), `confirm(): void` (touch + sets `auth.password_confirmed_at` = now; a successful interactive proof of identity), `recentlyConfirmed(): bool` (now - `auth.password_confirmed_at` <= confirm_window_seconds). These two session keys are written nowhere else in the app.
- `App\Security\SafeIntended` (static): `path(?string $url, string $host): string` returns a same-origin relative path+query or '/'; rejects absolute URLs to another host, scheme-relative `//`, backslashes, anything not starting with a single '/', and paths starting with /confirm-access, /login, /logout, /two-factor-challenge, /auth/google; `remember(Request $r, string $url): void` stores the validated path in `url.intended` (write validation); `pull(Request $r): string` pulls and re-validates (read validation), default '/'; `peek(Request $r): ?string` validated value without removing.
- Rule `access:recent`: authenticated AND SensitiveSession::recentlyConfirmed(); unauthenticated -> same login handling as other rules; stale -> `expectsJson() && !X-Inertia` ? 423 JSON `{"error":"confirm_required"}` : `redirect()->guest(url('/confirm-access'))`. No audit row. May be stacked with another access rule, e.g. `['access:admin', 'access:recent']`.
- Named limiters: `two-factor` keyed by the challenged user id from session `login.id` (fallback `ip:`), 5 per minute + 10 per 15 minutes; `reauth` keyed by the signed-in user id, 5 per minute + 20 per hour. Over limit: JSON callers get 429 `{"error":"throttle","minutes":N}`, others `back()->withErrors(['throttle' => (string) N])`, N = ceil(seconds/60) minimum 1; each lockout writes `AuditEvent::Lockout` with the member as actor (not via the Lockout event, whose listener resolves users by typed email).
- Test seam: `Tests\Support\AlwaysFreshSensitiveSession extends SensitiveSession` returns true from fresh() and recentlyConfirmed(); `TestCase::setUp` binds it by default; `TestCase::useRealSensitiveSession(): void` rebinds the real class (tests then use `withSession(['sensitive.active_at' => ..., 'auth.password_confirmed_at' => ...])`).
</context>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> session-held return address | Referer and URLs are attacker-influenced |
| client headers -> gate | request headers are untrusted |
| attacker with a password or session -> challenge/confirm | guessing codes and passwords |
