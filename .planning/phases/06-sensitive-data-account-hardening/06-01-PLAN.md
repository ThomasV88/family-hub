## Phase Goal

**As a** family member with access to Health or Finances, **I want to** protect my account with an authenticator app or passkey and be asked to confirm it's me after inactivity, **so that** medical and money data stay private even when a password leaks or a device is left unlocked.

<objective>
Lay the data and audit foundation every Phase 6 slice builds on: the re-added Fortify two-factor columns and passkeys table, an app_settings table for the admin requirement, a password_set flag (Google-created accounts have no usable password), the User model contracts, all new audit events, a listener that turns Fortify and passkey events into content-free audit rows, and the second-factor policy service.

Purpose: CONTEXT decisions "TOTP app (Fortify's two-factor with recovery codes) and passkeys (WebAuthn via laravel/passkeys)", "Admin can require a second factor for members who have health or finance access (setting, default off)", "Enable/disable of a factor, failed challenges, recovery code use, admin resets and re-auth confirmations are audited (never secrets or codes)"; research "Migrations to (re)add", Pattern 7, "Audit events (proposal)", Open Question 1 (Google-only members cannot use a password).
Output: 4 migrations (the password_set one runs a backfill), model and factory changes, audit enum and listener, three services, Totp test helper, 3 test files.
</objective>

## Contracts this plan creates (consumed by later plans)

- `User::hasSecondFactor(): bool` = `hasEnabledTwoFactorAuthentication() || passkeys()->exists()`; `User::passkeys()` from the Fortify `PasskeyAuthenticatable` trait; `users.password_set` boolean (default true; false means the account has no password the member knows). Forward maintenance (Google invite sets false, password reset sets true) is 06-10.
- `App\Security\PasswordSetBackfill::run(): int` (revision Warning 2; returns the number of rows set false): one UPDATE setting `password_set = false` for users where `google_id IS NOT NULL` AND no `audit_logs` row exists with event `google_linked` and (`actor_id` or `target_user_id`) = the user id (such a row means an existing password account was later linked to Google, so a password was set) AND no `audit_logs` row exists with event `password_reset` for that user id in either column (a completed reset means the member knows a password). Data used: `users.google_id` plus the append-only `audit_logs` table (InviteService::accept hashes `Str::random(64)` for Google invites; GoogleLoginService records `google_linked` when linking an existing account; ResetUserPassword records `password_reset`). ASSUMPTION (owner confirms in 06-13 Task 2): audit_logs has never been pruned, so a missing google_linked/password_reset row means none happened; if it cannot be determined (row missing for any reason) the account defaults to false, which only removes the password option from re-auth and never locks the member out (they can still sign in with Google; "Sign in again" works). The migration `2026_11_17_100003` calls it in `up()` after adding the column; `down()` drops the column.
- `App\Security\AppSettings` (container `scoped`): `get(string $key, mixed $default = null): mixed`, `set(string $key, mixed $value): void`. Values are JSON in `app_settings.value`.
- `App\Security\SecondFactorPolicy` (container `scoped`): `required(): bool` (setting `require_second_factor`, default false), `appliesTo(User $u): bool` (AccessGate level for Finance or Health is at least view), `mustEnrol(User $u): bool` (= required && appliesTo && !hasSecondFactor), `pendingCount(): int` (members for whom mustEnrol would be true if required were on; used by the admin card), `setRequired(bool $on): void`.
- New `AuditEvent` cases (string values, all <= 40 chars, all in group `security`): `TwoFactorEnabled` two_factor_enabled, `TwoFactorDisabled` two_factor_disabled, `RecoveryCodesRegenerated` recovery_codes_regenerated, `RecoveryCodeUsed` recovery_code_used, `PasskeyAdded` passkey_added, `PasskeyRenamed` passkey_renamed, `PasskeyRemoved` passkey_removed, `SecondFactorFailed` second_factor_failed (meta `method` in totp|recovery|passkey|password|google, `context` in login|reauth), `ReauthConfirmed` reauth_confirmed (meta `method`), `SecondFactorReset` second_factor_reset (actor admin, target member), `SecurityPolicyChanged` security_policy_changed (meta `setting`, `value`).
- `tests/Support/Totp.php`: `Totp::enable(User $u, bool $confirm = true): string` (returns the plain secret, uses Fortify actions), `Totp::code(string $secret, int $offset = 0): string` (Google2FA `oathTotp($secret, intdiv(time(), 30) + $offset)`), `Totp::recoveryCodes(User $u): array`.
</context>
