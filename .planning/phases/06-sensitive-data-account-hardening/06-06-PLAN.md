## Phase Goal

**As a** family member with access to Health or Finances, **I want to** protect my account with an authenticator app or passkey and be asked to confirm it's me after inactivity, **so that** medical and money data stay private even when a password leaks or a device is left unlocked.

<objective>
Give members the self-service UI for the authenticator app: the new Settings > Security section, the 3-step setup dialog with recovery codes, turning the app off, and creating new recovery codes, with the in-dialog "confirm it's you" for stale security windows and the guidance state for members under the admin requirement.

Purpose: ROADMAP success criterion 1 ("User can enable a TOTP app"); CONTEXT "members may enable either or both in their settings", "8 one-time recovery codes shown once at setup, regenerate on demand (needs re-auth)", "members under the requirement without a factor are guided to set one up before opening sensitive modules"; UI-SPEC Screens 1, 2, 3, 5, 6, "Confirmation windows", "Security UX Rules". Passkey cards on this page come in 06-09 (same phase); this plan provides the passkeys prop and a slot.
Output: controller, routes, section entry, page, 4 dialog/panel components, 4 test files (plus an updated shell test).
</objective>

## Server contract (this plan)

- `GET /settings/security` name `settings.security`, `access:authenticated` -> Inertia `Settings/Security` props: `sections` (SettingsSections::for), `status` {totp: hasEnabledTwoFactorAuthentication(), recoveryRemaining: int|null (count only, null when TOTP off)}, `passkeys` list of {id, name, authenticator (AAGUID label or null), createdAt ISO, lastUsedAt ISO|null} (never credential or credential_id), `required` (policy required() && appliesTo(user)), `guidance` (mustEnrol(user)), `continueTo` (SafeIntended::peek when guidance or flash status second_factor_required, else null), `methods` {password, totp, passkey, google} (same shape as /confirm-access), `confirmFresh` (SensitiveSession::recentlyConfirmed()), `passkeysEnabled` (config security.passkeys_enabled).
- `POST /settings/security/continue` name `settings.security.continue`, `access:authenticated`: 303 to SafeIntended::pull() with toast {key: 'security.guidance.done'}.
- Settings section `{key: 'security', href: '/settings/security', labelKey: 'settings.section.security', icon: 'shield-check'}` for every member, placed directly before appearance.
- Client endpoints used (from 06-05): POST /user/two-factor-authentication (enable), GET /user/two-factor-qr-code ({svg}), GET /user/two-factor-secret-key ({secretKey}), POST /user/confirmed-two-factor-authentication {code} -> {recoveryCodes}, DELETE /user/two-factor-authentication (disable; 423 confirm_required when confirmed and stale), POST /user/two-factor-recovery-codes (regenerate -> {recoveryCodes}; 423 when stale). In-dialog confirmation posts to /confirm-access in JSON mode through ReauthForm (06-04).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| server -> page props/history | anything in props is stored (encrypted) in browser history on shared family devices |
| browser DOM -> other people at the device | secrets visible after setup |
| signed-in session -> destructive security actions | idle/hijacked sessions |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-31 | Information disclosure | Security page props | mitigate | explicit mapping: booleans, counts, passkey display fields only; test scans the full response for secrets/codes/credential ids |
| T-06-32 | Information disclosure | QR, key, codes in DOM/history | mitigate | component-local state, v-if removal, reset on finish/cancel, router.clearHistory, no-store JSON; tests assert absence |
| T-06-33 | Elevation of privilege | turn-off / new codes from an idle session | mitigate | server 423 on stale 10-minute window (06-05); dialog requires ReauthForm; never auto-bypassed |
| T-06-34 | Tampering | guidance continue redirect | mitigate | continue pulls SafeIntended (same-origin path only) |
| T-06-35 | Information disclosure | recovery code download | mitigate | client-built Blob with codes only (no name/email), object URL revoked immediately |
</threat_model>
