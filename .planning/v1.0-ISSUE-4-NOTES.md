# Issue #4: contextual help, the green question marks (implementation notes)

## What was built

- A small green, bordered `?` (`resources/js/Components/ui/HelpTip.vue`) next to 55 fields, sections and buttons whose purpose is not obvious. Hover or keyboard focus (desktop) and tap (touch) show a bubble; Escape, an outside tap, blur or opening another tip closes it. The bubble is teleported to `body` (z-index 70, above dialogs and panels), positioned by `resources/js/Help/positionTip.js` (below by default, flips above, shifts inside the viewport, narrower than the viewport at 320 px). The hit area is 44 x 44 px around an 18 px mark, colours are the existing `--color-success` token (5.1:1 on white, 6.2:1 on the dark surface, a token pair is pinned in `tokenPairs.js`), with a forced-colors fallback and no motion under `prefers-reduced-motion`.
- Texts live in the database (`help_texts`, one row per key, a text and an "edited by an administrator" flag per language) and in the repo as defaults. The user always sees the language the app is set to.
- Administrators: Ctrl+click (Cmd+click, and the context menu event macOS sends for Ctrl+click) on a `?` opens an editor dialog (location, three languages, 400 character counter, reset to default per language, Save, Cancel). Other users get no editor; the same click toggles the tip.
- Settings > Contextual help (admin only, the 9th admin section): every tip with its placement, key, an Edited badge, the three texts, inline editing with the same editor, area filter, text search (diacritics ignored), counts, Unused keys, empty, filtered-empty and error states, stacked below 560 px.

## How to add a tip in three steps

1. Add the topic to `resources/help/topics.json` (`key` such as `area.what`, `area`, `screen`, `field`; the key never changes meaning afterwards) and its `title` and `text` (plain text, at most 400 characters, no `<` or `>`) under `topics` in `en.json`, `sk.json` and `pl.json`; add a new screen or area name to all three files if needed.
2. Put the tip in the template: `<HelpTip topic="area.what" :label="..." />` next to a heading, fieldset legend (`help-fieldset` plus `help-corner`), button or inside a `UiCard` `#action` slot, or `help="area.what"` on a `UiField`.
3. Run `npx vitest run tests/js/help` (the coverage test fails on an unknown topic, a dead key, a missing language, a text over the limit or a missing placement). `help:sync` inserts the row on the next deploy.

## Design decisions and deviations

- Registry in the repo, texts in the DB; `help:sync` is idempotent, refreshes defaults and placement for languages nobody edited, keeps edited languages, reports orphan keys and never deletes them. A missing or empty row falls back to the registry default at runtime, so a tip is never empty. A failing sync does not stop a deploy (warning only), because of that fallback.
- Shared prop is an Inertia once-prop: sent on the first visit and when the language or an edit changes the key, not on every navigation, so pages without tips pay nothing after the first load. Guests get `null`. Unreadable registry: no tips and a reported error, never a 500.
- Edit endpoint needs `access:admin` and a throttle but NOT `access:recent` (PROVISIONAL): the text is plain text, grants nothing and exposes nothing, so a stale-session dialog on every typo is not worth it. The route is not in the grant prefixes of `SensitiveRoutes`. If the owner wants it, add `access:recent` to `settings.help.update` and list it in `accessGranting()`; the central dialog and replay already work for the editor.
- Validation: each text 1 to 400 characters (multibyte), no `<` `>`, no control characters, only `sk`, `pl`, `en`; `texts` and `reset` cannot name the same language; unknown key is 404. DB check constraint also limits to 400.
- `edited_by` is a plain id without a foreign key, so removing a user never changes help.
- Title (the accessible name "Help: <title>") comes from the registry, not the DB, and is not editable.
- The tip for admins ends with a small line "Ctrl+click to edit".
- Tasks "Skip" and wishlist "Mark as received" tips show only where those buttons show.

## PROVISIONAL choices

- No `access:recent` on the edit route (above).
- Placement of the 55 tips and their wording (below); the owner may want fewer or more.
- Audit group for `help_text_changed` is Account.
- `help:sync` failure on deploy is a warning, not a stop.
- Area/screen names are shown in the language of the admin viewing the list.
